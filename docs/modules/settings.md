# 设置

状态：`in_progress`

## 1. 模块目标与非目标

承载账号安全、终端会话、资料隐私、黑名单入口、关于和开发环境信息。当前已交付“我的”资料隐私编排、安全退出与黑名单管理入口；V1 不含暗色主题、实验室或远程配置控制台。

## 2. 用户角色与使用场景

游客从“我的”进入登录；登录用户当前可管理资料隐私、本人关系列表、黑名单和退出，密码、邮箱、终端、注销及关于信息后续接入。

## 3. 页面、入口和导航关系

“我的” `/me` 当前直接展示本人总览、资料和公开范围表单，并可进入自己的公开主页、本人关注/粉丝及 `/me/blocks` 黑名单页。账号安全与关于后续拆为二级页面；任何开发信息都不得显示凭据。

## 4. 用户操作流程

资料和公开范围先读取服务端事实，只提交变化字段并采用服务端响应；黑名单读取服务端列表，取消拉黑成功后才移除，失败保留条目与请求 ID。当前终端退出二次确认，服务端失败时可重试或再次确认仅清本机。注销与关于页尚未接入。

## 5. API operationId 与生成类型

- 已接入：`usersGetMe`、`usersUpdateMe`、`usersFollowBlocks`、`usersFollowUnblock`、`authLogout`。
- 后续：`usersDeleteMe`、`authChangePassword`、`authRequestChangeEmailCode`、`authVerifyChangeEmail`、`authListSessions`、`authRevokeSession`。

## 6. 状态模型和数据流

本人资料由 users 的 autoDispose 控制器读取；用户名与资料隐私是独立编辑动作，共用防并发提交状态。表单保存初值、编辑值和局部错误，成功后使用 PATCH 响应重置。黑名单由 social 的 autoDispose 列表控制器管理，退出继续由 auth 的独立控制器管理。

## 7. 鉴权、权限和隐私规则

`/me` 只在认证状态请求私有资料；`/me/following`、`/me/followers` 与 `/me/blocks` 都受路由鉴权，游客先登录并保留安全回跳。用户名冷却、冲突和限流以服务端为准。页面只显示脱敏邮箱，不展示 Token、密码、验证码、完整邮箱以外的敏感凭据或预签名 URL。

## 8. 本地存储、缓存及失效规则

资料、关系列表和表单不持久化，账号设置服务端为权威；页面销毁、切号和退出释放私有状态。退出交由 SessionController 原子清理。

## 9. 加载、空数据、错误、重试和冲突状态

表单提交防重复，未变化不发请求；失败保留输入、旧资料与请求 ID。黑名单读取提供加载、空、失败、重试和刷新，取消拉黑串行执行并在失败时保留列表。已有简介因当前 DTO 不支持 null 而不能清空，客户端明确提示。退出失败保留会话并提供本机后备；验证码、终端与注销状态后续实现。

## 10. 跨模块约束

认证生命周期由 auth 实现，资料由 users，关系和黑名单由 social，头像由 media；设置只编排入口，不复制仓储逻辑。

## 11. 测试场景与验收条件

- [x] 游客看到登录入口且不请求私有资料，登录用户看到本人资料与隐私表单。
- [x] 简介与三项公开范围只提交变化字段，失败可恢复且服务端结果回写。
- [x] 本人关系与黑名单入口受鉴权，取消拉黑失败保留条目与请求 ID。
- [ ] 密码、邮箱和终端会话操作可恢复且状态正确。
- [x] 退出清本地会话且服务端失败保留安全后备；注销只用一次性账号人工验收。
- [ ] 开发信息准确且无敏感数据。

## 12. 已知限制和后续功能

当前不上传头像，不支持清空已有简介，也没有密码、邮箱、终端、注销、关于或开发信息页面。黑名单尚不与其他页面建立主动失效广播。不做暗色主题、动态实验开关和多账号管理；视觉设置在后续里程碑讨论。
