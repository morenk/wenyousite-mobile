# 首页

状态：`planned`

## 1. 模块目标与非目标

提供推荐主题流，以及分区、状态、标签和排序筛选。V1 不提供离线浏览或阅读进度。

## 2. 用户角色与使用场景

游客和用户都能浏览公开主题；登录用户在卡片上看到与自身相关的关系状态。

## 3. 页面、入口和导航关系

首页是默认分支；主题卡片进入主题详情；筛选面板是当前页面的可恢复状态。

## 4. 用户操作流程

首次加载推荐流，下拉刷新重置 cursor，上拉按原筛选继续；改变任一筛选先清空数据与 cursor，再请求第一页。

## 5. API operationId 与生成类型

- `threadsFindAll`、`threadTagsFindAll`、`tagsSearch`。
- 主要生成类型：`HomeThreadListItemResponseDto`、`ThreadsFindAll200Response`。

## 6. 状态模型和数据流

筛选条件与 `CursorPage` 组成不可变查询状态；仓储把生成 DTO 映射为主题卡片模型，分页控制器合并去重。

## 7. 鉴权、权限和隐私规则

游客不请求受保护数据；私密主题不得因本地缓存或错误合并泄露。登录关系状态缺失时安全降级。

## 8. 本地存储、缓存及失效规则

首版只做进程内页面保活和图片缓存；切换账号、权限改变、返回前台或手动刷新使关系状态失效。

## 9. 加载、空数据、错误、重试和冲突状态

首屏骨架、筛选后空结果、局部加载失败和重试分离；`40007` 清空后从第一页重载；重复项目按 ID 去重。

## 10. 跨模块约束

卡片图片走媒体降级规则；标签进入搜索；主题导航遵循[导航](../architecture/navigation.md)。

## 11. 测试场景与验收条件

- [ ] 游客进入推荐流并打开公开主题。
- [ ] 四类筛选与排序改变后正确重置分页。
- [ ] 空、错、重试、到底和无效 cursor 状态完整。
- [ ] 页面切换后保留筛选与滚动位置。

## 12. 已知限制和后续功能

不做离线流、阅读进度和复杂个性化解释；视觉精修在功能里程碑后独立进行。
