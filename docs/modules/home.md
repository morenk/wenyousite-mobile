# 首页

状态：`in_progress`

## 1. 模块目标与非目标

提供推荐主题流，以及动态分类、状态和排序筛选。当前切片不实现标签筛选、主题详情、离线浏览或阅读进度。

## 2. 用户角色与使用场景

游客和用户都能浏览公开主题；登录用户在卡片上看到与自身相关的关系状态。

## 3. 页面、入口和导航关系

首页是默认分支；筛选与滚动状态随保状态分支保留。主题卡片当前只承担扫读，下一切片接入主题详情路由后再增加可点击语义。

## 4. 用户操作流程

首次并行加载服务端分类和推荐流，下拉刷新重置 cursor，接近列表尾部或点击“加载更多”时按原筛选继续；改变分类、状态或排序先清空数据与 cursor，再请求第一页。

## 5. API operationId 与生成类型

- `threadCategoriesList`、`threadsFindAll`；标签筛选后续接入 `threadTagsFindAll`、`tagsSearch`。
- 主要生成类型：`ThreadCategoryResponseDto`、`HomeThreadListItemResponseDto`、`ThreadsFindAll200Response`。

## 6. 状态模型和数据流

`HomeFeedQuery` 与 `CursorPage` 组成不可变查询状态；仓储把生成 DTO 映射为主题卡片模型，控制器以请求世代丢弃过期响应，并在分页合并时按主题 ID 去重。

## 7. 鉴权、权限和隐私规则

游客不请求受保护数据；私密主题不得因本地缓存或错误合并泄露。登录关系状态缺失时安全降级。

## 8. 本地存储、缓存及失效规则

首版只做 Riverpod 进程内状态、`PageStorageKey` 滚动保活和图片缓存；手动或下拉刷新会重新读取分类与第一页。

## 9. 加载、空数据、错误、重试和冲突状态

首屏进度、筛选后空结果、首屏错误、刷新/分页局部错误和重试分离；`40007` 清空后从第一页重载；重复项目按 ID 去重。复杂骨架屏按视觉计划后置。

## 10. 跨模块约束

卡片图片走媒体降级规则；标签进入搜索；主题导航遵循[导航](../architecture/navigation.md)。
