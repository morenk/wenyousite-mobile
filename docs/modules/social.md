# 社交关系

状态：`in_progress`

## 1. 模块目标与非目标

统一主题与动态收藏、私有收藏夹分类、关注、订阅、点赞和拉黑的读写状态。当前已交付主题点赞、主题收藏与两类订阅、本人主题收藏夹管理、动态快捷收藏归类、公开用户页关注与拉黑，以及公开/本人关注、粉丝和本人黑名单列表；动态收藏页分类筛选与公开用户动态收藏列表仍是后续切片。收藏表情由独立 stickers 模块负责，本模块不包含推荐算法配置。

## 2. 用户角色与使用场景

游客与登录用户可从公开主页查看服务端允许的关注和粉丝列表，也能看到主题喜欢计数；游客触发主题点赞先登录。普通登录用户可点赞、收藏主题，在本人私有收藏页按“全部 / 默认收藏夹 / 自建收藏夹”筛选、新建分类并移动收藏，订阅楼主/协作者的官方更新，并按帖内已标记玩家订阅发言；楼主和协作者自动接收更新。登录用户还可管理公开关系及本人黑名单。

## 3. 页面、入口和导航关系

主题点赞、收藏和订阅入口位于 `/threads/:threadId` 固定底部拇指栏，并与发表楼层形成同一可达操作区，不再占用详情题头；快捷收藏完成后显示可短时操作的“修改收藏夹”气泡，进入移动端收藏夹选择 Sheet。玩家发言订阅仍在移动端 Bottom Sheet 中逐人切换。“我的”将“收藏”与关注、粉丝、温油置于同级入口；`/me/bookmarks` 使用共享等宽“主题帖 / 动态”内容页签，只响应点按，主题帖页管理本人私有收藏夹，动态页复用标准动态列表。`/me/following`、`/me/followers`、`/me/blocks` 管理关系。四个本人路径均保留登录回跳；公开关系和内容仍从 `/users/:userId` 进入，私有收藏夹名称和分类绝不进入公开用户页。

## 4. 用户操作流程

本人收藏页标题不重复解释收藏用途；主题帖收藏复用 threads 标准信息流卡片，完整呈现默认子贴活跃时间、摘要、安全首图、主题标签、玩家数及其他互动统计，动态收藏复用 moments 标准信息流，页面不维护两套列表样式。

主题与动态详情都以服务端投影初始化互动。快捷收藏不传 folderId 参数，先写入服务端默认收藏夹；成功气泡保留 5 秒“修改收藏夹”入口，用户未操作时不再发送请求。主题选择其他收藏夹时使用收藏记录 ID 移动，动态使用稳定动态 ID 移动；选择器独立加载收藏夹，按当前内容类型展示主题或动态数量，并覆盖加载失败重试、移动失败原地重选、唯一在途动作和明确关闭。本人主题收藏页并行读取分类计数和“全部”首屏；“全部”只在本地合成，服务端默认收藏夹保持第一项，切换分类必须清空不透明游标并按 folderId 参数从首屏读取。新建名称发送前 trim 并校验 1–24 字，成功后自动选中新分类；每条主题收藏可从移动端底部选择器移动到其他收藏夹。移动或取消成功后重新读取当前筛选首屏和服务端分类计数，禁止从收藏记录 ID 构造游标。订阅控制器独立收敛本人订阅和帖内成员候选：本人订阅成功后即可操作官方更新，候选读取失败只影响玩家入口并可单独重试；官方/玩家订阅都按记录 ID 取消。点赞采用服务端计数；点赞、收藏、订阅、关注与拉黑在写入结果不明时读取对应详情、订阅列表或用户关系投影，只有投影证明目标已达成才同步为完成。点赞/收藏统一复用 Foundation v6.3.0 语义色、选中表面、实心资产和精确在途动作反馈。

- 已接入 `subscriptionsFindAll`、`subscriptionsCreate`、`subscriptionsRemove`，并以 `threadMembersFindAll` 读取玩家候选。
- 已接入 `usersFollowFollow`、`usersFollowUnfollow`、`usersFollowBlock`、`usersFollowUnblock`。
- 已接入 `usersFollowFollowing`、`usersFollowFollowers`、`usersFollowUserFollowing`、`usersFollowUserFollowers`、`usersFollowBlocks`。
- 已接入 `threadsLike`、`threadsUnlike`。
- 已接入动态默认收藏与 `momentsMoveBookmark`；`momentsBookmarks` 的可选 folderId 参数和 `usersGetUserMomentBookmarks` 已进入生成客户端，分类列表与公开页业务层尚未接入。

## 6. 状态模型和数据流

`ThreadInteractionTarget` 管理详情点赞与快捷收藏，并通过可选投影读取端口采用最新主题详情；`BookmarkListController` 独立保存服务端收藏夹、当前 `selectedFolderId`、分类错误、当前筛选分页和创建/移动/取消的唯一在途动作。收藏 DTO 在 data 层映射为包含完整主题卡字段与收藏管理 ID 的展示模型，页面再交给共享 `ThreadFeedCard`；非法头像/封面 URL 安全降级，超契约多图只取首张安全图片。分类读取失败不遮断“全部”收藏，列表筛选失败也不丢失已取得的分类。主题订阅控制器以 `threadId` 为 family key，内部观察稳定 `SessionScope` 并只用当前 `accountId` 过滤本人候选；状态保存当前主题订阅、玩家候选、独立的 `candidateFailure` 与唯一在途目标。`UserRelationTarget` 管理关系写入并可采用公开用户关系投影，`UserRelationListTarget` 管理公开/本人列表。收藏、互动、订阅、关系与关系列表五类端口位于 `social/application`，API 适配器由 `main.dart` 组合根绑定，控制器不导入具体 data 仓储。校准中的动作保存中性结果状态和问题编号；所有状态均为 autoDispose，当前不建立跨页面事件总线。

## 7. 鉴权、权限和隐私规则

所有写操作和 `/me/*` 私有列表需要登录；游客进入 `/me/bookmarks` 时先登录并保留原目标。收藏夹 ID、名称和计数仅属于本人，移动时收藏记录与目标收藏夹都由服务端复核归属，404 不猜测资源是否存在。游客点赞只进入登录，收藏与订阅入口不显示。主题 capability 或当前成员角色表明楼主/协作者时隐藏订阅控件；普通用户只能选择服务端成员列表中的已标记参与者。收藏列表由服务端过滤已失去访问权的主题，客户端不泄露失效私密条目。

## 8. 本地存储、缓存及失效规则

互动、订阅、收藏与关系列表只存在于 autoDispose Provider；离页、退出或切号即释放。玩家订阅面板记录打开时的会话作用域，切号或退出后当帧隐藏并自动关闭，旧控制器迟到结果不得恢复旧账号操作。主题刷新重新采用详情投影；收藏页下拉刷新并行重读当前筛选首屏与分类计数，分类切换、创建、移动和取消均建立新的请求世代并丢弃旧响应。收藏夹名称、选择和 cursor 不持久化、不离线排队，也不写进公开内容或全局缓存。

## 9. 加载、空数据、错误、重试和冲突状态

在途和确认期间禁用同一组按钮并忽略快速重复操作。写入直接成功或最新投影证明目标已达成时采用权威结果；读取到相反状态或读取失败时显示中性的“结果暂时无法确定”并提供刷新，不宣告失败也不重复提交。`40904` 仅在订阅列表精确存在目标记录时收敛为订阅完成，明确权限、参数和内容冲突仍显示失败。本人收藏首屏与关注/粉丝/黑名单首屏使用连续列表 Skeleton，把分类与列表加载错误分开恢复；“全部”空态提示从详情收藏，具体分类空态提示可从其他分类移动。新建弹窗保留输入并显示长度/同名错误，移动到当前分类本地 no-op；`40007` 清空游标并从当前筛选首屏重载。移动或取消写入已成功、后续权威刷新失败时采用安全本地结果并提示下拉刷新。缺少收藏记录 ID 时整页失败，不展示不可管理条目。订阅列表读取失败时整体失败并可重试；玩家候选为空时不显示玩家入口，候选读取失败时保留官方更新控件并在玩家区域提供独立重试，已失效候选在本地阻止写入。

## 10. 跨模块约束

关注、粉丝、拉黑与订阅候选中的具名头像统一回退用户名首个可读字符；匿名或不可用身份才使用中性状态图标。

threads 页面消费主题互动和订阅控制器，moments 详情使用同一收藏夹读取端口与动态移动端点，users 的“我的”页面进入 social 收藏/关系列表；通知计数不因写入伪造。点赞只使用响应计数，主题收藏和订阅只使用响应记录 ID，动态收藏移动使用动态 ID；玩家候选来自 threads 成员端点。收藏夹 `bookmarkCount` 与 `momentBookmarkCount` 分别使用服务端主题、动态原始记录计数，可能高于当前仍可见内容数，客户端不得从已加载页推算或断言相等。收藏页移动/取消不会主动改写仍存活的详情 Provider，跨页刷新仍以服务端为准。

## 12. 已知限制和后续功能

当前未建立跨页面互动事件总线，主题与动态收藏、订阅变化不会主动改写其他仍存活页面。动态收藏分类筛选和公开用户动态收藏虽已有服务端契约，但移动端尚未接入。后端订阅列表暂无按主题/类型筛选和分页参数，移动端目前必须读取本人完整订阅后过滤；数据量增长前需要补齐契约。后端当前没有收藏夹重命名或删除接口，移动端不伪造这些动作。不做离线关系队列或推荐偏好；视觉动效后置。
