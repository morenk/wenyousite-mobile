# 社交关系

状态：`in_progress`

## 1. 模块目标与非目标

统一收藏、关注、订阅、点赞和拉黑的读写状态。当前已交付主题点赞、收藏与两类订阅、公开用户页关注与拉黑，以及公开/本人关注、粉丝和本人黑名单列表；V1 不包含收藏表情或推荐算法配置。

## 2. 用户角色与使用场景

游客与登录用户可从公开主页查看服务端允许的关注和粉丝列表，也能看到主题喜欢计数；游客触发主题点赞先登录。普通登录用户可点赞、收藏主题，订阅楼主/协作者的官方更新，并按帖内已标记玩家订阅发言；楼主和协作者自动接收更新。登录用户还可管理公开关系及本人黑名单。

## 3. 页面、入口和导航关系

主题点赞、收藏和订阅入口位于 `/threads/:threadId` 详情头部；玩家发言订阅在移动端底部面板中逐人切换。带 `post` 目标时，游客登录回跳保留完整查询。关系按钮位于 `/users/:userId`；公开统计进入指定用户列表，“我的”通过三个 `/me/*` 路由管理关系与黑名单。本人收藏管理列表后续接入。

## 4. 用户操作流程

主题详情以服务端登录态投影初始化喜欢与收藏；订阅控制器并发读取本人订阅和帖内成员，只保留当前主题记录及 `PARTICIPANT + playerMarked` 候选，并排除本人。官方更新和玩家发言按创建返回的稳定记录 ID 取消，同一主题一次只执行一个订阅写入。点赞采用服务端计数，收藏与订阅保存记录 ID；关系写入成功后同步局部状态，失败均保持旧状态。

## 5. API operationId 与生成类型

- 已接入 `bookmarksCreate`、`bookmarksRemove`；`bookmarksFindAll` 后续用于本人收藏管理列表。
- 已接入 `subscriptionsFindAll`、`subscriptionsCreate`、`subscriptionsRemove`，并以 `threadMembersFindAll` 读取玩家候选。
- 已接入 `usersFollowFollow`、`usersFollowUnfollow`、`usersFollowBlock`、`usersFollowUnblock`。
- 已接入 `usersFollowFollowing`、`usersFollowFollowers`、`usersFollowUserFollowing`、`usersFollowUserFollowers`、`usersFollowBlocks`。
- 已接入 `threadsLike`、`threadsUnlike`。

## 6. 状态模型和数据流

`ThreadInteractionTarget` 管理点赞与收藏；`ThreadSubscriptionTarget` 以主题 ID 和当前成员用户 ID 为 family 键，并保存当前主题订阅、玩家候选、唯一在途目标与局部反馈，加载 epoch 丢弃旧响应。`UserRelationTarget` 管理关系写入；`UserRelationListTarget` 管理公开/本人列表。所有状态均为 autoDispose，当前不建立跨页面事件总线。

## 7. 鉴权、权限和隐私规则

所有写操作和 `/me/*` 关系列表需要登录。游客点赞只进入登录并保留帖子目标，收藏与订阅入口不显示。主题 capability 或当前成员角色表明楼主/协作者时隐藏订阅控件，因为服务端会自动通知；普通用户只能选择服务端成员列表中的已标记参与者，最终权限仍由后端校验。客户端不根据计数推断关系，也不允许游客读取私有列表。

## 8. 本地存储、缓存及失效规则

互动、订阅、关系写状态和列表只存在于 autoDispose Provider；离页、退出或切号即释放。主题刷新重新采用详情投影并读取本人订阅与候选，关系列表下拉刷新读取完整列表；不持久化、不离线排队，也不把状态写进全局缓存。

## 9. 加载、空数据、错误、重试和冲突状态

在途时禁用同一组按钮并忽略快速重复操作；点赞、收藏、订阅和关系写失败都保留原状态、请求 ID 和再次点击重试能力，空响应不伪装成功。订阅初始读取提供加载、失败与重试，玩家候选为空时不显示面板入口；已失效候选在本地阻止写入。关系列表保留完整空错刷新状态。

## 10. 跨模块约束

threads 页面消费 social 的主题互动和订阅控制器，users 页面消费关系控制器与列表页；通知计数不因写入伪造。点赞只使用响应计数，收藏和订阅只使用响应记录 ID；玩家候选来自 threads 成员端点，social 不自行推断成员身份。跨页刷新仍以服务端为准。
