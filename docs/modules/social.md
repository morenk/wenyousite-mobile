# 社交关系

状态：`in_progress`

## 1. 模块目标与非目标

统一收藏、关注、订阅、点赞和拉黑的读写状态。当前已交付主题点赞与收藏、公开用户页关注与拉黑，以及公开/本人关注、粉丝和本人黑名单列表；V1 不包含收藏表情或推荐算法配置。

## 2. 用户角色与使用场景

游客与登录用户可从公开主页查看服务端允许的关注和粉丝列表，也能看到主题喜欢计数；游客触发主题点赞先登录。登录用户可点赞与收藏主题、在他人公开主页管理关注与拉黑，并在“我的”查看本人关系和黑名单。本人主页不显示自我关系操作。

## 3. 页面、入口和导航关系

主题点赞与收藏按钮位于 `/threads/:threadId` 详情头部；带 `post` 目标时，游客登录回跳保留完整查询。关系按钮位于 `/users/:userId`；公开统计进入 `/users/:userId/following` 与 `/users/:userId/followers`，“我的”通过 `/me/following`、`/me/followers` 和 `/me/blocks` 管理本人列表。本人收藏列表与订阅入口后续接入。

## 4. 用户操作流程

主题详情以服务端登录态投影初始化喜欢、收藏和收藏记录 ID；同一主题的互动写入串行化，点赞采用服务端最新计数，收藏成功保存记录 ID 供取消使用，缺少 ID 时要求刷新而不发送错误删除。公开页先完成本人身份读取并排除自我目标，再显示关注与拉黑按钮；成功后同步关系与粉丝数，失败保持旧状态。拉黑前二次确认，解除拉黑不重复确认。公开统计读取指定用户列表，本人入口使用本人专用端点；黑名单取消拉黑成功后才移除条目。

## 5. API operationId 与生成类型

- 已接入 `bookmarksCreate`、`bookmarksRemove`；`bookmarksFindAll` 后续用于本人收藏管理列表。
- `subscriptionsFindAll`、`subscriptionsCreate`、`subscriptionsRemove`。
- 已接入 `usersFollowFollow`、`usersFollowUnfollow`、`usersFollowBlock`、`usersFollowUnblock`。
- 已接入 `usersFollowFollowing`、`usersFollowFollowers`、`usersFollowUserFollowing`、`usersFollowUserFollowers`、`usersFollowBlocks`。
- 已接入 `threadsLike`、`threadsUnlike`。

## 6. 状态模型和数据流

`ThreadInteractionTarget` 以主题 ID、详情登录态投影、喜欢数和收藏记录 ID 作为 family 键；控制器保存服务端权威互动状态、唯一在途动作和局部反馈，详情统计与按钮消费同一状态。`UserRelationTarget` 管理目标关系写入；`UserRelationListTarget` 区分公开用户和本人列表，列表控制器以加载 epoch 丢弃旧响应。所有状态均为 autoDispose，当前不建立跨页面事件总线。

## 7. 鉴权、权限和隐私规则

所有写操作和 `/me/*` 关系列表需要登录。游客可看到主题点赞入口，但点击只进入登录并保留 `/threads/:id?post=:postId`，不发写请求；收藏按钮只对登录会话显示。游客进入本人列表同样先登录并保留目标。公开页用 `usersGetMe` 成功结果排除自我关系操作；客户端不根据计数推断关系，也不允许游客读取黑名单。

## 8. 本地存储、缓存及失效规则

互动、关系写状态和列表只存在于 autoDispose Provider；离页、退出或切号即释放。主题或公开资料刷新用新的服务端投影建立状态，关系列表下拉刷新读取完整列表；不持久化、不离线排队，也不把状态写进全局缓存。

## 9. 加载、空数据、错误、重试和冲突状态

在途时禁用同一组按钮并忽略快速重复操作；点赞、收藏和关系写失败都保留原状态、请求 ID 和再次点击重试能力，空响应不伪装成功。列表提供加载、空、失败、重试与下拉刷新，后发刷新胜过先发旧响应。取消拉黑串行执行，失败保留条目，成功后才原地移除。

## 10. 跨模块约束

threads 页面消费 social 的主题互动控制器，users 页面消费关系控制器和列表页；通知计数不因写入伪造。点赞只使用响应中的最新计数，收藏只使用响应中的记录 ID。列表行只传稳定 userId 返回公开资料；跨页刷新仍以服务端为准。

## 12. 已知限制和后续功能
