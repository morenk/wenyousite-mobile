# 社交关系

状态：`in_progress`

## 1. 模块目标与非目标

统一收藏、关注、订阅、点赞和拉黑的读写状态。当前已交付主题点赞、收藏与两类订阅、本人收藏管理、公开用户页关注与拉黑，以及公开/本人关注、粉丝和本人黑名单列表；V1 不包含收藏表情或推荐算法配置。

## 2. 用户角色与使用场景

游客与登录用户可从公开主页查看服务端允许的关注和粉丝列表，也能看到主题喜欢计数；游客触发主题点赞先登录。普通登录用户可点赞、收藏主题，订阅楼主/协作者的官方更新，并按帖内已标记玩家订阅发言；楼主和协作者自动接收更新。登录用户还可管理公开关系及本人黑名单。

## 3. 页面、入口和导航关系

主题点赞、收藏和订阅入口位于 `/threads/:threadId` 详情头部；玩家发言订阅在移动端底部面板中逐人切换。“我的”提供 `/me/bookmarks` 管理本人收藏，并通过 `/me/following`、`/me/followers`、`/me/blocks` 管理关系。四个本人路径均保留登录回跳；公开关系和内容仍从 `/users/:userId` 进入。

## 4. 用户操作流程

主题详情以服务端投影初始化喜欢与收藏；本人收藏页按不透明游标分页，每条必须携带稳定收藏记录 ID。取消成功后原地移除；若删除的是服务端分页游标对应尾项，则回退到新的尾项 ID 再继续加载。订阅控制器并发读取本人订阅和帖内成员，官方/玩家订阅按记录 ID 取消。点赞采用服务端计数，所有失败均保持旧状态。

## 5. API operationId 与生成类型

- 已接入 `bookmarksFindAll`、`bookmarksCreate`、`bookmarksRemove`。
- 已接入 `subscriptionsFindAll`、`subscriptionsCreate`、`subscriptionsRemove`，并以 `threadMembersFindAll` 读取玩家候选。
- 已接入 `usersFollowFollow`、`usersFollowUnfollow`、`usersFollowBlock`、`usersFollowUnblock`。
- 已接入 `usersFollowFollowing`、`usersFollowFollowers`、`usersFollowUserFollowing`、`usersFollowUserFollowers`、`usersFollowBlocks`。
- 已接入 `threadsLike`、`threadsUnlike`。

## 6. 状态模型和数据流

`ThreadInteractionTarget` 管理详情点赞与收藏；`BookmarkListController` 管理本人收藏页、分页游标、加载更多和唯一在途取消动作；`ThreadSubscriptionTarget` 保存当前主题订阅、玩家候选与唯一在途目标。`UserRelationTarget` 管理关系写入，`UserRelationListTarget` 管理公开/本人列表。所有状态均为 autoDispose，当前不建立跨页面事件总线。

## 7. 鉴权、权限和隐私规则

所有写操作和 `/me/*` 私有列表需要登录；游客进入 `/me/bookmarks` 时先登录并保留原目标。游客点赞只进入登录，收藏与订阅入口不显示。主题 capability 或当前成员角色表明楼主/协作者时隐藏订阅控件；普通用户只能选择服务端成员列表中的已标记参与者。收藏列表由服务端过滤已失去访问权的主题，客户端不泄露失效私密条目。

## 8. 本地存储、缓存及失效规则

互动、订阅、收藏与关系列表只存在于 autoDispose Provider；离页、退出或切号即释放。主题刷新重新采用详情投影，收藏和关系列表下拉刷新从首屏重新读取；不持久化、不离线排队，也不把状态写进全局缓存。

## 9. 加载、空数据、错误、重试和冲突状态

在途时禁用同一组按钮并忽略快速重复操作；点赞、收藏、订阅和关系写失败都保留原状态、请求 ID 和重试能力，空响应不伪装成功。本人收藏提供加载、空、首屏失败、加载更多失败、下拉刷新和局部取消失败；缺少记录 ID 时整页失败，不展示不可管理条目。订阅候选为空时不显示玩家入口，已失效候选在本地阻止写入。

## 10. 跨模块约束

threads 页面消费主题互动和订阅控制器，users 的“我的”页面进入 social 收藏/关系列表；通知计数不因写入伪造。点赞只使用响应计数，收藏和订阅只使用响应记录 ID；玩家候选来自 threads 成员端点。收藏页取消不会主动改写仍存活的详情 Provider，跨页刷新仍以服务端为准。
