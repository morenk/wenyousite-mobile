# 社交关系

状态：`in_progress`

## 1. 模块目标与非目标

统一主题收藏、私有收藏夹分类、关注、订阅、点赞和拉黑的读写状态。当前已交付主题点赞、收藏与两类订阅、本人收藏夹管理、公开用户页关注与拉黑，以及公开/本人关注、粉丝和本人黑名单列表；收藏表情由独立 stickers 模块负责，本模块不包含推荐算法配置。

## 2. 用户角色与使用场景

游客与登录用户可从公开主页查看服务端允许的关注和粉丝列表，也能看到主题喜欢计数；游客触发主题点赞先登录。普通登录用户可点赞、收藏主题，在本人私有收藏页按“全部 / 默认收藏夹 / 自建收藏夹”筛选、新建分类并移动收藏，订阅楼主/协作者的官方更新，并按帖内已标记玩家订阅发言；楼主和协作者自动接收更新。登录用户还可管理公开关系及本人黑名单。

## 3. 页面、入口和导航关系

主题点赞、收藏和订阅入口位于 `/threads/:threadId` 详情头部；玩家发言订阅在移动端底部面板中逐人切换。“我的”提供 `/me/bookmarks` 管理本人私有主题收藏夹，并通过 `/me/following`、`/me/followers`、`/me/blocks` 管理关系。四个本人路径均保留登录回跳；公开关系和内容仍从 `/users/:userId` 进入，私有收藏夹名称和分类绝不进入公开用户页。

## 4. 用户操作流程

本人收藏页标题不重复解释收藏用途。

主题详情以服务端投影初始化喜欢与收藏，快捷收藏不传 folderId，继续进入服务端默认收藏夹。本人收藏页并行读取分类计数和“全部”首屏；“全部”只在本地合成，服务端默认收藏夹保持第一项，切换分类必须清空不透明游标并按 folderId 从首屏读取。新建名称发送前 trim 并校验 1–24 字，成功后自动选中新分类；每条收藏可从移动端底部选择器移动到其他收藏夹。移动或取消成功后重新读取当前筛选首屏和服务端分类计数，禁止从收藏记录 ID 构造游标。订阅控制器并发读取本人订阅和帖内成员，官方/玩家订阅按记录 ID 取消。点赞采用服务端计数，所有失败均保持旧状态。

## 5. API operationId 与生成类型

- 已接入 `bookmarksFindAll`、`bookmarksFindFolders`、`bookmarksCreateFolder`、`bookmarksMove`、`bookmarksCreate`、`bookmarksRemove`；详情快捷收藏仍不传可选 folderId。
- 已接入 `subscriptionsFindAll`、`subscriptionsCreate`、`subscriptionsRemove`，并以 `threadMembersFindAll` 读取玩家候选。
- 已接入 `usersFollowFollow`、`usersFollowUnfollow`、`usersFollowBlock`、`usersFollowUnblock`。
- 已接入 `usersFollowFollowing`、`usersFollowFollowers`、`usersFollowUserFollowing`、`usersFollowUserFollowers`、`usersFollowBlocks`。
- 已接入 `threadsLike`、`threadsUnlike`。

## 6. 状态模型和数据流

`ThreadInteractionTarget` 管理详情点赞与快捷收藏；`BookmarkListController` 独立保存服务端收藏夹、当前 `selectedFolderId`、分类错误、当前筛选分页和创建/移动/取消的唯一在途动作。分类读取失败不遮断“全部”收藏，列表筛选失败也不丢失已取得的分类。`ThreadSubscriptionTarget` 保存当前主题订阅、玩家候选与唯一在途目标。`UserRelationTarget` 管理关系写入，`UserRelationListTarget` 管理公开/本人列表。所有状态均为 autoDispose，当前不建立跨页面事件总线。

## 7. 鉴权、权限和隐私规则

所有写操作和 `/me/*` 私有列表需要登录；游客进入 `/me/bookmarks` 时先登录并保留原目标。收藏夹 ID、名称和计数仅属于本人，移动时收藏记录与目标收藏夹都由服务端复核归属，404 不猜测资源是否存在。游客点赞只进入登录，收藏与订阅入口不显示。主题 capability 或当前成员角色表明楼主/协作者时隐藏订阅控件；普通用户只能选择服务端成员列表中的已标记参与者。收藏列表由服务端过滤已失去访问权的主题，客户端不泄露失效私密条目。

## 8. 本地存储、缓存及失效规则

互动、订阅、收藏与关系列表只存在于 autoDispose Provider；离页、退出或切号即释放。主题刷新重新采用详情投影；收藏页下拉刷新并行重读当前筛选首屏与分类计数，分类切换、创建、移动和取消均建立新的请求世代并丢弃旧响应。收藏夹名称、选择和 cursor 不持久化、不离线排队，也不写进公开内容或全局缓存。

## 9. 加载、空数据、错误、重试和冲突状态

在途时禁用同一组按钮并忽略快速重复操作；点赞、收藏、订阅和关系写失败都保留原状态、请求 ID 和重试能力，空响应不伪装成功。本人收藏把分类与列表加载错误分开恢复；“全部”空态提示从详情收藏，具体分类空态提示可从其他分类移动。新建弹窗保留输入并显示长度/同名错误，移动到当前分类本地 no-op；`40007` 清空游标并从当前筛选首屏重载。移动或取消写入已成功、后续权威刷新失败时采用安全本地结果并提示下拉刷新。缺少收藏记录 ID 时整页失败，不展示不可管理条目。订阅候选为空时不显示玩家入口，已失效候选在本地阻止写入。

## 10. 跨模块约束

threads 页面消费主题互动和订阅控制器，users 的“我的”页面进入 social 收藏/关系列表；通知计数不因写入伪造。点赞只使用响应计数，收藏和订阅只使用响应记录 ID；玩家候选来自 threads 成员端点。收藏夹 `bookmarkCount` 使用服务端原始记录计数，可能高于当前仍可见主题数，客户端不得从已加载页推算或断言相等。收藏页移动/取消不会主动改写仍存活的详情 Provider，跨页刷新仍以服务端为准。

## 12. 已知限制和后续功能

当前未建立跨页面互动事件总线，主题收藏与订阅变化不会主动改写其他仍存活页面；详情快捷收藏暂不弹出分类选择，保持进入默认收藏夹。后端当前没有收藏夹重命名或删除接口，移动端不伪造这些动作。不做离线关系队列或推荐偏好；视觉动效后置。
