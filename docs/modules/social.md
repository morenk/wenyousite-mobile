# 社交关系

状态：`planned`

## 1. 模块目标与非目标

统一收藏、关注、订阅、点赞和拉黑的读写状态。V1 不包含收藏表情或推荐算法配置。

## 2. 用户角色与使用场景

登录用户管理主题和用户关系；游客看到计数和登录引导，不执行乐观写入。

## 3. 页面、入口和导航关系

关系按钮分布在主题、楼层和用户页；收藏/订阅/拉黑列表从“我的”进入。

## 4. 用户操作流程

用户点击后串行化同一资源写操作；可安全时乐观更新，失败回滚；拉黑前提示影响并刷新相关页面。

## 5. API operationId 与生成类型

- `bookmarksFindAll`、`bookmarksCreate`、`bookmarksRemove`。
- `subscriptionsFindAll`、`subscriptionsCreate`、`subscriptionsRemove`。
- `usersFollowFollow`、`usersFollowUnfollow`、`usersFollowBlock`、`usersFollowUnblock`、`usersFollowBlocks`。
- `threadsLike`、`threadsUnlike`。

## 6. 状态模型和数据流

关系键由类型与资源 ID 组成；每个键保存服务端状态、进行中动作和错误。列表与详情通过仓储事件同步。

## 7. 鉴权、权限和隐私规则

所有写操作需要登录；拉黑列表只属于当前用户。客户端不根据计数推断私人关系。

## 8. 本地存储、缓存及失效规则

只做会话内关系缓存；切号全部清空。服务端 404/403、拉黑变化或详情刷新使单键失效。

## 9. 加载、空数据、错误、重试和冲突状态

重复点击合并或排队；失败回滚并保留重试；服务端已是目标状态时按幂等成功处理；列表空状态给出解释。

## 10. 跨模块约束

主题与用户模块只消费关系仓储，不各自实现一套写入逻辑；通知计数不因乐观关系写入伪造。

## 11. 测试场景与验收条件

- [ ] 收藏、订阅、关注、点赞和拉黑增删闭环通过。
- [ ] 快速重复点击不产生错误最终状态。
- [ ] 失败回滚，列表与详情保持一致。
- [ ] 切号不泄露关系和拉黑列表。

## 12. 已知限制和后续功能

不做收藏表情、离线关系队列或推荐偏好；视觉动效后置。
