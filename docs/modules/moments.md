# 动态

状态：`in_progress`

## 1. 模块目标与非目标

实现独立于主题帖的短内容动态：发现/关注/用户信息流、按独立收藏夹分页的本人收藏双列瀑布流、详情、纯文本发布编辑、最多九图、本机自动草稿、删除、点赞、收藏、两层评论、评论图片、收藏表情、站内传送门与社区举报。动态正文不解析通用 Markdown，只按后端 v1 黄金契约激活合法站内坐标；不做视频、话题或离线自动发布。

## 2. 用户角色与使用场景

游客可浏览发现流、用户动态、详情与评论；登录用户额外查看关注流和本人动态收藏夹，发布、编辑或删除自己的动态，点赞/收藏，并发送纯文本、单图或单个收藏表情评论。服务端返回的 `canEdit`、`canDelete`、动态 `canInteract` 和评论 `canDelete` 是最终权限事实；`canInteract` 缺失按 true 兼容旧服务。

## 3. 页面、入口和导航关系

动态是四分支应用壳的 `/moments` 主分支，分为“发现”和“关注”；顶栏只提供全站搜索入口，不重复展示动态收藏入口。在任一主导航分支点击底栏中央发布动作都会先打开轻量选择器，选择“动态”后进入受保护的 `/compose/moment`。详情使用公开 `/moments/:momentId`，动态评论通知可附加 `?comment=:commentId` 精确定位；编辑使用受保护的 `/moments/:momentId/edit`。本人动态收藏从“我的”进入统一 `/me/bookmarks` 页面，以“主题 / 动态”页签切换类型并直接展示默认夹；指定收藏夹仍使用 `/me/bookmarks/moments/folders/:folderId`，旧 `/me/bookmarks/moments` 与 `/moments/bookmarks` 重定向到统一入口。公开用户主页通过 `/users/:userId/moments` 读取该用户动态。全站搜索的动态 Tab 以稳定 momentId 进入同一详情。

## 4. 用户操作流程

发现流与关注流统一按最后一条未删除评论时间倒序，无评论时按动态发布时间倒序；点赞、收藏、加油和编辑不改变位置。顶部“发现 / 关注”使用共享线性内容页签和底部选中线，支持点按或在信息流内容区左右滑动切换。发现、关注、收藏和用户信息流以 12dp 间距双列瀑布呈现，卡片只展示封面、两行标题、作者和点赞，正文、评论、收藏与加油进入详情处理。图片封面按服务端宽高预留比例，过长竖图最低收束到 3:4，多图显示数量；列表优先使用 feed，再回退 thumbnail、medium 和主图。纯文字封面固定 3:4，使用 Foundation 展示字体与服务端主题色，标题只在封面中出现一次。独立列表下拉刷新回到首屏，接近底部或按钮加载下一游标；分页追加、反复滚动到底或回顶时保持连续双列和完整滚动范围。嵌入“我的”动态页签时，列表加入本人主页的统一滚动链，不重复安装刷新层。

发布页依次展示图片区、2～40 字必填标题和最多 1000 字选填正文，底部安全区只保留全宽“发布”或“保存”主操作。无图时图片区仅显示一个 48dp“添加图片”入口；选中后才显示缩略图、剩余数量和继续添加动作。一次可选当前剩余容量，不打开裁剪页；后台最多推进两张 `MOMENT` 图片并保持原顺序，上传进度与失败直接显示在图片及图片区，失败可复用同一输入重试或取消。正文使用只支持普通文字与传送门原子的轻量输入器，不带格式工具栏或字数提示。标题、正文、封面与已完成图片顺序 500ms 防抖写入本机草稿；重新进入自动恢复，离页时明确选择保存或不保存。未完成图片不进入草稿，上传中或仍有失败批次时禁止提交。无图时由服务端返回确定性文字封面主题；编辑提交当前 `version`，删除需二次确认。

详情先以完整标题建立阅读层级，再展示作者、图片轮播、纯文本正文和累计加油；标题/正文保留内边距，轮播只保留页面级外边距。轮播与评论图片优先 medium，再回退 thumbnail 和主图；多图在固定舞台内横滑切换。点按图片进入共享全屏原图页，支持图库横滑、双击或捏合缩放、平移、未放大时下滑关闭和加载失败后切换候选。右上角“图片操作”始终针对当前图片：Android/iOS 可把主图原始字节保存到系统相册，登录且表情能力开启时还可按动态或评论的稳定 ID 添加到表情收藏；进行中禁止重复操作，失败留在当前图片并可重试。当前不提供分享或批量保存。正文与评论只把合法站内坐标渲染为可点传送门，普通 Markdown、外部地址、非法邀请和歧义查询保持完整字面文本。

详情首次收藏先打开动态收藏夹选择 Sheet，默认夹预选且可内联新建；用户确认后只发一次收藏写入，已收藏时点击直接取消。`canInteract == false` 时禁止新增收藏，既有收藏仍可取消。非本人动态的“加油 / 举报”放在正文后的有标签操作区，不占用顶栏。评论主列表默认最新，评论总数与“倒序 / 正序”直接排序同行；顶层评论按所选顺序展示，内嵌回复保持服务端正序。尚有未展示回复时使用与主题帖相同的普通字重、弱化前景“展开楼中楼（N 条）”入口和方向图标，命中区不小于 48dp。评论文字长按进入系统选字，作者、时间和非文字区域长按才打开操作菜单。详情右下角以紧凑悬浮入口发表评论；打开后使用唯一的私聊式轻量输入 dock，文字独占第一行，图片、表情和发送位于下方操作行。点击外部暗区或系统返回收起并在本页内保留未发送内容；评论最多 500 字，可带一张图片或一个收藏表情。详情按来源返回；无来源栈时返回动态列表。

评论正文文字长按进入系统选字，作者、时间、空白、图片、表情和传送门等非文字区域长按才打开帖子楼层同款中央遮罩窗口；窗口显示评论或回复操作标题，以对称栅格按权限展示复制、删除和举报，暗区阻断背景点击，点按暗区、显式关闭入口或系统返回均可退出。点击评论仍直接回复，菜单不再重复提供回复；评论输入继续使用原有 Sheet，排序按钮不打开 Sheet。

顶部“发现 / 关注”除点按页签外，也支持在信息流内容区左右滑动切换相邻栏目。内容按 Foundation standard 180ms 沿方向轻量入场，已访问栏目在当前页面生命周期内保持列表、分页与滚动状态，返回时不重新请求首屏；短滑与首尾越界保持当前栏目，瀑布流纵向滚动和下拉刷新继续由列表处理，减少动态效果时瞬时切换。

## 5. API operationId 与生成类型

- 信息流与详情：`momentsList`、按必填 folderId 调用的 `momentsBookmarks`、`userMomentsList`、`momentsDetail`。
- 搜索读模型由 search 模块调用 `searchSearchMoments`，映射为同一 `MomentCard`。
- 内容写入：`momentsCreate`、`momentsUpdate`、`momentsRemove`。
- 收藏目录与互动：`momentsBookmarkFolders`、`momentsCreateBookmarkFolder`、`momentsBookmark`、`momentsUnbookmark`、`momentsMoveBookmark`；首次收藏携带 folderId。
- 评论：`momentsCommentsList`、`momentsReplies`、`momentsCreateComment`、`momentsRemoveComment`；`momentsCommentAuthors` 保留契约与仓储映射，但详情页不再请求作者候选。
- 定位上下文：`momentsCommentContext` 按稳定 commentId 返回目标所在主评论、精确目标和当前可见回复数；第 17 个 Moments operationId 已接入通知定位主闭环。
- 图片收藏表情复用 stickers 模块的 `stickersImportMomentImage` 与 `stickersImportMomentCommentImage`，分别提交 `momentId + mediaId` 与 `momentCommentId + mediaId`。
- 社区举报：reports 模块调用 `reportsCreate`，分别提交 `MOMENT` 或 `MOMENT_COMMENT` 目标。
- 主要生成类型：`MomentCardResponseDto`、`MomentDetailResponseDto`、`MomentMediaResponseDto`、`MomentRootCommentResponseDto`、`MomentCommentResponseDto`、`MomentStickerResponseDto`、`CreateMomentDto`、`UpdateMomentDto` 与 `CreateMomentCommentDto`。

## 6. 状态模型和数据流

`MomentFeedController` 以 main/user target 隔离公开列表、游标、刷新、分页和单条互动写入；本人收藏由 `MomentBookmarkListController` 以必填 folderId 建立独立分页，保留本人收藏 DTO 的 `bookmarkFolderId` 与 `canInteract`，移动/取消后本地移除并权威刷新。`BookmarkFolderCatalogController` 通过动态专属仓储读取/创建目录，不与主题目录混用。`MomentMedia` 保存主图、显式派生 URL、contentType、animated 和尺寸，并为信息流与正文分别给出有序候选；仓储和搜索映射器对所有非空 URL fail-closed。`MomentFeedList` 通过滚动通知触发接近底部分页，因此独立页面可使用自身滚动位置，嵌入本人主页时也可继承父级滚动协调器；卡片与全宽尾部状态由同一懒加载瀑布流维护几何，稳定 Key 在刷新重排和分页追加时恢复既有卡片位置。`MomentDetailController` 同时读取详情与主评论；切换顶层顺序只重载一次主评论首页并清空原 cursor 与已展开回复。根评论内嵌回复与楼中楼分页均保留后端返回顺序，楼中楼分页固定请求 `OLDEST`。带评论坐标时，独立且按会话隔离的 `momentCommentContextProvider` 并行读取上下文；展示投影按 ID 去重，以上下文目标覆盖重复项，将缺失主评论按当前顺序注入，并把目标回复按最早顺序展开。上下文不改写普通列表 cursor，也不触发 `fetchComments` 或 `fetchReplies` 分页扫描。`MomentComposerController` 负责创建幂等键、编辑版本、冲突重试和删除确认结果；动态仓储与本机草稿存储端口位于 `moments/application`。用户在 `40002` 后选择“保留我的内容”时，控制器先读取最新详情和权限，再以最新 `version` 重交当前表单；选择“使用最新内容”时清除本机草稿并重载详情。动态发布页为未完成图片保留本地输入、独立任务状态和完成结果，最多两张在途；全部完成后一次按原顺序并入已上传列表。评论仍按页面实例消费单图上传任务。

信息流与详情的点赞/收藏状态记录精确在途动作，只锁定对应控件并保留旧选中投影，直到服务端回包覆盖。可写消费者统一使用 Foundation v6.5.1 的点赞/收藏语义色、透明选中容器和官方实心图标变体；搜索等只读消费者始终显示中性线性图标，不暴露按钮或 toggled 语义。

## 7. 鉴权、权限和隐私规则

发现、用户列表、详情与评论读操作允许游客；可选认证请求仍通过普通拦截器发送，以便登录用户取得 viewerLiked/viewerBookmarked 和权限投影。关注、收藏目录/内容及所有写操作要求登录，游客从当前安全路径进入登录回跳。动态编辑/删除只消费服务端 capability；收藏相关 `canInteract == false` 禁止新增收藏和移动，但允许取消，字段缺失按 true。其余点赞、评论与加油对该字段的消费仍是独立债务。举报入口用同一 `canEdit` 排除本人动态，评论则用当前 JWT `sub` 做保守本人隐藏，最终目标可见性和本人关系都由服务端复核。客户端不猜测隐藏动态、评论或被拉黑关系。预签名 URL、图片字节、评论正文和幂等键不落日志或持久化。

## 8. 本地存储、缓存及失效规则

动态列表、评论、排序、游标、上传进度和创建幂等键只保存在当前 Riverpod/页面生命周期；主分支按需构建“发现 / 关注”，已访问栏目在同一页面生命周期内继续挂载，栏目切换不释放其列表状态。评论定位上下文同样不持久化，按 momentId、commentId 和账号会话分区，详情下拉刷新以及评论创建/删除成功后失效重读。评论输入草稿也只保留在当前详情页内存，不写 SharedPreferences 或云端。发布/编辑表单例外：页面通过 `MomentDraftStore` 端口按新建或稳定 momentId 分区，data 适配器将标题、正文、已完成媒体的安全主 URL、可选派生 URL、contentType、animated、尺寸、封面 ID、图片顺序和更新时间写入 SharedPreferences；读取旧草稿时新增字段缺失按空派生图和非动画恢复。不保存源图片字节、未完成批次、预签名 URL 或 Token。进入页面自动恢复草稿但保留进入时基线供用户一键撤销；成功发布、保存、删除、选择最新内容或明确不保存后清除对应草稿。创建/评论请求在结果不明确时保留同一 `clientRequestId`；服务端确认成功后才轮换。图片使用共享安全 HTTP(S) 缓存；发布、编辑、删除和通知返回后失效相关信息流/详情。

## 9. 加载、空数据、错误、重试和冲突状态

全模块错误遵循[网络与会话](../architecture/networking.md)统一分级：可操作的预期失败只给恢复提示；本机、网络连接、温油站服务与内容处理异常才标注问题环节，只有可核对的服务/内容异常及结果待核对写入显示问题编号。普通页面不展示 HTTP、业务或内部诊断码，Debug 现场诊断可复制安全技术字段。

信息流空态只保留当前事实标题，不教学下拉、关注或发布。

发现、关注、收藏和用户信息流分别覆盖双列首屏骨架、空、首屏失败、刷新失败和分页失败；接近底部自动加载并保留显式“加载更多”后备入口，`40007` 丢弃失效 cursor 并回到首屏。详情首屏使用单列详情结构 Skeleton，区分不存在与网络失败，已加载内容刷新失败时继续保留可读事实。评论定位加载时在排序行后显示“正在定位评论…”；上下文 404 或 `40415` 保留动态与普通评论并显示“目标评论已不可见”，不提供无意义重试；网络或 5xx 失败只为定位请求展示安全文案、问题编号和“重试定位”。`40002` 显示“这条动态刚刚更新了”，并明确提供“保留我的内容 / 使用最新内容”，不静默覆盖本机输入；其他 `40415` 收敛为动态或评论已不存在；不明确创建/评论失败保留原输入与同一幂等键。上传失败在当前本地缩略图与图片区复用同一图片重试或取消剩余批次；已经完成的同批图片保留，处理中与未解决失败批次均禁止提交，只有用户确认退出后才取消任务并忽略迟到结果。

动态评论和回复的复制结果只由系统剪贴板写入决定；复制时保留普通正文，只把传送门、提及、骰子和规范表情等行内原子替换为阅读态可见 label，不写入目标地址或协议节点。写入成功后显示短确认，确认提示异常不显示“复制失败”也不重复复制，只有写入本身失败才保留关闭与重试任务。

## 10. 跨模块约束

动态作者头像、发布时间与互动计数复用 Foundation 共享身份和格式化组件；短时间同时提供完整时间语义，紧凑计数的操作语义保留服务端原值。

media/application 提供相册与上传端口、唯一任务状态、取消、失败和同文件重试；共享上传横幅直接消费任务阶段与进度，不在各编辑器重复推导文案。moments presentation 不直接导入 media/data 或 Dio，只消费完成结果并维护最多九图、封面顺序及评论图片/表情互斥。stickers 提供用户私有收藏选择器；notifications 只传稳定 momentId 和可选 momentCommentId；users 暴露公开用户动态入口；search 复用动态卡片；wallet 维护加油幂等写入；reports 管理举报。动态正文和评论始终是纯文本，不进入 Markdown/Quill Codec。合法站内坐标由共享阅读组件渲染成 Foundation v6.5.1 传送门胶囊。视觉只消费 Foundation v6.5.1 Token、元素契约、语义图标与图片角色；发现、关注、收藏和用户信息流显式消费双列瀑布流领域例外，详情保持单列和不超过 600dp，独立操作命中区不小于 48dp。

## 12. 已知限制和后续功能

动态发布支持按剩余容量一次多选、不经裁剪并以有界流水线处理，评论附件仍一次一张且同样不经裁剪；本机草稿不跨设备同步，也不后台自动发布。未完成本地缩略图只存在于当前发布页，页面或进程释放后不能恢复。全屏图库具备规范核心手势，但暂不显示下载/分享入口。动态加油已由 wallet 接入；当前不在信息流卡片直接弹出写入，以详情作为稳定确认上下文。本人动态收藏已按独立目录和收藏夹筛选；公开用户页尚未接入公开动态收藏分页。`canInteract` 对点赞、评论和加油的完整消费仍需独立收敛。传送门 v1 只做语法识别，不预取目标标题或权限，最终可见性由目标页面服务端请求决定；邀请 token 除正文/评论本身外不写日志、诊断或独立缓存。
