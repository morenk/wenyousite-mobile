# 应用壳

状态：`in_progress`

## 1. 模块目标与非目标

提供启动兼容检查、四栏主导航、游客模式、全局网络/错误状态和创建入口。当前不实现 FCM、暗色主题、App Links 或业务列表内容。

## 2. 用户角色与使用场景

游客可直接进入首页和搜索；已登录用户额外使用通知、创作和个人功能。所有用户在启动时都要确认服务端契约可兼容。

## 3. 页面、入口和导航关系

启动门禁包裹 `/home`、`/search`、`/notifications`、`/me` 四个保状态分支；悬浮按钮进入受保护的 `/compose/thread`。游客会先进入 `/auth/login?returnTo=/compose/thread`，可继续进入 `/auth/register`，登录或注册成功后恢复创建目标；会话撤销、盗用、锁定、注销或刷新失败时统一进入带原因的登录页，也可明确继续游客浏览。

## 4. 用户操作流程

启动调用元信息接口；主版本 3 且 Markdown v2 时恢复会话并进入目标页，未知主版本显示升级页，网络错误显示请求 ID 与重试。游客可浏览公开分支，触发创建主题时保存目标并进入登录页；已登录用户可在“我的”安全退出当前终端。

## 5. API operationId 与生成类型

- `metaGetMeta` → `MetaGetMeta200Response`、`ApiMetaResponseDto`。

## 6. 状态模型和数据流

启动状态为 checking、ready、incompatible、failed；环境与会话由 Riverpod 注入。go_router 只消费可导航状态，不发起网络请求。

## 7. 鉴权、权限和隐私规则

壳层不假定游客有写权限。升级与错误页不得展示 Token、响应正文或敏感 URL，只允许显示请求 ID 和安全提示。

## 8. 本地存储、缓存及失效规则

契约结果只在本次进程缓存；每次冷启动重新检查。Token 由认证模块的安全存储管理，壳层不直接读写。

## 9. 加载、空数据、错误、重试和冲突状态

检查期间显示明确进度；断网可手动重试；未知主版本不可绕过。业务分支的空状态由各模块负责。

## 10. 跨模块约束

遵循[导航](../architecture/navigation.md)和[网络与会话](../architecture/networking.md)；主粉 `#FB7299`、背景 `#FFF7FA`，Android 竖屏优先。

## 11. 测试场景与验收条件

- [x] 兼容元信息进入四栏首页，游客无需登录。
- [x] 主版本未知时只显示升级页；网络失败可重试且有请求 ID。
- [x] 会话失效进入带原因的登录页，并可回到游客首页。
