# 楼层与回复

状态：`in_progress`

## 1. 模块目标与非目标

当前完成子贴楼层阅读、独立楼中楼分页，以及楼层、回复和子贴正文的创建、编辑、软删除与社区举报主链。V1 不记录阅读进度，不离线自动发帖，也不在移动端提供已删除内容恢复。

## 2. 用户角色与使用场景

游客可阅读公开主题的楼层和楼中楼；登录用户可按子贴发言策略发表楼层或回复。帖子作者可编辑和删除自己的楼层/回复，主题管理者还可在主题详情删除普通楼层；楼主或协作者可添加、编辑子贴正文。服务端始终是最终权限权威。

## 3. 页面、入口和导航关系

主题详情在当前子贴正文下连续展示升序楼层；子贴正文长按复用帖子中央遮罩操作窗口，所有读者可复制正文或公开链接，只有主题管理者可直接打开 BODY 编辑器，空正文则为管理者显示“添加正文”。点击楼层非交互正文或元信息区域直接回复该层；楼层和内嵌楼中楼头像拥有独立 48dp 入口并进入 `/users/:userId`，不会触发外层回复。普通楼层正文不按内容长度或视口高度折叠，直接完整显示；从正文文字区域纵向拖动会直接滚动主题页，长按拖动可跨段落连续选择文字。楼中楼固定最多预览服务端内嵌的前三条，不再按真实高度裁切或绘制渐变；只要存在回复，即使只有一条也始终显示“展开楼中楼”入口并进入 `/threads/:threadId/posts/:postId/replies` 独立页，前三条以外只在独立页查看，短预览直接点按未删除回复仍会回复该条。楼层卡片不再常驻“N 条回复”按钮，零回复也不创建预览。链接、正文图片与内嵌回复保留各自手势，不被整层点击吞并；正文文字长按只进入系统选字，作者、时间、楼层号、空白及骰子、图片、传送门等非文字节点长按才打开中央操作窗口，提供复制内容、复制链接、编辑、删除和举报，回复仍由整层点击进入而不在菜单内重复出现。右下角仍提供不占正文布局高度的紧凑发表入口。可选 `?post=:replyId` 精确定位目标回复；搜索、公开用户最近回复和通知使用 `/threads/:threadId?post=:replyId` 时，客户端解析父楼层后直接打开独立讨论，返回主题不重复跳转。独立页同样使用悬浮入口回复原楼层；主楼层和每条回复的头像独立进入作者主页，头像手势优先于整卡回复手势。点击任意未删除、非提交中的具体回复会把它作为 `replyToPostId`，主楼层继续作为 `parentPostId`。独立页按路由 `threadId` 读取权威主题可见性和管理 capability：公开非本人内容才显示举报，楼主/协作者可删除普通主楼层及回复；查询参数不参与权限判断，直接深链同样 fail-closed。

主题详情中的内嵌楼中楼不再为每条回复绘制圆角卡片、描边或底色；整个回复组的 2dp 左侧引导线内移 12dp，回复内容再内缩 12dp，同级回复之间只保留轻分隔线，“展开楼中楼”使用无常驻边框的安静操作。

## 4. 用户操作流程

主题详情的主楼控制行与独立讨论复用同一个“总数 + 作者下拉框 + 顺序切换”组件。作者候选按当前子贴或根楼层只返回实际发言者，并显示楼主、协作者或玩家角色；作者触发器按内容收缩且最宽 112dp，菜单以 160～260dp 独立宽度展示完整候选；作者与“正序 / 倒序”按钮统一使用 12sp 安静排版，选择作者或点击顺序会分别立即重载首屏并保留另一项条件。切换子贴时恢复全部作者但保留顺序；筛选结果为空可直接查看全部楼层。主楼筛选只约束服务端主楼列表，卡片中的楼中楼预览保持完整。

选择子贴或进入独立讨论后先沿不透明 cursor 加载首屏 20 条；首帧交付后，当前页按相同排序与作者筛选串行预取全部剩余文字页，每次只保留一个请求在途并逐页按 ID 合并。主题详情与独立讨论固定预布局可见区前后各两个视口，约覆盖五个手机视口；楼层或回复首次进入该邻域并完成构建后，其文本渲染树保留到当前阅读页释放，滑走再返回不会重新解析 Markdown 或重新创建可选择文本。父页面因后续分页或操作状态刷新时继续复用已构建渲染树，只有正文、字号、主题依赖或交互能力实际变化才失效。纯文字正文绕过 Markdown 语法树并保持原段落间距，任何可能带格式、提及、骰子、传送门或图片的正文继续走完整解析；网络图片只在条目首次进入两屏缓存邻域时创建与加载，不随文字页预取一次拉取。楼层和独立回复使用连续列表、留白与分隔线；精确目标只显示 1dp Foundation 淡粉边框，不铺底色、不扩大到整组上下文，也不展示“已定位到”可见说明，1.2 秒后按 slow motion 淡出，减少动态效果时直接复原。首次定位期间可随排序、筛选和异步内容布局重新对齐；用户开始纵向拖动后立即释放当前坐标吸附，后续布局变化不再拉回目标，目标、排序或筛选上下文变化时才开启新一次定位。页面内容不播放入场、目标滚动、字体或卡片弹出动画；真实页面入栈和返回只使用全局 180ms 水平位移。异步骰子结果只更新自己的内联标签，不重建全文。楼层号、回复对象和发布时间均为弱化的次级文字，等级以用户名旁按内容收缩的小徽标呈现，禁止拉伸到容器宽度；主题流只创建前三条楼中楼的轻量预览，完整回复串只在独立回复页出现。普通正文图片保持 `contain` 和自身宽度，在可用内容列左侧独占一行且不与前后文字并排，不永久叠加收藏按钮，整张图只作为原图入口；共享黑底原图页提供缩放、平移和下滑关闭，登录且表情能力开启时再从顶栏图片操作按需收藏。发布时间优先显示“x分钟前 / x小时前 / x天前”，更久后才显示日期。独立回复页先校验主楼层，把主题名与“子贴 · 楼层”压入始终可见的 48dp 阅读顶栏，正文区不重复相同语境；回复区常驻总数、最宽 112dp 的范围作者下拉框和显示当前“正序 / 倒序”的内容宽度切换按钮；两者使用一致字体，下拉菜单不随窄触发器被压缩。选择回复者或点击顺序会分别立即重载首屏并保留另一项条件；作者目录只列出当前根楼层下实际回复的楼主、协作者和已标记玩家。候选读取失败显示独立重试入口，顺序与正文仍可用；首屏外的精确目标会额外读取并注入正确位置。登录用户从主题详情悬浮入口发表当前子贴楼层，从独立页悬浮入口回复原楼层，或从具体回复动作带入指定目标；三个入口都复用同一可扩展半屏 Quill 编辑器。悬浮入口按文案收缩、保留 48dp 命中区且不扣减正文视口高度；顶栏与入口在所有滚动方向、分页加载和身份变化后都固定常显，不播放位移、缩放或淡入动画，列表末尾额外留白避免遮挡。编辑器顶栏只保留当前目标与展开操作，提交固定在键盘工具栏，正文以 17sp、1.8 行高直接占据连续页面画布，不再套说明行、圆角面板或底部整宽提交区；320～400dp 键盘态的整排格式栏改为 48dp 浮动入口，键盘避让与格式托盘展开均在一帧内到位、不播放尺寸或位移动画，同时保留全部格式能力且不丢焦点或选区。打开后自动聚焦，编辑或恢复已有正文时光标落在文末。游客在相同位置进入登录并保留当前目标。作者可打开同一编辑器修改内容，管理者可在主题详情删除楼层。管理者长按已有子贴正文、点按空正文的添加入口，或使用主题详情右上角操作，均打开同一 BODY 半屏编辑器；主题设置与子贴管理不再提供第二套正文编辑入口。所有已有主题帖子编辑器输入 `@` 均以当前 `threadId` 查询候选并插入规范提及节点。主题详情楼层、独立讨论主楼层和回复都不常驻举报/编辑/删除按钮；正文文字长按保留系统选择，作者、时间、楼层号、空白和非文字节点长按打开操作菜单，按权限集中提供复制正文、复制楼层链接、编辑、删除和举报。

主题流创建最多三条轻量楼中楼预览：短预览直接点按具体回复，只要存在楼中楼就始终可通过“展开楼中楼”进入独立讨论，不再按预览高度折叠；独立讨论的主楼层和每条回复正文也可直接点按回复，链接与图片仍优先处理自己的交互。发表新楼层后只刷新主题元信息并通过 `post` 坐标定位新楼层，不重新读取首屏楼层窗口。

编辑已有楼层、回复或子贴 BODY 时，半屏入口先读取该帖最新版并在完成前不创建可输入编辑器；读取失败可重试或关闭。页面内保留的本机修改若仍基于同一版本则随最新版版本继续编辑，若最新版已经包含相同正文则清除临时草稿；只有两边正文都发生变化时才先让用户选择使用最新版或继续编辑本机内容。

楼层、回复与子贴 BODY 编辑器允许普通正文和收藏表情在同一段混排。打开表情选择器前固定当前选区，返回后以无富文本属性的原子节点一次替换；创建或更新时 `content` 保存正文与 `wenyousite-sticker:v1` 标记组成的完整 Markdown，不拆分为独立附件，也不因光标处存在待应用样式而进入“不能安全保存”状态。

骰子额度按单个 Post 正文计算：当前子贴 BODY、每个楼层和每个楼中楼回复分别最多 20 个，不按整条子贴累计。编辑托盘在标题副行把待掷表达式与 `N/20` 合并显示，常用面数直接在键盘上方的横向滑动栏选择且不收起输入焦点；达到上限时原位提示先删除一个骰子，允许第 20 个并阻止第 21 个。楼层和回复允许仅含骰子，已发布子贴 BODY 必须包含非骰子文字。

楼层与回复的长按菜单复用核心中央操作窗口：页面其余区域统一暗淡并阻断背景点击，窗口不依赖楼层在视口中的位置；窗口显示“楼层操作 / 回复操作”标题，图标在上、短标签在下，四项按 2×2、五至六项按三列对称排布，点按暗区、48dp 显式关闭入口或系统返回均可退出且不会触发背景操作，选择后才执行复制、编辑、删除或举报。需要筛选、创作和连续滚动的完整任务继续使用 Bottom Sheet。

楼层、独立讨论主楼层、非根回复和主题流内嵌回复都使用 17sp、1.8 行高的共享 Markdown 阅读样式，不通过缩小正文牺牲可读性。主题流相邻顶层楼层与独立讨论顶层回复都使用 Foundation `input` 的 1dp 分隔线和 24dp 总节奏；正文内 Markdown `---` 仍使用更浅的 `border` 1dp。主题流内嵌回复以整体右移的共享左侧引导线、更深缩进和同级轻分隔线表达层级，不再逐条卡片化。

共享 Markdown 阅读器会把旧客户端写入的顶层连续空行恢复成逐个真实空段，普通段落边界仍只计算一次；首部与尾部空行按协议规则保留，围栏代码、缩进代码和原始 HTML 块保持字面内容。连续 `<br />` 各自贡献 17sp/1.8 的正文行高并在阅读态完整保留；搜索和列表紧凑预览继续把这些空白折叠为单个分隔。创建或编辑楼层、回复时，键盘连续回车和粘贴产生的新空段会在实际 `postsCreate`、`postsUpdate` 或 `postsUpsertBody` 载荷中逐段写为 canonical `<br />`，不会在发布时被末行换行属性吞掉。

新建楼层、新建回复及恢复同目标未发送草稿默认使用视口 40% 高度；编辑楼层、回复或子贴正文默认 52%，均可在 30%～94% 间拖动。更多、链接或骰子托盘需要更大空间时，仅补足标题、实际工具区与 96dp 正文画布，关闭托盘后恢复；用户手动拖动或展开后不再自动回缩。所有帖子模式都不显示左上角 X，点击编辑器外部会直接刷新 Markdown、保存页面草稿并返回原讨论，内层托盘不会先行拦截；系统返回仍先关闭内层托盘再关闭编辑器。

## 5. API operationId 与生成类型

- 阅读：`postsFindFloors` 使用查询参数 order 与可选 authorId 读取主楼层，`postsFindById` 定位目标，`postsFindReplies` 读取独立讨论；`postsFindFloorAuthors` 按子贴返回实际主楼作者，`postsFindReplyAuthors` 按根楼层返回实际回复作者。`postsFindLatestInThread` 直接返回主题全部存活子贴内最新有效主楼层或回复的稳定坐标，由主题详情顶栏按需调用。
- 写入：`postsCreate`、`postsUpdate`、`postsUpsertBody`、`postsRemove`；提及候选复用 editor 的 `usersMentionCandidates`；社区举报复用 reports 的 `reportsCreate`。
- 主要生成类型：`FloorResponseDto`、`ReplyResponseDto`、`PostDetailResponseDto`、`PostResponseDto`、`LatestThreadPostResponseDto`、`CreatePostDto`、`UpdatePostDto`、`UpsertBodyDto`、`ApiPaginationMeta`。

## 6. 状态模型和数据流

主题详情继续维护所选子贴的楼层页。独立讨论以主楼层 ID 为 family key，分离主楼层、回复页、cursor、排序、作者筛选、刷新、后台预取和分页错误；排序或作者每次直接操作只触发一次首页重载，分页合并按 ID 去重并按时间重排。`isPrefetchingFloors` 与 `isPrefetchingReplies` 只描述当前文字页串行预取任务，筛选、子贴、刷新和会话请求 epoch 变化会立即使旧任务失效，迟到页不得合并。posts application 分别以子贴 ID 和根楼层 ID 建立 autoDispose 作者目录 family，直接保持范围接口的稳定顺序；它们与讨论列表加载/失败隔离，切号时自动失效，创建或删除后刷新，编辑不刷新。目录成功刷新且已选作者消失时自动恢复全部作者；加载或失败不能清除现有筛选。刷新失败与加载更多失败记录各自重试来源，不会互相误用；读取、刷新或分页收到 403/404 时立即进入 restricted 终态并清空主楼层、回复与 cursor，防止旧私密内容继续显示。主题可见性和管理能力通过 posts application 的只读 `PostThreadContext` 端口获取，不直接读取 threads 页面状态。帖子读写端口位于 `posts/application`，API 适配器由 `main.dart` 组合根绑定，三个控制器不导入具体 data 仓储。帖子编辑器只持有 Markdown、当前版本、提交结果、待确认创建和冲突最新版；图片上传会话由 `media/application` 独立管理，不进入 `PostComposerState`；删除使用独立串行状态。相关 family 监听稳定账号会话作用域，Token 刷新不重建内容；切号或会话结束会关闭旧编辑器、清空页面内草稿并释放旧状态，迟到的旧账号加载、草稿回调或提交结果不得进入新会话。

主题详情控制器额外维护主楼顺序与作者组合及同一请求 epoch；加载更多、刷新与 `40007` 恢复持续携带当前组合，迟到的旧筛选响应会被丢弃。目标主楼若被当前作者筛选排除，页面先清除作者筛选并提示，再按服务端目标事实定位，不直接注入筛选外内容。

页面内帖子草稿同时保存正文、目标帖子 ID、打开时版本和基线正文。编辑入口读取最新版后再决定安全恢复、清除已保存草稿或显示分叉选择；编辑器控制器始终使用这次读取到的当前版本提交，不复用列表或深链目标中的旧版本。

## 7. 鉴权、权限和隐私规则

游客写入口进入登录并保留当前主题目标，不发送受保护请求。作者身份由当前会话 JWT `sub` 仅用于显示本人动作，服务端仍复核作者、主题管理能力、访问权限、双向拉黑和 postingPolicy；`40302`、`40303` 分别稳定提示协作者或玩家限制。独立页读取权威主题 capability 后允许主题管理者删除普通主楼层和回复，作者仍可编辑/删除本人内容；举报只对权威公开主题中的非本人、未删除目标开放。URL 查询参数、本机身份与删除能力都不等同于举报授权，最终目标事实仍由服务端复核。BODY 帖不能走普通删除。

## 8. 本地存储、缓存及失效规则

楼层、回复和写入状态只保留在当前 Riverpod/页面会话，不写 Drift。半屏编辑器点击外部时先刷新 Markdown，再收起键盘与编辑器，当前 Markdown 按目标保存在页面内输入草稿，再次打开同一目标自动恢复；页面销毁或进程终止后释放，默认不上传云端。用户可在正文草稿面板为当前编辑器显式开启槽位 1 自动保存；关闭面板后继续随编辑写入，关闭编辑器、切号或发生冲突时停止。帖子本身不建立本地离线发件箱；提及候选也只按当前主题保留在 autoDispose 状态，正文保存规范 userId 而不保存候选列表。切号、权限变化、页面释放、主题 403/404 或筛选变化会释放对应状态；写入确认后清除当前输入草稿并重新读取服务端事实。

帖子更新确认后立即失效对应的目标定位缓存，再刷新主题元信息或独立讨论；主题详情仍保留当前楼层、cursor 和滚动窗口，新的帖子事实由目标读取覆盖，避免后续编辑再次拿到保存前版本。

## 9. 加载、空数据、错误、重试和冲突状态

契约 5.12.2 起，指定 `replyToPostId` 时必须同时提交同一主楼层的 `parentPostId`；当前回复目标模型和生成请求已固定成对提交。非法组合返回 HTTP 400 时保留编辑内容与问题编号并交给用户处理，不自动重放或改挂到其他楼层。

楼层与回复分别覆盖结构化首屏 Skeleton、空、失败、下拉刷新、后台预取失败和加载到底；作者目录加载、失败和无候选分别显示紧凑禁用态、重试入口和空态，不替换已加载正文，也不阻断排序。预取失败保留首屏及已成功合并的页，尾部重试继续当前 cursor；`40007 INVALID_CURSOR` 从当前筛选第一页恢复，同一预取任务最多自动恢复一次，连续失效则停止并提供重试。刷新错误只重试刷新，预取错误只重试剩余页。403/404 视为不可继续读取的权限终态并清空旧内容，不提供可能反复泄露状态的普通重试。创建请求每次用户操作生成 UUID v4；超时、连接失败或 5xx 时，在编辑器仍打开期间保留原载荷和 `clientRequestId`，用户继续编辑后会先确认原创建，再以版本更新保存当前正文。提交在途时系统返回、外部点击和重复入口均被锁定，只有结果明确后才关闭；上传在途返回则先取消任务再退出。正文版本冲突只认 `40002`，仅在业务码缺失时兼容 HTTP 409；回读最新版已等于待保存 Markdown 时按完成收敛，内容确实不同才要求明确确认覆盖。`postsUpdate` 和 `postsUpsertBody` 都禁止超时、5xx 或登录续期后的网络层自动重放，结果不明时保留正文并由用户重试；`40912` 仍只用于废弃创建冲突幂等键。`40003` 提示骰子格式无效，`40004` 明确当前正文最多 20 个骰子。图片选择后先裁剪再上传，上传失败保留当前正文，并可在当前 Sheet 内重试同一裁剪文件；关闭 Sheet、主动取消或进程终止会释放该上传任务。帖子删除返回 `40403` 时按已经删除收敛。正文或链接复制失败以不可点击背景的任务弹窗提供关闭和重试，复制成功才显示短确认。空响应不伪装成功。

独立讨论主楼层与回复的“复制内容”把原始 Markdown 和服务端骰子显示结果交给 editor 的 clipboard v2 阅读态写入器：文本样式与传送门、提及、骰子语义只保存在当前进程 Delta，Android 系统剪贴板只写干净的可见 `text/plain`；图片和表情只写 `[图片]` / `[表情]`，不携带 URL 或资产 ID。同一松散列表项目之间的 Markdown 空白和同一引用内的空 `>` 行只承担阅读结构，不作为编辑器空段；明确的 `<br />` 与不同块间距继续保留。随机 marker、当前登录会话、十分钟时效和可见文本全部匹配时，本站编辑器恢复结构并为复制的骰子生成新 ID、丢弃结算结果；原生文字选区、跨设备只传文本、进程重启或任一匹配失败时按普通文本粘贴。复制失败先清除结构载荷，显式重试重新捕获并写入；短成功确认无法显示时记录脱敏诊断，不得回退成“复制失败”或再次写入相同正文。

专用现场诊断 Debug 包在首个稳定成功帧或首屏读取失败后输出 `post_detail_render_result` 到 Android 日志，字段仅包含应用/构建版本、系统与机型、申明的渲染器与 A/B 变体、读取结果、内容类型与块数、正文滚动视口尺寸、有效键盘 inset、失败阶段、错误码和耗时。失败阶段统一为 `fetch`、`parse`、`layout`、`media_decode`、`webview_process`、`draw`；当前原生 Flutter 链路直接使用其中适用阶段。读取成功但正文滚动视口任一边为零时固定记录 `layout` / `zero_scroll_viewport`，不得上报成功。启用诊断时同时把该事件和调用堆栈写入进程内诊断缓冲区，并在就绪后首帧、750ms 与 2500ms 记录路由、Scaffold、AppBar、滚动视口、题头、正文、Markdown 和底栏的真实布局几何；测试者可从全局“诊断”入口连同原始/有效窗口指标一键复制。普通用户 Debug 与 Release 包默认不调度上述采集；日志与复制内容不得包含正文、帖子 ID、用户令牌、账号、私聊内容或请求 URL。

## 10. 跨模块约束

楼层与回复阅读统一消费 Markdown v4 对齐，隐藏协议 marker 并只对普通段落和 H2/H3 应用布局；“复制内容”通过 clipboard v2 进程载荷保留合法对齐，系统 `text/plain` 不暴露 marker。

楼层与回复阅读和编辑重开共用行内格式边界兼容：标点或符号紧邻的粗体、斜体、粗斜体和删除线按原语义显示，不暴露星号、下划线或波浪线，也不插入可见空格；转义、代码、链接、图片、定义和畸形定界符仍按字面显示。

楼层与回复作者头像复用共享首字符降级；可见相对时间遵循 Foundation 72 小时窗口，组合楼层语义同时提供完整发布时间。

帖子创建、编辑、关闭前保留和五槽位正文草稿统一等待 editor 粘贴事务并从当前 Delta 重编码；外部复制内容只作为普通文本，编码失败或 10000 字符超限时保留半屏编辑器及页面内草稿，不提交缓存旧正文。

帖子输入复用 editor 的 Markdown ↔ Delta Codec、协议 embed 和五槽位正文草稿；图片上传任务复用 `media/application` 的共享控制器；服务端生成骰子结果，已结算节点通过结构化映射打开 Foundation 逐骰明细面板。主题详情提供子贴、capability、楼层和公开举报上下文，posts 通过明确只读端口读取主题事实，不直接读取 threads 页面状态；社区举报的原因、详情与重复待处理收敛由 reports 管理。视觉只使用 Foundation v6.5.0 Token、语义图标与共享组件，连续楼层/回复不使用逐条装饰面板；楼层与独立讨论复用核心头像按钮的安全图片降级、48dp 命中区和“查看个人主页”语义。

## 12. 已知限制和后续功能

帖子待确认创建只在当前不可随意关闭的编辑会话内保留，应用进程被系统终止后不自动恢复或发送；槽位 1 自动保存也不会在页面或进程释放后继续运行。讨论筛选作者目录只包含当前范围内存在有效内容的楼主、协作者和已标记玩家；提及继续使用独立的主题候选接口，不与讨论筛选目录混用。主题最新发言只按服务端坐标导航，不扫描子贴或帖子分页。图片密集正文的解码性能与更完整的已有 Markdown 富文本还原仍需后续专项处理。
