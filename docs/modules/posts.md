# 楼层与回复

状态：`in_progress`

## 1. 模块目标与非目标

当前完成子贴楼层阅读、独立楼中楼分页，以及楼层、回复和子贴正文的创建、编辑、软删除与社区举报主链。V1 不记录阅读进度，不离线自动发帖，也不在移动端提供已删除内容恢复。

## 2. 用户角色与使用场景

游客可阅读公开主题的楼层和楼中楼；登录用户可按子贴发言策略发表楼层或回复。帖子作者可编辑和删除自己的楼层/回复，主题管理者还可在主题详情删除普通楼层；楼主或协作者可添加、编辑子贴正文。服务端始终是最终权限权威。

## 3. 页面、入口和导航关系

主题详情在当前子贴正文下连续展示升序楼层；子贴正文长按复用帖子中央遮罩操作窗口，所有读者可复制正文或公开链接，只有主题管理者可直接打开 BODY 编辑器，空正文则为管理者显示“添加正文”。点击楼层非交互正文或元信息区域直接回复该层；楼层和内嵌楼中楼头像拥有独立 48dp 入口并进入 `/users/:userId`，不会触发外层回复。普通楼层正文的真实排版高度超过当前视口 1.2 倍时，先以视口 0.8 倍高度、底部渐变和“展开全文”呈现，展开后可从正文末尾收起。楼中楼最多预览服务端内嵌的前五条：真实预览高度超过 320dp，或回复总数大于当前可见数时，才显示唯一的渐变“展开全部 N 条回复”入口并进入 `/threads/:threadId/posts/:postId/replies` 独立页；两项都未触发时不提供进入独立页的界面入口，短预览直接点按未删除回复则回复该条。楼层卡片不再常驻“N 条回复”按钮，零回复也不创建预览。链接、正文图片与内嵌回复保留各自手势，不被整层点击吞并；楼层号只作弱化文字，不再承担“更多”按钮，复制、回复、编辑、删除和举报统一由长按打开的中央遮罩操作窗口承载。右下角仍提供不占正文布局高度的紧凑发表入口。可选 `?post=:replyId` 精确定位目标回复；搜索、公开用户最近回复和通知使用 `/threads/:threadId?post=:replyId` 时，客户端解析父楼层后直接打开独立讨论，返回主题不重复跳转，因此没有页面入口时仍可消费稳定深链。独立页同样使用悬浮入口回复原楼层；主楼层和每条回复的头像独立进入作者主页，头像手势优先于整卡回复手势。点击任意未删除、非提交中的具体回复会把它作为 `replyToPostId`，主楼层继续作为 `parentPostId`。独立页按路由 `threadId` 读取权威主题可见性和管理 capability：公开非本人内容才显示举报，楼主/协作者可删除普通主楼层及回复；查询参数不参与权限判断，直接深链同样 fail-closed。

## 4. 用户操作流程

主题详情的主楼控制行与独立讨论复用同一个“总数 + 讨论设置”组件。主楼面板显示楼层顺序和“只看发言者”，候选同样只包含楼主、协作者与已标记玩家；两项修改先留在本地草稿，显式应用后合并为一次首屏重载。切换子贴时恢复全部发言者但保留顺序；筛选结果为空可直接查看全部楼层。主楼筛选只约束服务端主楼列表，卡片中的楼中楼预览保持完整。

选择子贴后沿不透明 cursor 加载楼层；接近末尾或点击按钮继续分页。楼层和独立回复使用连续列表、留白与分隔线；精确目标只显示 1dp Foundation 淡粉边框，不铺底色、不扩大到整组上下文，也不展示“已定位到”可见说明，1.2 秒后按 slow motion 淡出，减少动态效果时直接复原。首次定位期间可随排序、筛选和异步内容布局重新对齐；用户开始纵向拖动后立即释放当前坐标吸附，后续布局变化不再拉回目标，目标、排序或筛选上下文变化时才开启新一次定位。页面不播放入场、目标滚动、字体或卡片弹出动画；异步骰子结果只更新自己的内联标签，不重建全文。楼层号、回复对象和发布时间均为弱化的次级文字，等级以用户名旁按内容收缩的小徽标呈现，禁止拉伸到容器宽度；主题流只创建前五条楼中楼的轻量预览，完整回复串只在独立回复页出现。普通正文图片不永久叠加收藏按钮，整张图只作为原图入口；共享黑底原图页提供缩放、平移和下滑关闭，登录且表情能力开启时再从顶栏图片操作按需收藏。发布时间优先显示“x分钟前 / x小时前 / x天前”，更久后才显示日期。独立回复页先校验主楼层，把主题名与“子贴 · 楼层”压入始终可见的 48dp 阅读顶栏，正文区不重复相同语境；回复区只常驻总数和单一弱化设置入口。底部设置面板只列出楼主、协作者和已标记玩家，普通参与人不进入候选；顺序与回复者先保留为面板本地草稿，用户点“应用”后才合并为一次首屏重载，非默认草稿才显示“恢复默认”。候选读取失败只影响回复者选择，可独立重试，顺序与正文仍可用；首屏外的精确目标会额外读取并注入正确位置。登录用户从主题详情悬浮入口发表当前子贴楼层，从独立页悬浮入口回复原楼层，或从具体回复动作带入指定目标；三个入口都复用同一可扩展半屏 Quill 编辑器。悬浮入口按文案收缩、保留 48dp 命中区且不扣减正文视口高度；顶栏与入口在所有滚动方向、分页加载和身份变化后都固定常显，不播放位移、缩放或淡入动画，列表末尾额外留白避免遮挡。编辑器只保留“关闭 / 当前目标 / 提交”紧凑顶栏，正文以 17sp、1.8 行高直接占据连续页面画布，不再套说明行、圆角面板或底部整宽提交区；320～400dp 键盘态的整排格式栏改为 48dp 浮动入口，键盘避让与格式托盘展开均在一帧内到位、不播放尺寸或位移动画，同时保留全部格式能力且不丢焦点或选区。打开后自动聚焦，编辑或恢复已有正文时光标落在文末。游客在相同位置进入登录并保留当前目标。作者可打开同一编辑器修改内容，管理者可在主题详情删除楼层。管理者长按已有子贴正文，或点按空正文的添加入口，均打开同一 BODY 半屏编辑器；主题管理工作台编辑非默认子贴时则在全屏表单中连同元数据保存 BODY。所有已有主题帖子编辑器输入 `@` 均以当前 `threadId` 查询候选并插入规范提及节点。主题详情楼层、独立讨论主楼层和回复都不常驻举报/编辑/删除按钮；长按卡片打开操作菜单，按权限集中提供复制正文、复制楼层链接、回复、编辑、删除和举报。

主题流创建轻量楼中楼预览：短预览直接点按具体回复，只有真实高度或未预览条数触发超限时才通过“展开全部”进入独立讨论；独立讨论的主楼层和每条回复正文也可直接点按回复，链接与图片仍优先处理自己的交互。发表新楼层后只刷新主题元信息并通过 `post` 坐标定位新楼层，不重新读取首屏楼层窗口。

骰子额度按单个 Post 正文计算：当前子贴 BODY、每个楼层和每个楼中楼回复分别最多 20 个，不按整条子贴累计。编辑托盘显示“当前正文 N/20”，允许第 20 个并阻止第 21 个；楼层和回复允许仅含骰子，已发布子贴 BODY 必须包含非骰子文字。

楼层与回复的长按菜单复用核心中央操作窗口：页面其余区域统一暗淡并阻断背景点击，窗口不依赖楼层在视口中的位置；图标在上、短标签在下，每行最多三项，使用 48dp 显式关闭入口或系统返回退出，选择后才执行复制、回复、编辑、删除或举报。需要筛选、创作和连续滚动的完整任务继续使用 Bottom Sheet。

楼层、独立讨论主楼层、非根回复和主题流内嵌回复都使用 17sp、1.8 行高的共享 Markdown 阅读样式；层级只由留白、分隔线、身份元信息和软面板表达，不再通过缩小正文牺牲可读性。

## 5. API operationId 与生成类型

- 阅读：`postsFindFloors` 使用查询参数 order 与可选 authorId 读取主楼层，`postsFindById` 定位目标，`postsFindReplies` 读取独立讨论；主楼与独立讨论的角色作者目录都复用 threads 的 `threadMembersFindAll`。
- 写入：`postsCreate`、`postsUpdate`、`postsUpsertBody`、`postsRemove`；提及候选复用 editor 的 `usersMentionCandidates`；社区举报复用 reports 的 `reportsCreate`。
- 主要生成类型：`FloorResponseDto`、`ReplyResponseDto`、`PostDetailResponseDto`、`PostResponseDto`、`CreatePostDto`、`UpdatePostDto`、`UpsertBodyDto`、`ApiPaginationMeta`。

## 6. 状态模型和数据流

主题详情继续维护所选子贴的楼层页。独立讨论以主楼层 ID 为 family key，分离主楼层、回复页、cursor、排序、作者筛选、刷新和分页错误；一次应用顺序与作者只触发一次首页重载，分页合并按 ID 去重并按时间重排。角色作者目录由 posts application 的独立 autoDispose family 读取完整主题成员后投影为楼主、协作者、玩家，并按角色再按加入时间排序；它与回复列表加载/失败隔离，切号时自动失效。刷新失败与加载更多失败记录各自重试来源，不会互相误用；读取、刷新或分页收到 403/404 时立即进入 restricted 终态并清空主楼层、回复与 cursor，防止旧私密内容继续显示。主题可见性和管理能力通过 posts application 的只读 `PostThreadContext` 端口获取，不直接读取 threads 页面状态。帖子读写端口位于 `posts/application`，API 适配器由 `main.dart` 组合根绑定，三个控制器不导入具体 data 仓储。帖子编辑器只持有 Markdown、当前版本、提交结果、待确认创建和冲突最新版；图片上传会话由 `media/application` 独立管理，不进入 `PostComposerState`；删除使用独立串行状态。相关 family 监听稳定账号会话作用域，Token 刷新不重建内容，切号或会话结束才释放。

主题详情控制器额外维护主楼顺序与作者组合及同一请求 epoch；加载更多、刷新与 `40007` 恢复持续携带当前组合，迟到的旧筛选响应会被丢弃。目标主楼若被当前作者筛选排除，页面先清除作者筛选并提示，再按服务端目标事实定位，不直接注入筛选外内容。

## 7. 鉴权、权限和隐私规则

游客写入口进入登录并保留当前主题目标，不发送受保护请求。作者身份由当前会话 JWT `sub` 仅用于显示本人动作，服务端仍复核作者、主题管理能力、访问权限、双向拉黑和 postingPolicy；`40302`、`40303` 分别稳定提示协作者或玩家限制。独立页读取权威主题 capability 后允许主题管理者删除普通主楼层和回复，作者仍可编辑/删除本人内容；举报只对权威公开主题中的非本人、未删除目标开放。URL 查询参数、本机身份与删除能力都不等同于举报授权，最终目标事实仍由服务端复核。BODY 帖不能走普通删除。

## 8. 本地存储、缓存及失效规则

楼层、回复和写入状态只保留在当前 Riverpod/页面会话，不写 Drift。半屏编辑器点暗区或关闭按钮时立即收起键盘与编辑器，当前 Markdown 按目标保存在页面内输入草稿，再次打开同一目标自动恢复；页面销毁或进程终止后释放，不自动上传云端。编辑器仍可手动使用后端五槽位正文草稿保存长内容，但帖子本身不建立本地离线发件箱；提及候选也只按当前主题保留在 autoDispose 状态，正文保存规范 userId 而不保存候选列表。切号、权限变化、页面释放、主题 403/404 或筛选变化会释放对应状态；写入确认后清除当前输入草稿并重新读取服务端事实。

## 9. 加载、空数据、错误、重试和冲突状态

楼层与回复分别覆盖结构化首屏 Skeleton、空、失败、下拉刷新、分页失败和加载到底；角色作者目录失败在设置面板独立展示并重试，不替换已加载正文。`40007 INVALID_CURSOR` 从当前筛选第一页恢复；刷新错误只重试刷新，分页错误只重试原 cursor。403/404 视为不可继续读取的权限终态并清空旧内容，不提供可能反复泄露状态的普通重试。创建请求每次用户操作生成 UUID v4；超时、连接失败或 5xx 时，在编辑器仍打开期间保留原载荷和 `clientRequestId`，用户继续编辑后会先确认原创建，再以版本更新保存当前正文。提交在途时系统返回、关闭按钮和重复入口均被锁定，只有结果明确后才关闭；上传在途返回则先取消任务再退出。`40912` 废弃冲突幂等键；`40002`/HTTP 409 读取最新版并要求用户明确确认后才覆盖；`40003` 提示骰子格式无效，`40004` 明确当前正文最多 20 个骰子。图片选择后先裁剪再上传，上传失败保留当前正文，并可在当前 Sheet 内重试同一裁剪文件；关闭 Sheet、主动取消或进程终止会释放该上传任务。帖子删除返回 `40403` 时按已经删除收敛。正文或链接复制失败以不可点击背景的任务弹窗提供关闭和重试，复制成功才显示短确认。空响应不伪装成功。

## 10. 跨模块约束

楼层与回复作者头像复用共享首字符降级；可见相对时间遵循 Foundation 72 小时窗口，组合楼层语义同时提供完整发布时间。

帖子输入复用 editor 的 Markdown ↔ Delta Codec、协议 embed 和五槽位正文草稿；图片上传任务复用 `media/application` 的共享控制器；服务端生成骰子结果，已结算节点通过结构化映射打开 Foundation 逐骰明细面板。主题详情提供子贴、capability、楼层和公开举报上下文，posts 通过明确只读端口读取主题事实，不直接读取 threads 页面状态；社区举报的原因、详情与重复待处理收敛由 reports 管理。视觉只使用 Foundation v6.2.0 Token、语义图标与共享组件，连续楼层/回复不使用逐条装饰面板；楼层与独立讨论复用核心头像按钮的安全图片降级、48dp 命中区和“查看个人主页”语义。

## 12. 已知限制和后续功能

帖子待确认创建只在当前不可随意关闭的编辑会话内保留，应用进程被系统终止后不自动恢复或发送；用户应先用五槽位草稿保存长正文。主楼发言者与独立页回复者筛选共用主题成员角色目录，只覆盖楼主、协作者和已标记玩家；成员角色在设置面板打开期间发生变化时，下次目录刷新才采用新事实。提及继续使用独立的主题候选接口，不与讨论筛选目录混用。后续仍需阅读性能专项和更完整的已有 Markdown 富文本还原。
