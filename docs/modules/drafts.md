# 草稿

状态：`planned`

## 1. 模块目标与非目标

提供本地自动快照与后端五槽位云草稿。V1 不做跨设备实时协作或后台自动发布。

## 2. 用户角色与使用场景

本地快照适用于正在编辑的所有用户会话；登录用户可手动保存、恢复和删除云草稿。

## 3. 页面、入口和导航关系

编辑器自动使用本地快照；创建入口可进入草稿列表；云草稿选择后进入匹配上下文的编辑器。

## 4. 用户操作流程

编辑器把内存 Delta 序列化为完整 Markdown 后防抖写本地；用户选择云保存时读取槽位、创建或更新；恢复时若本地与云都变化，展示更新时间并让用户选择，禁止静默覆盖。

## 5. API operationId 与生成类型

- `draftsFindAll`、`draftsCreate`、`draftsSlotUsage`、`draftsFindById`、`draftsUpdate`、`draftsRemove`。
- 主要生成类型：`DraftResponseDto`、`DraftSlotUsageResponseDto`、`CreateDraftDto`、`UpdateDraftDto`。

## 6. 状态模型和数据流

本地快照以编辑上下文键索引；云草稿列表是服务端事实；映射层把云 DTO 转换为编辑器可恢复模型。

## 7. 鉴权、权限和隐私规则

云草稿必须登录；本地草稿不跨账号自动展示。退出时保留未归属本地草稿，但账号草稿按用户隔离。

## 8. 本地存储、缓存及失效规则

本地以完整 Markdown 存 Drift，Delta 不作为快照事实；云草稿只缓存当前会话。发布成功删除对应快照；五槽位用量每次保存前或 409 后刷新。

## 9. 加载、空数据、错误、重试和冲突状态

无草稿、槽位已满、云端已删除、版本冲突和网络失败有独立处理。删除需确认；云失败不删除本地副本。

## 10. 跨模块约束

正文规范化、媒体状态和幂等键由编辑器保持；本地表结构遵循[持久化](../architecture/persistence.md)。

## 11. 测试场景与验收条件

- [ ] 自动快照在进程重启后恢复。
- [ ] 五槽位创建、更新、删除和满额提示正确。
- [ ] 本地/云冲突不静默覆盖，网络失败不丢本地内容。
- [ ] 发布成功仅清理关联草稿。

## 12. 已知限制和后续功能

不做实时同步、自动合并和后台发布；云草稿数量由后端五槽位约束。
