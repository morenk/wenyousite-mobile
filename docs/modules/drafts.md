# 草稿

状态：`in_progress`

## 1. 模块目标与非目标

提供按账号隔离的主题本地自动快照、可跨设备列出/继续编辑/删除的未发布服务端主题草稿、后端用户级五槽位正文草稿，以及按新建/动态 ID 分区的本机动态草稿。正文草稿槽位 1 可由当前编辑器显式开启云端自动保存；V1 不做跨设备实时协作、云端自动合并、后台持续保存或自动发布。

## 2. 用户角色与使用场景

已登录用户创建主题时获得本地防丢快照，可主动保存为未发布主题实体，并从服务端草稿箱继续另一设备保存的完整主题或删除不再需要的条目；也可把当前纯正文保存到五个全局槽位，在另一设备或后续编辑会话中恢复。用户可为当前主题、楼层、回复或子贴正文编辑会话开启槽位 1 自动保存，其他四个槽位继续手动管理。标题、分类、可见范围和标签不进入五槽位正文草稿。发布或编辑动态时，标题、正文、封面、已完成图片顺序及其公开派生信息自动保存在本机，重新进入和离开时都由用户明确决定恢复、保留或放弃。

## 3. 页面、入口和导航关系

`/compose/thread` 自动加载本地主题快照并显示本地保存状态。顶栏单一“云端草稿”入口按需提供“保存当前主题”和“打开云端草稿”：前者保存当前完整表单，后者打开 90% 高度的完整主题草稿箱，可刷新、继续编辑或二次确认删除。主题、楼层、回复和子贴正文编辑器工具栏的“正文草稿”打开独立五槽位纯正文面板；面板顶部提供“槽位 1 自动保存”开关，工具栏入口同步显示等待、保存中、已保存或失败状态。两类服务端资源拥有不同文案和入口，不互相替代，也不在页面底部常驻整宽按钮。`/compose/moment` 与 `/moments/:momentId/edit` 不增加草稿箱入口，而是在重新进入与离页时使用明确对话框处理当前本机草稿。

## 4. 用户操作流程

页面把内存 Delta 经类型化块文档安全编码为完整 Markdown，字段变化后 700ms 防抖覆盖本地快照；应用暂停、失活或离页前立即刷新。所有本地快照、完整主题草稿和五槽位正文草稿写入都先等待当前粘贴事务并从实时 Delta 重编码；编码失败、重新解析后块结构不等价或 10000 字符超限时保留现有草稿且不发送缓存正文。本地快照不存在远端主题时，首次保存会持久化创建载荷并调用 `threadsCreate`，随后用 `threadsSaveAggregate` 保存当前字段和版本；后续保存直接聚合更新同一未发布主题。发布确认后删除关联本地快照。

打开服务端主题草稿箱先调用列表端点取得摘要；选择其他草稿时明确告知当前编辑器将被替换，并先确保当前内容已写入本机。确认后再用稳定 threadId 读取完整主题详情，只有服务端确认未发布、未删除且楼主就是当前账号时，才采用正文、标签及主题/默认子贴/正文的全部版本并覆盖本地工作快照。当前正在编辑的服务端草稿不可在面板内删除；其他条目删除需二次确认。

打开正文草稿面板时用同一服务端快照读取列表和槽位用量。用户可让服务端自动选择下一空位，也可保存到指定空槽；占用槽位必须确认后携带当前版本更新，删除也必须确认。恢复前重新读取单条最新版；当前编辑器已有不同正文时，用户明确选择“覆盖并恢复”后才替换正文，标题、分类和标签保持不变。

开启自动保存前先刷新槽位事实；槽位 1 已有正文时，用户必须确认当前编辑器将持续覆盖该槽位。开启动作只建立当前正文基线，不立即写入；之后每次正文变化以 800ms 防抖保存完整 Markdown，空正文不发送。首次创建复用稳定 `clientRequestId`，之后始终携带最新 `id` 和 `version` 更新同一槽位。关闭面板不停止当前编辑器的自动保存；主动关闭开关、删除槽位 1、离开编辑器、切号，或发生保存失败/版本冲突时停止。重新打开面板会刷新槽位 1，若其他设备已经改动或删除当前版本，移动端停止自动保存并保留可见错误，不静默覆盖。

## 5. API operationId 与生成类型

- 主题实体草稿：`threadsFindDrafts`、`threadsFindById`、`threadsCreate`、`threadsSaveAggregate`、`threadsRemove`，使用 `DraftThreadResponseDto`、`ThreadDetailResponseDto`、`CreateThreadDto`、`SaveThreadAggregateDto`。
- 五槽位正文草稿：`draftsState`、`draftsFindById`、`draftsCreate`、`draftsUpdate`、`draftsRemove`。
- 相关生成类型：`DraftResponseDto`、`DraftSlotUsageResponseDto`、`CreateDraftDto`、`UpdateDraftDto`、`DeleteDraftResponseDto`、`DraftStateResponseDto` 与 `DraftsState200Response`。

## 6. 状态模型和数据流

`ThreadComposeState.localSnapshotStatus` 区分 idle、saving、saved、failed；`ThreadRemoteDraft` 保存服务端主题、默认子贴和正文版本；`PendingCreateOperation` 区分 pending、sending、awaitingConfirmation。`RemoteThreadDraftsState` 独立管理完整主题草稿箱的加载、列表、删除目标和失败，列表摘要不直接承担编辑版本。数据库只存完整 Markdown 和表单元数据，不保存 Delta。

`ContentDraftsState` 分离列表加载阶段、槽位用量、按槽位排序的领域草稿、当前写入/删除目标、动作反馈、版本冲突及自动保存开关/等待/保存中/已保存/失败状态；`ContentDraftConflict` 同时保留刚读取的云端最新版和未提交的本机正文。自动保存控制器以编辑器会话为 key，面板关闭后由对应页面继续观察，编辑器释放时自动取消防抖任务。五槽位草稿、主题远端草稿与本地快照的抽象端口都位于各自 `application` 层，API/Drift 适配器由 `main.dart` 组合根绑定；服务端 DTO 不直接承担面板状态。

主题创作、完整主题草稿箱和五槽位正文草稿共同观察稳定的 `SessionScope(accountId, generation)`：Access Token 刷新只替换凭据，不重建这些状态；登录账号变化、明确退出或会话失效才推进代次并释放旧账号状态。

## 7. 鉴权、权限和隐私规则

两类服务端草稿都必须登录。本地快照按 JWT `sub` 分区，但服务端仍是身份和权限事实；主题草稿详情必须再次匹配当前 ownerId、目标 ID、未发布和未删除事实，未知可见范围 fail-closed。切号或会话失效会释放两类服务端草稿状态，不展示其他账号内容；普通 Token 刷新不得误判为身份变化。Token、预签名 URL、验证码和密码不得进入草稿。退出登录不静默删除尚未发布的账号快照；账号注销也不会由远端端点删除本机快照，但原账号不可恢复，因此注销前必须把这类草稿视为不可恢复内容并明确提示。

## 8. 本地存储、缓存及失效规则

`local_editor_snapshots` 以稳定 ID `thread:new:<ownerId>` upsert，保存上下文、Markdown、JSON 元数据、`clientRequestId` 和更新时间；`pending_create_operations` 保存操作类型、规范化载荷、状态和更新时间。服务端主题草稿确认后更新快照中的远端版本；发布确认后仅删除关联快照。

完整主题草稿箱只在当前面板会话内缓存；五槽位状态以当前编辑器会话为边界，以 `draftsState` 返回的原子快照为事实，关闭面板后仅在自动保存开启时继续存活，编辑器释放或身份变化后释放。完整主题草稿被选中后只把当前一份完整内容写入账号工作快照，其他摘要不进 Drift。两类列表创建、更新或删除成功后失效或更新当前内存状态。动态草稿按新建或稳定 momentId 写入 SharedPreferences，保存文字、已完成媒体的主 URL、派生 URL、contentType、animated、尺寸、封面和顺序；旧记录缺少新增字段时按空派生图和非动画恢复。成功写入服务端或明确放弃后删除。

## 9. 加载、空数据、错误、重试和冲突状态

本地元数据无法识别时停止恢复且不覆盖原记录；写盘失败明确提示，离页时要求用户选择留下或承担风险退出。创建主题超时或 5xx 保留原规范化载荷和幂等键；`40912` 清理冲突待确认记录并生成新键。服务端保存失败不会删除本地副本。

完整主题草稿箱覆盖加载、空数据、失败请求 ID、刷新、逐项删除和失败保留；打开详情失败继续保留当前编辑器。存在待确认创建记录或当前内容写盘失败时禁止切换，目标错配、已发布、已删除、非本人或缺失默认子贴时不采用响应。正文草稿面板覆盖加载、失败重试、空槽、五槽满额、逐项处理中和成功/失败反馈。空正文、超过 10000 字符或包含 21 个及以上骰子的正文不会发送；仅含骰子的草稿仍可保存。手动覆盖携带当前 `version`；收到 `40002 OPTIMISTIC_LOCK_CONFLICT` 时先读取最新版，保留本机待保存正文，再由用户二次确认是否覆盖。自动保存遇到冲突、网络失败或非法正文则立即停用并在面板及工具栏保留失败状态，只有用户重新开启后才继续。恢复也先读取最新版，禁止静默覆盖当前编辑器；删除携带当前版本，失败保留原条目。

## 10. 跨模块约束

Markdown 规范化和可见性由编辑器与核心 Markdown 能力保持，数据库规则见[持久化](../architecture/persistence.md)。主题实体草稿与后端 `/drafts` 五槽位正文草稿是不同资源，页面和文档不得混称。完整主题草稿箱复用 threads 的详情与删除端点，但切换编排归 editor；媒体只有完成后的公开 URL 能进入任一快照；恢复五槽位正文不修改主题表单元数据。

## 12. 已知限制和后续功能

槽位 1 自动保存开关只属于当前编辑器会话，重新进入编辑器需再次开启；应用退到后台或进程结束后不会持续运行。云端冲突只支持停止自动保存，或在手动流程中“保留云端 / 用当前全文覆盖最新版”，不做逐段差异、自动合并和历史版本恢复。完整主题草稿箱按后端固定顺序展示且不分页；切换会明确覆盖当前单份本机工作快照，不保留本机历史版本。用户主动放弃并删除纯本地主题快照的入口仍待实现。
