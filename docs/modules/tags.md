# 标签发现与主题标签管理

状态：`in_progress`

## 1. 模块目标与非目标

提供公开标签主题聚合页，以及楼主/协作者维护主题标签的移动端闭环。当前切片不提供全局标签后台、颜色编辑、批量排序或首页多标签组合筛选。

## 2. 用户角色与使用场景

游客和登录用户都能从首页主题卡片、主题详情或标签主题卡片进入公开标签页。楼主与协作者可在统一主题管理的“主题设置”内按名称添加和移除标签；普通成员与游客不能进入管理工作台。标签是跨主题复用的全局事实，用户无需区分第一次建立标签与把后续主题关联到同一标签。

## 3. 页面、入口和导航关系

公开路由 `/tags/:tagId` 先读取标签事实，再用稳定 `tagId` 精确筛选公开主题；主题卡片仍进入 `/threads/:threadId`，卡片内其他标签可继续进入对应标签页。主题详情在标题下方常驻单行横滑标签栏，点按任一标签直接进入对应 `/tags/:tagId`，不需要打开顶栏更多操作。受保护路由 `/threads/:threadId/manage` 承载主题设置；旧 `/threads/:threadId/manage/tags` 仍可恢复完整登录目标，但会打开同一工作台内的标签编辑器。

## 4. 用户操作流程

公开页并发读取标签详情、动态分类和第一页主题，聚合结果与首页发现共享 `threadsFindAll` 语义，因此不返回已注销楼主的主题，并且卡片只展示唯一首图。接近列表尾部或点击“加载更多”时原样回传 cursor；下拉刷新重新读取三类权威事实。主题管理从完整主题详情映射当前标签名称，在本地编辑最多五项；点击主题设置的统一保存后，通过 `threadsSaveAggregate` 的标签名称集合与标题、状态、默认正文等内容原子替换关联，同名标签由后端自动复用，移除名称只解除当前主题关联，不删除全局标签。

## 5. API operationId 与生成类型

- 公开发现：`tagsGetById`、`threadsFindAll`、`threadCategoriesList`，使用 `TagResponseDto`、`HomeThreadListItemResponseDto` 与 `ThreadsFindAll200Response`。
- 标签检索：公开发现与其他候选入口使用 `tagsSearch`、`tagsGetById`，类型为 `TagsSearch200Response` 与 `TagResponseDto`；统一主题设置不单独调用全局创建端点。
- 主题关联：`threadsFindById` 读取详情中的主题标签关系，`threadsSaveAggregate` 通过 `SaveThreadAggregateDto` 的标签名称集合原子替换关联。

## 6. 状态模型和数据流

公开页把标签事实、分类映射、主题页、cursor 和局部失败分离；复用 threads 的主题卡片读模型和映射，使用 `RequestEpoch` 阻止刷新与旧分页结果互相覆盖，并用 `mergeUniqueBy` 按主题 ID 去重。已有主题的标签编辑状态属于 threads 聚合表单：最多五个去重名称，保存成功采用完整主题详情投影，冲突时与其他主题字段一起保留本机表单并让用户选择最新版或覆盖。tags 的公开读取端口仍位于 `tags/application`，API 适配器由 `main.dart` 组合根绑定，公开列表控制器不导入具体 data 仓储。

标签主题卡使用同页动态分类目录解析展示名称；未知或已停用 slug 只保留为数据标识，页面固定显示“历史分类”。

## 7. 鉴权、权限和隐私规则

标签详情、搜索和标签主题聚合公开可读，但只返回公开可访问主题。主题管理必须登录，并再次以主题 `capabilities.canManageThread` 或 OWNER/COLLABORATOR 角色校验；聚合写操作由后端重复授权。写入失败不清空已编辑名称，用户可在当前工作台显式重试。错误页不根据标签 ID 猜测私密主题。

## 8. 本地存储、缓存及失效规则

标签页只使用 autoDispose Riverpod 状态和页面滚动状态，不持久化全局标签、搜索词或主题关联。返回公开页会重新建立页面状态；主题设置中的未保存名称只留在当前页面，离页前必须明确保存或放弃，成功后采用聚合响应，下拉或重新进入时读取服务端权威关系。

## 9. 加载、空数据、错误、重试和冲突状态

公开页区分首屏加载、404/停用、空主题、刷新失败和分页失败；`40007` 重新读取标签与第一页。主题设置区分无权限、名称校验、聚合写入失败和版本冲突，保留问题编号；空响应、重复名称、无效名称和不匹配目标均不能伪装成功。冲突重读完整主题后仍保留本机名称，由用户明确采用最新版或覆盖，不自动重复写入。

## 10. 跨模块约束

主题条目复用 threads 的公开读模型与发现卡片组件：每项是占满内容列的独立细边框圆角卡片，唯一安全首图在卡片内以整宽 16:9 展示，无图不预留图片舞台；tags 不反向依赖 home。详情和管理入口由 threads 模块提供，验证恢复复用 auth/settings 路由。主题列表、详情和管理工作台的标签统一使用无图标、中性前景、透明表面、Foundation 细边框与 `#` 前缀，不消费服务端局部颜色表达状态；可见胶囊对齐 Web 为 32dp 高、10dp 水平内边距、12sp 中字重和全圆角。详情标签栏保持单行并随标题滚出，不吸顶、不用 `+N` 隐藏任何标签。导航标签的外围仍保留至少 48dp 触控区，非交互标签按内容收缩。

## 12. 已知限制和后续功能

移动端按名称关联标签，不开放任意颜色选择；颜色和描述来自已存在标签或后台治理。首页暂不提供多标签组合筛选，公开标签页一次只锁定一个稳定 ID。统一主题设置当前只提供名称输入与已选列表，不在该弹窗中加载全局候选搜索；保存后以聚合响应和下次详情读取为权威事实。
