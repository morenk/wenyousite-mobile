# 主题与子贴

状态：`in_progress`

## 1. 模块目标与非目标

当前实现公开主题详情、子贴选择、Markdown 正文展示、点赞/收藏/订阅/举报互动、新建主题的本地恢复/云端草稿/聚合发布，并让楼主或协作者添加和编辑子贴正文、完整管理子贴目录、主题标签、已有主题元数据与成员玩家标记。楼主还可任免协作者、管理已发布私密主题邀请并在二次确认后删除主题；V1 不实现举报审核后台或子贴级标签。

## 2. 用户角色与使用场景

游客和登录用户都能阅读公开主题、切换子贴、浏览楼层并查看喜欢与累计加油；游客写操作先登录，登录用户可点赞、收藏、给非本人楼主加油、创建主题并按发言策略发表楼层。普通登录用户还可订阅官方更新和已标记玩家发言，并可在非楼主时退出自己的玩家身份；受邀登录用户可预览私密主题概要并幂等加入。楼主/协作者自动收取更新，可维护子贴正文、普通楼层、主题元数据、非默认子贴目录及成员玩家标记。只有楼主可修改主题可见范围、任免协作者、刷新已发布私密主题邀请并删除主题；默认子贴由服务端固定在目录第一位，任何管理者都不能单独删除或跨位移动。

## 3. 页面、入口和导航关系

首页、标签与搜索主题结果都复用同一整宽卡片：主题标题先建立列表层级，随后由 40dp 头像、作者/等级/活跃时间与分类/状态/置顶两条紧凑元信息补充语境，整宽 16:9 首图和两行摘要继续获得完整卡片宽度；固定 48dp 页脚左侧用 Foundation 语义图标展示玩家/回复/加油，右侧按宽度显示一至三个 32dp 可见高度的标签和不可点击的剩余 `+N`。成员数不再重复占据卡片底部。搜索接口尚未投影的状态、等级、摘要、加油和标签使用安全缺省值，但不另建一套卡片排版。首页与标签发现不展示已注销楼主的主题，显式搜索仍可进入这些公开历史内容。

首页和搜索主题卡片进入命名路由 `/threads/:threadId`，详情顶栏不显示重复的“主题详情”，只常驻返回、主题内搜索和操作入口；管理、加油、举报及非楼主玩家退出入口收进“更多主题操作”，退出再进入身份 Bottom Sheet 二次确认。搜索进入公开 `/threads/:threadId/search` 并覆盖该主题全部子贴。楼层结果使用 `/threads/:threadId?post=:postId` 回到同一详情页定位，具体回复结果则在解析父楼层后直接进入 `/threads/:threadId/posts/:floorId/replies?post=:replyId` 独立讨论；站内传送门还可用 `/threads/:threadId?subthread=:subthreadId` 直接选择子贴。`post` 与 `subthread` 统一为互斥入口坐标，外部地址同时提供两者时以服务端可核验的 `post` 为准；坐标只在进入详情、坐标变化或登录身份变化时完成一次初始定位。定位完成后用户可自由切换子贴；帖子归属仍在读取时，用户通过前后按钮或目录作出的选择会取消该次自动定位，迟到结果不得覆盖用户选择。导航栈中同时存在的两个同主题详情页各自持有所选子贴、筛选、楼层窗口和滚动位置，不共享页面状态。详情和独立讨论跟随全局路由的 180ms 水平位移，阅读正文自身不淡入、缩放或重新入场；无来源栈返回主分支时瞬时兜底。详情 capability 对管理者开放受保护的 `/threads/:threadId/manage`，工作台使用“主题设置 / 子贴内容 / 成员权限”三个统一线性页签；旧的 tags、subthreads、members 管理地址仍可恢复登录目标，但分别打开同一工作台的对应页签或标签编辑器。新建与编辑非默认子贴使用 `/threads/:threadId/manage/subthreads/new` 和 `/threads/:threadId/manage/subthreads/:subthreadId/edit` 全屏路由。应用壳创建按钮进入受保护路由 `/compose/thread`，发布确认后替换到新主题详情。游客从互动、发帖、创建、管理或邀请入口登录时保留完整目标。主题标题与子贴选择器各自占行，关联标签位于主题标题下方并以单行横向滑动展示，点按直接进入 `/tags/:tagId`；子贴选择器两侧保留前后切换，目录 Bottom Sheet 展示完整标题与楼层数。多子贴时，主题标题与标签栏滚出视口后选择器冻结在阅读顶栏下方；从冻结选择器主动切换后回到新子贴正文开头，单子贴时选择器随正文正常滚走。喜欢、收藏、订阅和发表楼层固定在页面底部拇指栏，不再与题头争夺横向空间；320dp 或系统字号放大时发表按钮收为带完整 tooltip/TalkBack 语义的 48dp 图标，大额喜欢计数按 Foundation 规则紧凑显示，其他互动仍保持单行可操作。

## 4. 用户操作流程

阅读时调用主题详情接口加载完整事实。移动端题头先呈现最多两行的主题标题；有关联标签时，下方以单行横滑栏按服务端顺序展示全部标签，标签较少时居中，超出可用宽度时从左侧开始滑动，无标签时不保留空白。当前子贴标题位于标签栏下方，最多两行并保留前后切换；分类、状态、置顶/私密、楼主、等级、时间、浏览/玩家/楼层/加油统计不在题头重复展示。目录入口仍保留完整子贴标题和各自楼层数，所有独立入口保持至少 48dp 命中区。选中子贴正文直接铺在阅读画布上，不套第二层面板；正文底部保留与普通楼层一致的 12dp 内边距，再以横贯视口的 1px 上边界进入紧凑楼层控制行。左侧显示当前子贴总楼层数，右侧依次为“全部玩家与管理者”作者下拉框和显示当前“最早/最新在前”的切换按钮。选择作者或点击顺序会立即清空 cursor 并重载当前子贴首屏，同时保留另一项条件；候选读取失败仅把作者控件替换为可重试状态，不影响顺序或正文。楼层继续用分隔线形成连续文本流，32dp 紧凑头像视觉置于 48dp 点击区内，用户名、内容宽度等级和时间保持同一行；头像直接进入作者主页。每层右侧只显示弱化楼层号；点击楼层非交互正文或元信息区域直接回复该层，长按打开阻断背景点击的中央遮罩操作窗口，头像、链接、图片与内嵌回复保持各自行为。楼层正文真实高度超过视口 1.2 倍时，以视口 0.8 倍高度和底部渐变提供展开/收起。楼中楼最多预览服务端内嵌的前五条，主楼发言者筛选不二次过滤这些回复；真实预览高度超过 320dp 或回复总数大于可见数时才显示唯一“展开全部”入口并进入独立讨论，否则短预览直接点按具体回复且不提供独立页入口。楼层右下角不再常驻“N 条回复”按钮，零回复也不创建预览；搜索、通知和站内坐标仍可直接进入独立讨论。按 `sortOrder` 排列子贴并加载对应正文/楼层；用户主动切换子贴时保留顺序但恢复全部发言者。带 `subthread` 或 `post` 的坐标按服务端事实定位；若目标主楼不属于当前发言者筛选，客户端先恢复全部发言者并给出短提示，再加载和定位目标，绝不把筛选外楼层直接混入列表。用户尚未主动滚动时，排序、筛选或异步图片改变布局后会按当前坐标重新对齐；一旦用户开始纵向拖动，当前坐标便停止自动对齐，直到目标、排序或筛选上下文变化。发表成功后保留楼层窗口与滚动位置并平滑定位到新楼层。点赞、收藏、订阅和发表入口位于固定底部拇指栏，不随滚动收起、恢复、缩放或淡入；正文视口由 Scaffold 正确扣除栏高，列表末尾无需为悬浮按钮额外留白。

合法站内坐标在主题 Markdown 阅读态统一使用 Foundation 的门图标柔粉胶囊，600 字重、可换行且不截断，并保留 48dp 命中区；外层命中区横向按内容收缩，使传送门可与前后文字自然混排而不独占或居中整行。普通链接仍使用品牌深色下划线。用户提及和 `@全体玩家` 不进入传送门：阅读与编辑态共用透明、无图标、品牌深色 600 字重原子文字，用户提及仅在阅读态进入资料页。编辑态传送门按文字基线参与同一行排版，保持原子编辑且不执行导航。

主题与子贴正文复用共享空段读取规则：旧正文顶层连续空行会在阅读时恢复为逐个协议空段，普通段落边界只保留一次，围栏代码、缩进代码和原始 HTML 块不参与推断。相邻 `<br />` 分别渲染实际正文行高并计入长文折叠，紧凑摘要仍折叠空白；进入编辑器后下一次保存会自然写入 canonical 标记，不执行服务端批量改写。创作或管理正文时，键盘连续回车、首尾空段和粘贴中的新空段在本地快照、云草稿、聚合保存与发布共用的编码出口逐段写为 canonical `<br />`；已有 Markdown 的普通结构分隔保持原样。

创建时先恢复按账号隔离的本地 Markdown 快照并加载动态分类；分类只消费 ID、标识、名称、描述、图标、排序和可用状态，不读取或提交颜色；创作页顶栏使用明确的“发布”主按钮，分类、可见性和标签在正文前以带标题的元信息按钮呈现，正文草稿从格式工具栏中独立出来，不夹在样式按钮之间。用户可在正文草稿面板为当前主题、楼层、回复或子贴正文编辑器开启槽位 1 自动保存，关闭面板后继续随正文变化写入，离开编辑器或发生冲突时停止；首次保存/发布用稳定 `clientRequestId` 调用 `threadsCreate` 建立未发布主题，再携带主题、默认子贴与正文版本调用 `threadsSaveAggregate`。保存保持 `published=false` 并允许正文仅含骰子；发布前必须确认默认子贴正文包含非骰子文字且当前正文不超过 20 个骰子，最终仍以响应明确确认 `published=true`。

管理已有主题时并发读取完整详情与动态分区，以 capability 和成员角色决定页面入口；“主题设置”把标题、分区、状态、楼主可见性、主题标签和默认子贴正文放在同一表单，保存时强制 flush 编辑器，并携带主题、默认子贴与 BODY 的全部版本调用 `threadsSaveAggregate`。协作者不发送可见范围字段，已发布主题的默认正文必须含非骰子文字，楼主删除必须再次确认且只有非空服务端响应才视为成功。切换页签、系统返回或离开路由时如有修改，用户必须明确继续编辑、放弃或保存后继续；版本冲突保留本机表单，可载入最新版或基于最新版版本覆盖。

管理成员时并发读取主题 capability 与完整成员列表。楼主和协作者可直接切换非楼主成员的玩家标记；只有楼主可在二次确认后把参与人任命为协作者或移除协作者。成员更新结果不明时重新读取完整成员列表，精确角色或玩家标记证明目标已达成才按完成处理。详情仅在当前成员已标记玩家且不是楼主时，于顶栏“更多主题操作”展示退出入口；进入身份 Bottom Sheet 并确认退出后重读详情、失效对应订阅状态并关闭面板。

管理私密邀请时，仅已发布私密主题楼主显示入口；每次生成前明确说明旧链接立即失效，成功后保留新链接供重复复制。受邀用户登录后读取主题标题、分类、状态、楼主和参与人数；已加入用户直接进入主题，未加入用户明确接受邀请。加入失败时保留预览，由用户关闭提示后显式重试。

管理子贴时在统一工作台读取主题 capability、完整详情正文与 `sortOrder` 权威目录；默认子贴不出现在可排序的非默认子贴清单中，它的正文由“主题设置”维护。点击“添加子贴”进入全屏编辑器，在一次 `subthreadsCreate` 中原子提交标题、发言权限和可选正文；编辑已有子贴时先读取单条最新版补齐 `version`，并在同一编辑任务中保存标题、权限与 BODY 正文。创建在同一次用户操作和网络重试间复用 `clientRequestId`；若结果不明后用户继续改表单，先用原载荷和原幂等键确认已有创建，再以版本更新同一子贴，禁止直接创建第二条。显式拖拽把默认子贴补回集合后提交完整 ID 顺序，失败保留服务端确认顺序。删除必须二次确认正文、楼层和回复会一并移除。创建、编辑、删除或排序结果不明时读取权威目录，只有目标事实已达成才视为完成；版本冲突重读后已等于目标时也按完成收敛，`40912` 等内容冲突仍明确失败。

管理主题标签时在“主题设置”内维护最多五个规范名称；保存随聚合请求原子替换主题关联，后端自动复用同名标签。旧 `/manage/tags` 地址继续打开统一工作台内的标签编辑器；公开标签聚合仍由 tags 模块维护。

## 5. API operationId 与生成类型

主楼层列表的 `postsFindFloors` 向后端传入 `order=OLDEST|NEWEST` 和可选 authorId，默认“OLDEST + 全部玩家与管理者”；authorId 候选由子贴范围化 `postsFindFloorAuthors` 返回当前实际主楼作者。顺序点击或作者选择会分别立即清空 cursor 并从当前子贴首页重载，同时保留另一项条件；加载更多、`40007` 首页恢复和同子贴刷新继续携带当前组合。用户切换子贴时仅清除 authorId，排序继续保留。后端筛选范围只包含主楼层，服务端内嵌楼中楼预览保持原样。

- 当前读取：`threadsFindById`、用于目标定位的 `postsFindById`；普通详情响应已经包含子贴集合、子贴正文 ID/版本、主题标签、统计、互动状态和 capability 等可选登录态投影，不额外请求子贴列表。独立管理工作台使用 `subthreadsFindAll` 取得规范目录，并在编辑前使用 `subthreadsFindById` 取得最新版和所属主题事实。
- 当前讨论作者目录：`postsFindFloorAuthors` 按子贴读取实际主楼作者，`postsFindReplyAuthors` 按根楼层读取实际回复作者；目录与正文加载隔离，创建或删除对应讨论后刷新。
- 当前主题内搜索：search 模块调用 `threadSearchSearchPosts`，使用 `ThreadSearchSearchPosts200Response` 与 `SearchPostResponseDto`。
- 当前互动与成员：`threadsLike`、`threadsUnlike`、`bookmarksCreate`、`bookmarksRemove`、`subscriptionsFindAll`、`subscriptionsCreate`、`subscriptionsRemove`、`threadMembersFindAll`、`threadMembersUpdateMember`、`threadMembersExitMember`。
- 主要生成类型：`ThreadDetailResponseDto`、`ThreadCapabilitiesResponseDto`、`SubscriptionResponseDto`、`CreateSubscriptionDto`、`ThreadMemberResponseDto`、`ThreadLikeResponseDto`、`BookmarkResponseDto`、`ThreadSubthreadResponseDto`。
- 当前创建与草稿箱：`threadsFindDrafts`、`threadsCreate`、`threadsSaveAggregate`，使用 `DraftThreadResponseDto`、`CreateThreadDto`、`SaveThreadAggregateDto` 和详情响应中的乐观锁版本；继续编辑草稿复用 `threadsFindById`，删除复用 `threadsRemove`。
- 当前已有主题管理：`threadsSaveAggregate`、`threadsRemove`，使用 `SaveThreadAggregateDto`、`ThreadDetailResponseDto`、`ThreadCapabilitiesResponseDto` 与 `MessageResponseDto`；动态分区继续使用 `threadCategoriesList`。
- 当前私密邀请：`threadsCreateInviteLink`、`threadsPreviewInviteLink`、`threadsJoinByInviteLink`，使用 `InviteLinkResponseDto`、`InvitePreviewResponseDto`、`InviteThreadPreviewResponseDto` 与 `JoinedThreadMemberResponseDto`。
- 当前子贴管理：`subthreadsFindAll`、`subthreadsFindById`、`subthreadsCreate`、`subthreadsUpdate`、`subthreadsRemove`、`subthreadsReorder`；已有 BODY 再使用 `postsUpsertBody`。主要类型为 `SubthreadResponseDto`、`CreateSubthreadDto`、`UpdateSubthreadDto`、`ReorderSubthreadsDto`、`ReorderedSubthreadResponseDto` 与 `UpsertBodyDto`。
- 当前主题标签管理随 `threadsSaveAggregate` 请求中的标签名称集合原子保存；全局公开发现仍由 tags 模块使用 `tagsSearch`、`tagsGetById`。
- 当前社区举报：reports 模块调用 `reportsCreate` 提交公开非本人主题或楼层目标。
- 子贴正文与楼层写入由 posts 模块调用 `postsCreate`、`postsUpdate`、`postsUpsertBody`、`postsRemove`。
- 已废弃的 `threadMembersJoin` 不接入；公开主题成员身份由服务端发帖等真实业务行为建立，私密主题只通过邀请加入。

## 6. 状态模型和数据流

主题详情阶段、详情数据、选中子贴 ID、`floorOrder`、`floorAuthorId` 与当前楼层页分离；筛选组合拥有同一个请求 epoch，旧筛选、旧子贴和旧分页响应不能覆盖新列表。角色发言者目录复用 posts application 的独立 autoDispose family，与楼层首屏加载和失败隔离并随稳定会话作用域失效。页面协调文件只保留路由、生命周期与区块组合，详情头部、正文、楼层筛选、目标定位和管理区块拆入独立文件。目标帖子由独立 FutureProvider 读取。主题内搜索由 search 的 autoDispose family 按 threadId 隔离关键词、请求代次、cursor 和局部错误。点赞/收藏与订阅分别由 social 的 autoDispose family 管理；订阅记录与玩家候选并发读取但独立收敛，玩家列表失败不会遮断官方更新开关。创建状态由 editor 模块管理表单、本地快照、远端草稿版本、待确认幂等请求和提交动作。主题详情、已有主题、子贴、成员与邀请的抽象端口位于 `threads/application`，API 适配器由 `main.dart` 组合根绑定，所有控制器不导入具体 data 仓储。统一工作台只构建当前页签，主题聚合表单、子贴目录和成员权限继续各用独立 autoDispose family；跨页签只交换导航结果，不互读页面状态。子贴创建键按标题、权限和正文的规范化表单指纹稳定复用，创建/编辑页只在强类型完成结果后关闭；暂时无法确认时保留字段、问题编号、原载荷和原幂等键。单条编辑先刷新元数据版本并保留详情中的 BODY 版本，排序写入不乐观覆盖；成员写入串行执行并只替换响应确认的目标成员，退出状态与列表状态分离。邀请预览丢弃过期刷新，加入写入串行执行并校验返回主题与预览目标一致。Access Token 刷新不释放账号内创作和草稿状态；登录、退出、失效或切号才切换稳定会话作用域。

主题分类展示属于共享 core 读模型：进程内公开目录合并搜索、收藏、邀请和云草稿的并发读取，保留最后成功快照；首页与标签页使用各自同步取得的目录。展示组件只接收 `ThreadCategoryPresentation`，slug 仅用于查询、筛选、表单值和保存；管理已停用分区时显示“历史分类（已停用）”。

写入后的 `refreshMetadata` 更新计数、权限与主题/子贴事实；所选子贴仍存在时保留楼层、cursor 和分页窗口，若并发删除或重排使所选子贴失效，则立即清空旧楼层窗口并加载新的权威首选子贴。完整下拉刷新仍重新读取楼层首屏。

## 7. 鉴权、权限和隐私规则

公开详情使用 OptionalAuth，游客可读取，登录态附加字段缺失时安全降级。游客点赞或发帖只进入登录，收藏与订阅入口不显示。订阅用 capability 与当前角色识别自动接收更新的楼主/协作者并隐藏控件；同一 capability 只用于显示正文、楼层和主题管理入口，服务端继续复核作者、管理者、双向拉黑与发言策略。管理、更新、删除、子贴/成员管理、邀请生成、邀请预览和接受邀请均要求登录，不再存在登录后邮箱验证门槛。协作者可以维护主题标题、分区、状态、非默认子贴及非楼主成员的玩家标记，只有楼主可改可见范围、任免协作者、刷新私密邀请和删除主题。客户端从不允许修改楼主角色，也不允许删除或移动默认子贴；退出只作用于当前用户且楼主无入口。邀请 token 不写入网络日志，链接只在当前页面内存与用户主动复制的系统剪贴板中短暂存在。USER 候选仅取已标记普通玩家并排除本人。不可访问主题不泄露标题、成员、正文或缓存内容。

## 8. 本地存储、缓存及失效规则

详情、所选子贴、楼层、互动、订阅、已有主题/子贴管理表单、成员管理列表和邀请状态仅做 Riverpod/当前阅读页进程内状态，不提供离线阅读。主题详情的阅读 controller 以“主题 ID + 页面实例”划分作用域；服务端主题与帖子事实仍可复用独立查询 Provider，但页面选中项、筛选和分页窗口不能仅按主题 ID 跨页面共享。选中子贴先展示首屏 20 条楼层，首帧完成后再按 cursor 串行预取当前顺序与发言者筛选下的全部剩余文字页；每页到达即按 ID 合并，切换子贴、筛选、刷新或会话会使旧请求代次失效。列表固定预布局可见区前后各两个视口，约覆盖五个手机视口；楼层首次进入邻域并完成构建后保留文本渲染树到当前阅读页释放，滑走再返回不重新解析或排版，分页状态刷新也复用原渲染树。纯文字正文走等价排版的轻量路径，包含格式、提及、骰子、传送门或图片时仍走完整 Markdown v3。分页预取只取得正文数据，图片 Widget 与网络图片请求仍只在首次进入两屏缓存邻域时创建，禁止因为全文预取而一次加载全部图片。创建主题把完整 Markdown、表单元数据和稳定创建请求写入 Drift；不保存 Delta，也不静默离线发布。发布确认后删除关联快照；已有主题与子贴全屏表单不持久化，未保存修改离页前必须明确处理，子贴创建结果不明时仅在当前编辑会话保留完整字段、原始载荷及稳定幂等键。子贴、成员写入和退出成功后以服务端响应或详情重读为准，不维护离线事实。邀请链接不写入 Drift 或安全存储，刷新页面后由楼主重新生成；系统剪贴板内容不由应用持久化或后台清理。切号、权限变化、404 或 403 会释放对应会话内状态。

## 9. 加载、空数据、错误、重试和冲突状态

首次加载以题头、正文和楼层结构 Skeleton 保持详情层级；重新加载、主题不可访问、无子贴和正文安全降级分别展示明确状态。发言者目录加载、失败和无候选分别显示“正在加载作者”“重新加载作者”和“暂无可筛选作者”，不遮断正文、排序或已加载楼层；只有目录成功返回且当前作者消失时才恢复全部作者。有效作者筛选返回空页时展示“没有符合条件的楼层”和“查看全部楼层”，恢复时保留当前顺序。目标定位和主题内搜索另有完整空错重试。主题内搜索短词不发请求；楼层后台预取失败保留已经合并的页并在列表尾部提供重试，单个预取任务始终只有一个请求在途。楼层和搜索的 `40007` 都从当前筛选第一页恢复；同一楼层预取任务最多自动恢复一次首页，恢复后的 cursor 再次失效时停止并交给用户重试，跨主题 ID 响应直接拒绝。互动、订阅、楼层删除、主题、子贴、成员和邀请写入串行执行，空响应不伪装成功，失败保留旧状态与请求 ID；骰子 `40003` 提示返回正文重新插入，`40004` 明确当前正文最多 20 个。主题、帖子或子贴删除返回各自“已不存在”业务码时按目标已达成收敛。官方订阅读取失败使用整体重试，玩家候选单独失败时保留官方开关并在玩家面板独立重试。子贴工作台加载失败可重试；创建或编辑不明确时保留全屏表单、问题编号与原幂等语义，不关闭也不显示成功，更新 `40002`/HTTP 409 时刷新目录并要求重新编辑；正文写入前元数据已保存而 BODY 失败时明确提示部分已保存。排序失败不改变权威顺序。成员工作台写入失败保留权威旧列表；邀请 `40408`、HTTP 404 或 403 是确定失效状态，不自动重试；临时预览失败允许重试，加入失败保留预览，生成失败保留上一次新链接。创建主题结果不确定时保留原幂等载荷，聚合失败保留本地内容和远端版本。主题聚合保存收到 `40002`/HTTP 409 时读取最新版但保留本机表单，由用户选择采用云端或基于新版本覆盖。

## 10. 跨模块约束

主题创建/发布、主题设置、子贴创建/编辑、楼层与回复保存，以及本地/云端草稿都统一等待 editor 粘贴事务并从当前 Delta 重编码；外部复制内容只作为普通文本，编码失败或 10000 字符超限时保留编辑状态，不提交缓存旧正文。

主题作者、成员和邀请楼主头像复用共享首字符降级；题头与楼层短时间遵循 Foundation 72 小时格式并提供完整时间语义，列表计数按阈值紧凑显示。

主楼与独立讨论复用核心“总数 + 作者下拉框 + 顺序切换”组件和 posts 范围化作者目录；动态评论继续使用独立的讨论设置组件，threads 不复制作者映射逻辑。

正文按 Markdown v3 规则渲染，未知扩展节点安全降级；异步骰子事实只更新对应内联节点，不能通过更换整段 Markdown 的 key 触发全文重建。已结算骰子按 nodeId 绑定服务端结果，点按后在安全区明细面板展示逐骰、小计、非零修正和总计。主题设置与非默认子贴全屏页复用同一个 threads 富文本编辑区，底层仍消费 editor 的 Quill 会话、工具栏、提及、图片和正文草稿能力；BODY 写入通过 posts API，页面不复制 Codec。楼主与协作者阅读时仍使用与普通读者完全相同的子贴正文布局，不常驻编辑按钮；已有正文长按可复制正文、复制链接或直接编辑，空正文显示“添加正文”，顶栏更多操作继续作为等价入口。点赞、收藏和订阅由 social 管理；温油加油由 wallet 管理，threads 只提供稳定目标并在成功后重读详情；社区举报由 reports 管理，threads 仅提供已确认公开且非本人的目标和稳定回跳。创建写入由 editor 编排，threads 仓储只映射后端 DTO、权限和乐观锁版本；图片只有完成态公开 URL 能进入正文。对外邀请使用当前 API origin 对应的 Web `/join/{token}`，应用内使用同形 `/join/:token`；V1 未配置 Android App Links，因此外部链接仍由 Web 接收。

## 12. 已知限制和后续功能

当前完成“详情 + 完整子贴目录/正文读写 + 主题标签发现/管理 + 楼层读写/楼中楼 + 全站/主题内搜索定位 + 点赞收藏订阅举报 + 创建发布 + 已有主题元数据管理/删除 + 成员身份管理/自行退出玩家 + 私密邀请”。契约 5.8 已为主题列表、草稿、详情、邀请预览与订阅响应提供 `categoryInfo` 分类展示投影；移动端当前仍通过旧 `category` slug 与分类目录解析名称，迁移共享主题读模型后才能移除这次二次读取。契约 5.9 已为每个子贴提供必填 `postingCapability`，但移动端尚未消费，发表入口仍由服务端按发言策略最终复核并可能返回权限提示；本人协作主题列表、任免通知和权限撤销后的管理页退出也需同一后续切片接入。`subscriptionsFindAll` 也尚无按主题筛选或分页参数，移动端当前读取本人完整订阅后再按主题过滤；需要后端契约切片后才能消除无界读取。V1 不做举报审核管理、子贴级标签或 Android App Links。
