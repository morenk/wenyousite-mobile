# 编辑器

状态：`in_progress`

## 1. 模块目标与非目标

基于 Flutter Quill 提供移动端富文本输入与工具栏，以自研 Markdown v4 ↔ Delta Codec 支持安全链接、图片、骰子、提及、协议节点和本地防丢。当前已交付创建主题编辑页，以及帖子、回复和子贴正文共用的半屏编辑器。独立正文预览为非目标；编辑态直接按阅读态等价字号、行高、内容层级、颜色和块节奏呈现，即满足 Foundation 的所见即所得要求。V1 不离线自动发布。

## 2. 用户角色与使用场景

已登录用户在 `/compose/thread` 创建公开或私密主题，保存服务端主题草稿或发布；也可在主题详情和楼中楼创建或编辑普通帖子，有 capability 的楼主/协作者可编辑子贴正文。契约 4.14 后所有已建立会话的注册用户使用统一发布身份；游客由路由或写入口登录后回到原目标。

## 3. 页面、入口和导航关系

应用壳创建按钮进入 `/compose/thread`。创建页标题为“写主题”，页面加载当前用户的本地快照和动态分类；AppBar 只保留独立的“云端草稿”和紧凑高对比“发布”，云端草稿按钮下方以两项锚点气泡提供“保存 / 打开”，完整草稿列表仍使用可滚动 Sheet。标题下方固定分类、可见性和标签元信息栏，正文聚焦时标题收为单行，元信息在编辑器内局部展开。正文工具栏的“正文草稿”独立放在格式操作之后，不夹在样式按钮中间；窄屏空间不足时降为单独的工具行。正文草稿面板可为当前编辑器开启槽位 1 自动保存，工具栏入口同步显示自动保存状态。发布成功后替换到 `/threads/:threadId`。主题详情和独立楼中楼使用可扩展 Bottom Sheet 创建或编辑楼层、回复与当前子贴正文：新建及恢复未发送草稿默认 40%，已有正文默认 52%，可在 30%～94% 间拖动；顶栏只承载目标和展开，发送固定在键盘工具栏右侧。默认与非默认子贴正文都从主题详情的正文长按或右上角操作进入半屏编辑器；主题设置不嵌入正文，子贴管理的新建/编辑页只维护标题与发帖权限。编辑态和成稿态普通正文图片进入同一共享原图页。

共享工具栏的标题、更多、链接和骰子托盘统一使用中性 `panel` 表面；主栏与更多托盘的格式选中项保持透明静止容器，只让语义图标本身切换为亮/黑夜鲜粉色，并通过按钮选中语义向辅助技术暴露状态，不绘制常驻圆形高亮。“更多”按 48dp 命中区排列纯图标，各行按实际图标数均分宽度、不保留空白格；左、中、右对齐是三个无共享胶囊或相连描边的普通图标按钮，并固定连续排在首行，混合选区不预选、无可对齐块时全部禁用。行内代码、引用、列表、删除线和对齐操作后保持托盘展开，链接与骰子切换到任务托盘，分隔线和表情插入结束后收起。

帖子编辑器打开更多、链接或骰子托盘时，以标题、实际工具区和至少 96dp 正文画布计算临时高度；关闭后恢复此前高度，期间发生手动拖动或展开时以用户选择为准。左上角不再提供 X；点击编辑器外部即使已有内层托盘，也会等待在途粘贴和 Markdown 刷新、保存页面草稿后直接返回原讨论。提交在途禁止关闭，上传在途则先取消上传。

## 4. 用户操作流程

当启动元信息声明 Markdown v4 时，主题与帖子编辑器的“更多”面板显示左对齐、居中和右对齐三个直接选项；普通段落与 H2/H3 可用，列表、引用、普通图片、分隔线和空段不响应。正文保存用紧邻目标块的隐藏 v1 marker 表达居中或居右，左对齐不写 marker；同一 Markdown 段落内的物理行必须同向，因此在已居中或居右段落末尾第一次回车时，空行光标及后续输入立即继承当前方向，不会先跳到左侧或把已有行清回居左；在该空行再次回车则补出空段并进入新的居左段落，光标状态与随后文字保持一致，旧段继续保留原方向。标题转换保留合法对齐，切换为列表或引用时清除。围栏/缩进代码、表格、原始 HTML、硬换行、未知协议和损坏协议原子属于兼容内容，其前方 marker 必须可见降级，不能被消费或创建对齐。发布后的阅读组件会把对齐块扩展到正文可用宽度，再按 marker 放置实际字形；短文本不会因内部块按内容收缩而退回左侧。元信息仍为 Markdown v3 时入口隐藏，但阅读、Codec 和 clipboard 已能安全消费 v4 内容。

历史正文中因标点或符号紧邻而被严格 CommonMark 留作字面的 `*`、`_`、`~~` 定界符，在编辑重开和发布态阅读时共用同一兼容规则，恢复为粗体、斜体、粗斜体或删除线。规范写回只用数字字符引用保护邻接字符，不增加可见空格；转义、代码、链接、图片、定义、空白边界、未闭合或更长定界符和普通单词内下划线继续保持字面。

主题标题字段始终显示“主题标题”标签，不以 placeholder 代替字段身份；正文编辑 Dock 的提示文字仍是短时创作入口提示。分类、可见性和标签选择态同时保留结构与字重线索，不只依赖颜色表达当前选择。

打开页面时以 JWT 的 `sub` 仅作本地账号分区，读取完整 Markdown 快照，再异步用 `usersGetMe` 和 `threadCategoriesList` 确认服务端身份与可用分类。首屏按标题 → 固定元信息栏 → 剩余正文画布 → 本地保存状态 → 键盘 dock 排列，正文不套装饰卡片或使用固定整机高度推算。编辑态正文统一为 17sp、1.8 行高，H2/H3、粗斜体、删除线、链接、行内代码、引用、列表和分隔线由编辑态与阅读态共享视觉规格，保持等价的 WYSIWYG 层级。工具栏格式策略会主动消除行内代码与强调/链接、标题与引用/列表等不能安全往返的冲突组合。发布始终从紧凑顶栏提交。工具栏消费 Foundation v6.8.0：正文/H2/H3、粗体、斜体、图片和更多固定在主栏，发送场景最右固定发送；再按可用宽度和 48dp 最小命中区依次提升草稿、引用和表情包，主栏与“更多”使用相同宽度和草稿占位口径，已提升动作不重复、未提升动作不丢失。分隔线固定留在“更多”面板，在 320～600dp、是否显示提交按钮及草稿是否独占一行的组合下都不提升到主栏，也不能从两处同时消失。标题选择与更多能力在编辑器内部展开，不打开独立格式 Bottom Sheet，也不横向滚动。链接与骰子进入独占任务托盘后隐藏基础格式栏和发送，只保留返回与深品牌色“插入”；字段使用持久标签，错误在对应字段和标题副行表达。骰子把“骰子数 / 面数 / 修正”收为紧凑表达式构建器，标题副行合并实时 canonical 预览与当前正文 `N/20`；七种 Foundation 常用面数常驻在字段下方的横向滑动栏，选择只替换面数并把焦点还给面数字段，软键盘不收起也不覆盖选项。常规手机字号保持三字段单行，放大字号时按表达式顺序换为两行并在托盘内纵向滚动；主格式工具栏仍禁止横向滚动。异步图片/表情/草稿返回后恢复选区、焦点和键盘。

正文图片上传固定使用 `RICH_CONTENT` 用途：静态图取景后归一化为 WebP，GIF 原样确认且不进入裁剪。上传完成后仍把服务端主 URL 写入 Markdown 节点，以保持正文引用与服务端媒体台账一致；派生图只用于创作预览和阅读侧按角色加载，不改变 Markdown v4 的公开地址语义。

表情选择器打开前由工具栏固定当前选区，返回后主题、楼层、回复和子贴正文编辑器都按该选区一次性替换为无富文本属性的 sticker embed；光标处待应用的粗体、斜体等样式不得附着到协议节点。正文与表情可在同一段任意混排，并统一编码为完整 Markdown v4；取消选择不改正文，真正损坏或不支持的协议节点仍由 Codec 阻止保存，不能以静默剥离属性绕过安全校验。

在已有主题上下文输入 `@` 会于 180ms 防抖后读取服务端按当前主题确认的关注用户和帖内标记玩家；继续输入用户名只在这组授权候选内筛选，不合并全站用户。服务端确认楼主或协作者权限时额外展示 `@全体玩家`。候选以根浮层靠近软键盘展示，不参与主题或帖子正文布局；浮层宽度随 320～600dp 视口收束、总高最多 200dp 并在内部滚动，窄屏键盘态额外避开 48dp 格式工具入口。关闭或选择候选都把焦点还给正文且不改变画布尺寸和当前选区；选择后以原子 Quill embed 替换当前 `@关键词` 并补一个分隔空格，Codec 固定序列化为 `[@用户名](/users/:userId)` 或 `@全体玩家`。全新主题必须先保存为服务端草稿取得真实 `threadId`，否则浮层只说明前置条件且不发请求。

正文变化先留在 `RichEditorSession` 的内存 Delta，120ms 空闲后编码为 Markdown；保存、提交、切后台、暂停或离页前强制 flush，随后主题控制器再以 700ms 防抖写本地快照。骰子表达式和服务端结果在阅读态与 Quill 编辑态共用 `WenyouDiceNode`：作为与文字共享基线的无图标行内原子节点，已结算使用 accent/onAccent，待掷使用 warningSoft/warning，内部不换行或截断；已结算节点保留至少 48dp 命中区，可打开包含安全区后整体不超过视口 80% 的 Bottom Sheet，按服务端顺序展示逐骰、小计、非零修正和总计，并在关闭后恢复触发点焦点。插入时生成 UUID `nodeId`，三字段 canonical notation 与 Markdown v4 往返保持稳定；单个 Post 正文最多 20 个节点，子贴正文、每个楼层和每个楼中楼回复分别计数。骰子托盘首次使用 `1d20+0`，同一编辑器会话只记住最后一次成功插入后的规范化三字段，取消或非法输入不覆盖该值，新编辑器会话恢复默认。用户与全体玩家提及同样复用透明、无图标、品牌深色 600 字重原子文字，编辑态不导航且按 userId 无损往返；阅读态用户提及保留资料页导航与 48dp 命中区。引用使用正常字形、muted 表面、2dp 深莓起始侧线、近端直角、远端紧凑圆角和 `0.5em / 0.75em` 内边距；行内代码使用平台等宽字体、0.88em 字号和 0.35em 圆角，Flutter Quill 内边距按 Foundation v6.8.0 正式原生边界例外处理。帖子半屏编辑器打开后自动聚焦，新建从空白处开始，编辑或恢复已有正文时把光标放到文末；点击编辑器外部会在强制刷新 Markdown 后收起，并按目标保留页面内草稿，提交请求在途时则锁定关闭和系统返回，等待明确结果。主题与帖子共用的 `RichEditorSession` 接管选择菜单和物理键盘复制、剪切、粘贴。系统剪贴板只写渲染后的可见纯文本：普通格式定界符、传送门目标、用户/骰子 ID 和媒体 URL 不进入 fallback，图片与表情分别显示为 `[图片]` / `[表情]`；移动端自己复制的结构化 Delta 仍仅留在当前进程。完整选择一个或多个块时，进程载荷额外带上最后一个块的终止换行属性，确保最后一段对齐不丢失；在已对齐段落内插入完整结构块时，拆开的左右残段都保留原方向。只有应用写入剪贴板的 UUID marker、当前登录会话作用域、十分钟时效和可见纯文本四者都匹配时，才恢复内部 Delta：复制骰子后粘贴为每个节点生成新 `nodeId` 并丢弃结果，剪切首次粘贴保留身份，后续再次粘贴按复制处理；mention、sticker 等其他协议节点保持原载荷。跨应用结构恢复只有一个例外：Android 从系统剪贴板读取 Web 写出的唯一合法 clipboard v1/v2 envelope，重新执行 H2/H3、粗斜体、删除线、行内代码、安全链接、引用、列表和分隔线白名单并通过 Markdown v4 编码校验后，才把站内阅读态或编辑态片段按原文本样式插入；未知版本、重复 envelope、脚本、样式、事件属性和未知节点都不能扩大格式能力。阅读态片段中的图片与表情始终降为 `[图片]` / `[表情]`，编辑器来源的合法站内图片和表情保留节点；两种来源的骰子都只保留规范表达式、生成新 `nodeId` 并丢弃既有结果，传送门和提及按安全目标保留。除该站内 v1/v2 片段外，任何外部来源即使文本相同，或内部载荷过期、失配、无法安全编码，都按可见普通文本处理；普通外部 HTML 不参与结构恢复，其中 Markdown 标点、前导缩进和行尾空格只在持久化表示中安全转义，重新打开时不显示转义斜杠或不可见保护字符。系统长按菜单、Quill 粘贴按钮和物理键盘 Ctrl/⌘+V 会主动读取系统剪贴板，因此可以验证内部 marker 或 Web v1/v2 HTML；输入法剪贴板历史若触发同一个系统 paste action，行为相同，若直接经文本输入通道提交文字，则因没有 marker/HTML 而固定作为纯文本，输入法的“粘贴为纯文本”、语音、手写、自动填充和拖放文本也不能恢复结构。剪贴板整体为合法站内坐标且没有匹配的内部编辑载荷时，仍按既有规则以原子传送门替换当前选区；Android 键盘剪贴板建议通过文本输入通道直接提交整段合法坐标时，也必须在 Quill 自动链接前收敛到同一传送门 Embed。混合文本、非法坐标和站外链接继续普通输入；标签与目标都是同一完整站内链接的历史节点只在编辑表面显示为“传送门”，原始 Markdown 不被静默改写。

开启正文自动保存前先刷新槽位 1；已有内容时明确确认覆盖风险。启用只记录当前正文基线，不因打开面板或切换开关立即写入；后续完整 Markdown 变化以 800ms 防抖写入云端，关闭草稿面板后仍跟随当前编辑器，离开编辑器或切号即释放。首次创建携带稳定幂等键，后续更新携带最新版本；空正文不发送，失败或检测到其他设备改动时自动停用并保留可见状态，需用户重新开启。

打开历史正文时，共享 Codec 会把顶层连续原始空行恢复为独占 `<br />` 空段：普通段落边界保留一次，首尾和额外空行按实际数量恢复；围栏代码、缩进代码和原始 HTML 块不参与推断。进入 Quill 前会去掉标记周围仅供 Markdown 解析的分块空行，因此每个协议标记只对应一个可编辑空段；用户下一次修改并保存后写入 canonical `<br />`，再次打开不增减段数。新输入时，键盘连续回车、首尾空段和粘贴中的可见空段在保存、自动草稿或发布前都由统一编码出口逐段写为 canonical `<br />`；已有 Markdown 的普通段落分隔继续保持结构空行，不会因编辑其他文字被升级为空段。

分隔线由工具栏经 `RichEditorSession` 的单次 Delta 事务插入独占块，撤销只回退该事务；canonical Markdown 固定为 `正文\n\n---\n\n正文`。`MarkdownEditorDocument` 统一描述段落软换行、H2/H3、引用、列表、分隔线、协议空段和兼容文本，保存时重新解析并比较块结构；结构不等价会保留当前正文并阻止本地快照、云草稿和发布覆盖。历史 `正文\n---` 继续按 Setext H2 显示，只在用户编辑保存后自然规范为 `## 正文`。编辑态与成稿态分隔线都使用正文可用宽度 50% 的居中短线圆点：线条为 Foundation `border` 1dp，中央圆点为 `brandStrong` 5dp，上下各保留 1.75em，不使用渐变、阴影、文字或动画。

移动端阅读菜单同样接入上述 clipboard v2 进程载荷，但入口必须先用 `MarkdownDeltaCodec` 的阅读复制模式解码原始 Markdown，不能先投影可见文本：子贴正文、主题楼层及独立讨论楼层/回复因此可在本站编辑器内恢复标题、强调、删除线、代码、引用、列表、分隔线、传送门、提及和骰子。阅读态允许 Web 可渲染但编辑器不能无损组合的嵌套样式按语义归一：引用中的强调文字继续保留强调，嵌套行内代码保留代码并清除代码片段上的强调冲突；同一松散列表内单个 Markdown 空白分隔和同一引用内分隔段落的空 `>` 行只承担阅读结构，不进入 Quill 成为可编辑空段，不同块之间的分隔与明确的 `<br />` 空段继续保留。CommonMark 的 H2/H3 闭合标记、引用可选空白、等价分隔线、`* ` / `+ ` 项目标记和实际数字或右括号有序标记，分别归一为编辑器 canonical 结构。常规编辑与保存仍使用严格无损解码。阅读态图片与表情会在捕获 Delta 时直接替换成字面 `[图片]` / `[表情]`，不保留 URL、资产 ID 或可恢复媒体节点；复制失败清除旧载荷，显式重试重新捕获并写入新 marker。原生文字选区复制仍是纯文本；Web 跨设备复制、进程重启和其他只转移 `text/plain` 的路径没有当前进程 marker，marker/会话不匹配或超过十分钟时也都按普通文本粘贴。

## 5. API operationId 与生成类型

- 页面引导：`usersGetMe`、`threadCategoriesList`。
- 当前创建与完整主题草稿链路：`threadsFindDrafts`、`threadsFindById`、`threadsCreate`、`threadsSaveAggregate`、`threadsRemove`，使用 `DraftThreadResponseDto`、`CreateThreadDto`、`SaveThreadAggregateDto`、`ThreadDetailResponseDto`。
- 图片链路：`mediaGetUploadUrl`、`mediaConfirmUpload`、`mediaGetMedia`。
- 收藏表情读取由 stickers 模块的 `stickersGetCollection` 提供，编辑器只消费返回的资产 ID、URL 与标准 Markdown 语义。
- 正文草稿链路：`draftsState`、`draftsFindById`、`draftsCreate`、`draftsUpdate`、`draftsRemove`。
- 当前帖子上下文：`postsCreate`、`postsUpdate`、`postsUpsertBody`、`usersMentionCandidates`；主题元数据与子贴目录端点由 threads 模块消费。
- 提及主要生成类型：`UsersMentionCandidates200Response`、`MentionCandidatesResponseDto`、`MentionCandidateDto`。

## 6. 状态模型和数据流

`ThreadComposeState` 分离加载阶段、账号/分类引导、表单字段、Markdown 正文、本地保存状态、当前服务端主题草稿版本、切换/保存/发布动作和失败反馈；`RemoteThreadDraftsState` 独立管理草稿摘要、刷新与删除，选择后由创作控制器读取完整详情。二者归属 `threads`。`PostComposerState` 单独管理短会话 Markdown、创建幂等确认、正文/帖子版本和云端冲突，不复用主题实体状态。主题设置与子贴管理由 threads 状态持有元数据表单与版本，不创建 Markdown 编辑生命周期；详情页正文统一交给 `PostComposerState` 和共享编辑器。`ContentDraftsController` 以每个编辑器会话为 key，持有槽位快照、自动保存状态、当前槽位 1 版本及防抖任务；页面在面板关闭后继续观察该状态。主题创作、云端草稿和帖子编辑器以 `SessionScope(accountId, generation)` 隔离：Access Token 刷新保持控制器与当前内容，登录、退出、会话失效或切号才重建。业务控制器只接收 Markdown，不持有 Quill Delta；Quill 生命周期、文档 generation 与 Delta 签名同步、格式错误、选区和图片/表情/骰子插入由公共 `RichEditorSession` 管理。系统粘贴统一由该会话接管，不再回退到 Quill 默认粘贴；仅 Web clipboard v1/v2 envelope 经过 `WenyouSiteClipboardParser` 白名单重建后作为结构化片段，其余外部文本与 HTML 都按普通文本插入。粘贴读取期间若选区、文档 Delta 签名或文档 generation 改变则整次拒绝，序列化后超过正文 10000 字符也不会部分写入。每次显式保存、发布、云草稿或本地快照前都先等待在途粘贴，再忽略缓存脏标记从当前 Delta 重新编码；失败时保留当前正文并展示可执行错误。`MarkdownDeltaCodec.encode` 对外部、手输和 IME 文本统一转义可成为 Markdown 语法的标点，并在完整编码出口再次字面化 Markdown v4 不支持结构，因此格式切换或残留属性也不能绕过提交边界；只有工具栏、协议插入器、合法完整站内坐标和已通过 clipboard v1/v2 白名单的站内片段创建语义节点。主题端口位于 `threads/application`，提及与本地快照端口位于 `editor/application`，适配器由 `main.dart` 组合根绑定。图片上传进度、失败与取消由 media 的独立上传任务控制器管理。恢复五槽位正文或切换完整主题时递增文档 generation。`MentionCandidatesController(threadId)` 独立管理当前查询的 loading/ready/failed、候选和请求失败，以 generation 丢弃乱序响应；页面只读取光标前最多 26 个字符检测提及，仓储只映射最多 20 个服务端授权的关注用户和帖内标记玩家，未知关系失败关闭。`MarkdownDeltaDocument` 返回内存 Delta 和兼容问题列表，未知或损坏协议节点锁定显示并保留原 token。

云端主题草稿摘要的分类元信息通过 threads/core 共享目录解析，只渲染“演绎”等用户 label。目录加载不阻塞草稿列表，刷新草稿时同时刷新目录；未知 slug 显示“历史分类”而不显示原值。

## 7. 鉴权、权限和隐私规则

路由和提交都要求会话，最终权限由服务端复核；契约 4.14 后发布资格不再包含邮箱验证状态。JWT 解码只用于本地快照分区，不能替代授权。提及候选只消费服务端 `usersMentionCandidates` 返回的主题授权投影；客户端不从全站搜索或本地关系扩大候选，也不依据本地角色自行开放 `@全体玩家`，后端在最终发帖时继续校验提及。草稿不保存 Token 或预签名 URL；图片 PUT 使用与主鉴权 Dio 分离的客户端，日志和错误反馈不暴露预签名查询参数。私密邀请 token 是访问凭据，除用户明确保存的正文或草稿外不得写入日志、诊断、分析事件或独立缓存，也不得用于预取私密主题元数据。外链仅允许 HTTP(S)/mailto，图片仅允许安全 HTTP(S)。

## 8. 本地存储、缓存及失效规则

`LocalEditorSnapshot` 按 `thread:new:<ownerId>` 覆盖保存完整 Markdown、表单元数据、远端版本和稳定创建请求 ID；Delta 不落库。`PendingCreateOperation` 保存主题创建的规范化载荷与 pending/sending/awaiting-confirmation 状态。发布确认后只删除当前账号关联的主题快照；服务端草稿保存后更新本地远端版本。楼层/回复编辑器默认只保留当前页面内存状态，本机临时草稿同时记录目标帖子 ID、打开时版本和基线 Markdown；再次打开已有正文时先读取最新版，再安全恢复、清除已保存草稿或要求用户处理真实分叉。用户显式开启后，当前编辑器正文自动覆盖五槽位云草稿的槽位 1，关闭面板不停止，页面释放后停止。候选不持久化且 Provider 随主题编辑上下文释放；最终正文只保存规范提及节点，不保存候选关系标签或查询结果。

## 9. 加载、空数据、错误、重试和冲突状态

全模块错误遵循[网络与会话](../architecture/networking.md)统一分级：可操作的预期失败只给恢复提示；本机、网络连接、温油站服务与内容处理异常才标注问题环节，只有可核对的服务/内容异常及结果待核对写入显示问题编号。普通页面不展示 HTTP、业务或内部诊断码，Debug 现场诊断可复制安全技术字段。

本地恢复失败不会覆盖原数据；离页前强制落盘失败时必须由用户明确选择留下或仍然退出，不能静默丢失。服务端主题草稿箱加载失败可重试，删除失败保留条目；切换前本机写盘失败或存在待确认创建时拒绝替换，详情错配/已发布/非本人/无默认子贴均 fail-closed。分类同步失败时本地编辑继续可用并提供重试。提及查询先显示加载，空结果明确说明，候选响应缺失或失败都展示稳定文案与请求 ID，并可按同一关键词重试；输入变化期间旧响应不能覆盖新候选。没有 `threadId` 时不请求候选。Codec 遇到不支持属性或冲突格式时阻止保存；图片选择后先在通用取景窗口拖动、缩放或切换比例，确认后才上传，图片节点的替代文字固定为“图片”，不以描述表单打断创作；上传任务区分选择、准备、上传、确认、处理与失败，可取消，失败时可在当前页面直接重试同一裁剪文件。骰子 `40003` 提示返回正文重新插入，`40004` 明确当前正文最多 20 个；主题发布和已发布子贴正文必须包含非骰子文字，楼层、回复和草稿允许仅含骰子。创建超时或 5xx 保留待确认记录；业务码 `40912` 清理冲突记录并生成新请求 ID。聚合失败保留本地与服务端草稿版本，不显示伪成功。五槽位恢复前读取单条最新版并确认替换；已有帖子或正文在编辑器显示前也读取最新版，加载失败只提供重试或关闭。更新收到 `40002` 时保留当前正文，回读已等于待保存 Markdown 则按完成处理，确有差异才要求确认覆盖；带其他业务码的 HTTP 409 不作为版本冲突。帖子更新写请求禁止网络层自动重放，结果不明时由用户重试。自动保存的写入失败或版本变化不会自动覆盖最新版，而是停用并要求用户查看后重新开启。帖子编辑器提交期间锁定关闭；未提交内容收起后保留在当前页面输入草稿。

## 10. 跨模块约束

Delta 仅存在页面内存，后端、服务端主题草稿和 Drift 都保存 Markdown v4。提及候选接口位于 users，但查询生命周期和插入行为由 editor 管理；帖子和主题页面只传真实 `threadId`。媒体上传任务生命周期属于 `media/application`；editor 页面不直接调用上传仓储或持有 Dio 取消令牌，只消费 `COMPLETED` 结果并插入正文。骰子结果只由服务端生成。五槽位正文草稿属于[草稿](drafts.md)模块，不等同于当前主题实体的未发布草稿。参见[Codec 架构](../architecture/editor-codec.md)和[持久化](../architecture/persistence.md)。

## 12. 已知限制和后续功能

任务列表、表格、围栏代码和无法证明精确往返的组合在编辑会话中显示为可理解源码，但保存时会转义为 Markdown v4 安全字面文本，不会把原始不支持结构原样提交。全新主题在首次服务端草稿保存前不能查询提及候选；独立正文预览为非目标，编辑态等价呈现即满足 Foundation，编辑撤销入口仍待后续切片。帖子待确认创建不会在进程终止后自动恢复；不做离线自动发送。
