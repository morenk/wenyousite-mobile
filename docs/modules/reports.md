# 社区举报

状态：`in_progress`

## 1. 模块目标与非目标

为用户、公开主题、公开楼层/回复、动态、动态评论和自己收到的私信提供统一举报提交闭环。举报只创建待人工审核记录并保存服务端目标快照，不在客户端即时隐藏、删除或处罚目标。本模块不提供举报历史、处理进度、撤回、管理员队列、内容处置或账号处罚；本人治理决定与申诉由 moderation 独立承载。

## 2. 用户角色与使用场景

游客在可举报目标看到入口，点击后先登录并返回原页面；所有已建立会话的注册用户可选择原因并提交补充说明。目标作者本人不显示对应入口，已删除内容、已注销用户和私密主题不开放提交；私信只允许接收者举报收到且未撤回的消息。管理员审核属于独立管理产品，不进入移动端。

## 3. 页面、入口和导航关系

非本人公开用户、公开主题和非本人动态在详情顶栏提供举报图标。公开主题详情中的主楼层，以及独立楼中楼中的主楼层和完整回复串，均通过长按卡片后的统一操作菜单提供举报，不在每张卡片底部常驻按钮；独立页按 `threadId` 读取权威主题可见性，URL 查询参数不能开启举报。动态主评论和回复在操作区提供入口。私信会话中，收到且未撤回、已确认送达的消息在长按菜单提供举报，本人发出的消息、撤回消息和本地失败消息不显示。游客使用各目标的稳定详情路径进入 `/auth/login?returnTo=...`，登录后按统一注册用户身份提交。

## 4. 用户操作流程

用户打开举报表单后先阅读人工审核与实名可见说明，从垃圾广告、骚扰或恶意攻击、仇恨或威胁、色情、暴力、个人信息、冒充或诈骗、知识产权、违法内容和其他十类原因中选择一项。补充说明最多 1000 字，选择“其他原因”时必填；客户端裁剪首尾空白但不修改正文。提交成功只显示已进入审核的确认，不修改当前内容投影；网络或结果不明确时保留表单，由用户显式重试。提交在途时锁定字段、取消、系统返回和外部关闭，等待明确结果后再退出。

举报原因复用列表页的锚点筛选器触发态、圆角菜单、选中标记和 48dp 选项；同一组件在举报弹窗中使用明确的可用宽度，不回退到 Material 默认下拉。

## 5. API operationId 与生成类型

- 提交：`reportsCreate`。
- 生成类型：`CreateReportDto`、`CreateReportDtoTargetTypeEnum`、`CreateReportDtoReasonCodeEnum`、`ReportsCreate201Response` 与 `ReportResponseDto`。

## 6. 状态模型和数据流

`ReportController` 以规范化 `ReportTarget` 为 family key，串行维护提交中和失败状态；原因与补充说明只在当前弹窗内存。仓储接口位于 `reports/application`，`main.dart` 组合根绑定 `ApiReportRepository` data 适配器，控制器不直接导入 data。适配器显式映射六类目标和十类原因，并要求服务端确认目标、原因与本次输入一致且状态为 `PENDING`。请求与响应生成枚举都有集合完整性回归，契约新增值时必须显式扩展领域映射；未知枚举、空 ID、错配响应和缺失确认一律 fail-closed。

## 7. 鉴权、权限和隐私规则

`reportsCreate` 要求登录；后端最终复核公开目标仍可见、未删除且不是举报者本人，私信目标必须由当前用户接收。客户端只用详情投影和当前会话收敛明显无效入口，不把查询参数或本机 ID 判断当作授权。表单明确告知管理员可见举报账号；补充说明和私信正文可能包含敏感内容，因此不写日志、不持久化，也不进入分析事件。拉黑关系、管理员身份或内容可删除能力不等同于举报权限。

## 8. 本地存储、缓存及失效规则

举报原因、说明、提交失败和结果只存在于弹窗/autoDispose Provider 生命周期，不写 Drift、SharedPreferences、文件或剪贴板。关闭弹窗即放弃本机表单；成功后也不缓存举报历史。

## 9. 加载、空数据、错误、重试和冲突状态

全模块错误遵循[网络与会话](../architecture/networking.md)统一分级：可操作的预期失败只给恢复提示；本机、网络连接、温油站服务与内容处理异常才标注问题环节，只有可核对的服务/内容异常及结果待核对写入显示问题编号。普通页面不展示 HTTP、业务或内部诊断码，Debug 现场诊断可复制安全技术字段。

提交期间锁定表单和取消按钮。目标删除或不公开时沿用对应 `404` 安全提示；`40914` 明确提示已有相同待处理举报，无需重复提交；`42900` 提示稍后显式重试并尊重服务端限流。举报没有 `clientRequestId`，POST 不进入自动重试拦截器；连接中断或 5xx 后由用户重试，后端唯一约束把已创建但响应丢失收敛为 `40914`。

## 10. 跨模块约束

users、threads、posts、moments 和 direct_messages 只提供目标事实与入口，提交状态不写回这些模块。auth 提供统一登录会话；core/network 提供请求 ID、会话失效和稳定业务错误。页面只消费 Foundation v6.5.1 Token、语义图标、共享锚点筛选器、状态横幅和至少 48dp 触控目标。管理端 operationId 不得为了覆盖数字从移动端调用。

## 12. 已知限制和后续功能

当前不展示举报处理结果，也不允许撤回举报。独立楼中楼会额外读取主题权威事实，读取失败时安全隐藏举报；不会从路由来源或查询参数猜测公开性。治理决定与申诉已由 moderation 使用独立隐私和凭据边界实现，但不会把举报记录与决定在客户端关联；管理后台继续保持产品范围外。
