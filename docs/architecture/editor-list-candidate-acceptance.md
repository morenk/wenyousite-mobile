## 已证实根因及候选行为

旧实现按固定两个空格和单行前缀猜测列表深度，同时多个入口对空项的定义不一致。空 `-` 又可能被解析为标题下划线，空父项后的语法空行会改变父子关系。只有编解码自洽或列表项数一致，不能证明阅读结构正确。

候选以独立 CommonMark 列表树读取类型、深度、父项和直属内容；写出按父项标记宽度安排缩进和必要分隔，再核对完整结构。用户空白行仍保存为共享的独占 `<br />`，语法分隔不变成额外可编辑行；列表前不机械增加空白行。正文和引用的一次回车语义保持既有契约，标题和列表保留常规行为。

候选同时修正阅读器的 Setext 优先级和剪贴板空项处理。已有四组编辑／阅读配对 Golden 中，第二个有序项目原来是正文里的字面 `2.`；候选恢复真实编号，已更新相应视觉基线。

边界回归同时保留不合法对齐文字与后续列表的既有分隔；跨行行内代码只在阅读校验时投影为空格，持久化继续保留原始换行。行首和行尾空格保护分别记录在会话元信息中，避免给历史正文额外添加保护字符。
