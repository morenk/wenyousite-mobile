## 构造样例的缺陷与回归边界

首轮构造样例已证实的缺陷在移动端 Markdown → Delta 的实现：原块模型只识别 `> ` 后有正文的引用，空 `>` 仅在阅读复制分支处理，普通编辑因此生成不带引用属性的可见标记行。阅读组件按完整 Markdown 块解析，编辑转换按物理行识别，两条路径产生不同语义。当时尚未取得原楼层 Markdown，不能仅凭构造样例断言根因；后续已取得原文、纠正 Debug 安装目标并由负责人确认标记拆分消失，见当前结论。Markdown 本身能够表达引用内分段。

共享编辑 fixture v7 的引用基础样例只有单行引用，48 条 editCases 集中覆盖行内样式组合；缺少引用分段编辑的结构预期。仅验证 encode/decode 往返，或将第一次解码的 Delta 作为保存校验基准，会遗漏“解码已错但往返自洽”的情况。本次新增显式 Quill 单块／空行／marks 预期和独立 Markdown 块解析断言。

后续共享契约应在后端授权工作区发布块结构编辑矩阵，再由三端共同消费：覆盖段落／标题／引用／列表／图片的边界、空行与软换行，叠加行内 marks、转义和原子节点，并验证打开编辑、首中尾输入、回车、退格、格式切换、复制粘贴、保存及两端重开。预期需明确文字、marks、块归属、分段和节点身份，不能由待测 Codec 自动生成。该跨端共享矩阵尚未发布，不以本次局部回归通过代替全部样式验收。

本轮保留已有引用的分段，不改变新输入的回车含义。已核对 Web Milkdown 7.21.3 的普通／引用非空段落：Enter 分段，Shift+Enter 段内换行；移动端现有一次回车可以写为软换行，两端新输入规则的一致性仍待独立处理，不能将本轮通过作为该项完成依据。
