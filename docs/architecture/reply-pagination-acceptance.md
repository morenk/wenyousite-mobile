# 楼中楼不可见回复目标候选验收

状态：2026-09-09 负责人补充确认人工验收通过／修复完成；原候选与失败记录保留为历史。

## 原始反馈与证据

负责人反馈[原楼层](https://wenyou.site/threads/cmtmnd85z00we7q3wyttyogst?post=cmtmnijv700xd7q3w19zxkkoq)的独立楼中楼在正序阅读中途出现“展示更多”，点击后提示“回复列表已经发生变化，请重新加载”，重新加载仍失败；切换倒序则直接显示“楼中楼讨论加载失败”。负责人确认 Web 正常。

本任务匿名只读请求该楼层及 `/api/v1/posts/{id}/replies?limit=20&order=OLDEST`，按服务端 cursor 连续读取。观察时 76 条回复分为 20、20、20、16 条四页；第 4 页第 14 条的 `replyToPostId` 非空、`replyToPost` 为 `null`。同一回复在 `NEWEST` 首屏第 3 条。各页 HTTP 请求成功，cursor 与 hasMore 正常，未修改任何线上内容。

最小触发结构（标识脱敏）：

```json
{
  "id": "reply-74",
  "parentPostId": "floor",
  "replyToPostId": "unavailable-target",
  "replyToPost": null
}
```

后端部署提交 `e8d0fd6cb193ab5e9a1c2c51c03382ef300adc0c` 的 `post-query.service.ts` 对 `replyToPost` 使用 `visiblePostWhere`，因此目标删除或因可见性规则被过滤后，目标 ID 仍保留而详情可为空；OpenAPI 同样声明详情可为 null。当前移动端却强制“有目标 ID 必须有目标详情”，导致一条合法回复使整页失败。重新加载相同响应无法恢复。主楼列表的内嵌回复复用了相同错误假设，须同步修正。

该结论不要求判断目标具体因何不可见，也不尝试额外读取或恢复目标资料。

## 候选范围与回归要求

- 独立讨论与主题内嵌回复接受缺失的可选目标详情，继续保留回复正文和目标 ID，目标用户名维持已有空值降级。
- 目标详情存在时继续校验目标 ID 和作者一致性；父楼、主题、子贴、作者、骰子及分页 cursor 的原有校验保持有效。
- 使用真实 Dio、生成客户端与生产仓储，按实测页长和触发位置构造脱敏响应；核对正序四页、刷新重试、倒序首屏与连续分页，覆盖主题内嵌预览及异常关联拒绝。
- 原实现的正序、倒序和预览回归均失败，8 项异常关联拒绝检查通过；候选的 11 项新增检查全部通过。

## 自动分页交互追加候选

负责人进一步明确独立讨论不应保留“加载更多”按钮。代码核实：首屏完成后已自动串行预取后续文字页，图片随列表进入预布局邻域创建；该按钮是遗留手动入口。候选移除正常分页按钮，仅显示加载进度，并将分页失败重试移到回复列表底部；页首仍保留刷新失败重试。

新增慢请求页面回归已在旧实现上因发现遗留按钮而失败，另扩展分页失败重试的位置检查。候选页面与生成客户端／仓储整栈相关 49 项检查通过，确认无需点击即可继续加载、慢请求不重复发起分页、失败保留已有回复并从原 cursor 重试。

追加调整的完整 `npm run check:apk` 通过：2311 项 Flutter 测试和 16 项 Windows 工具测试通过，既有 Sentry 显式外部回执验证跳过 1 项；静态分析零问题，契约再生成无差异，Debug APK 构建成功。
