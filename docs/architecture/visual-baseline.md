# 移动端视觉基线

移动端视觉唯一规范是 Foundation v1.2.1 的 Flutter profile 与仓库内 Token。现行页面使用纯白画布、轻量分隔、12/24dp 响应式外边距、600dp 最大内容宽度和不小于 48dp 的独立触控目标；列表容器与列表项占满分配列，只有消息气泡、标签、徽标和紧凑操作可按内容收缩；柔粉只作为品牌与状态强调色，不作为整页背景。

四个主导航固定为“首页 / 动态 / 消息 / 我的”，中央粉色按钮是全局“发布”；搜索从首页与动态顶栏进入，不占主导航分支。发布按钮点击后选择“发布主题帖”或“发布动态”，当前频道只影响推荐顺序。开发 API、契约版本和环境连接提示不得作为正常用户首屏内容。

连续内容使用留白和分隔线表达层级；卡片只用于真正独立的概览或操作模块。首页与标签聚合是文章索引，主题条目使用扁平画布和分隔线，按“单行弱化语境 → 标题 → 作者/等级/时间 → 摘要 → 一行统计”阅读；无图主题在 360dp 小于 190dp，有图主题把唯一首图限制为 104×88dp 右侧缩略图，不能用整宽封面压过文字。主题题头属于阅读语境而不是独立卡片：使用扁平画布、单行弱化语境、标题和一行元信息，分类、状态与标签不使用胶囊背景，最多五标签横向浏览而不增加题头高度；360/400/600dp 题头固定小于 190dp，让首屏同时出现子贴正文和第一楼。管理身份不能改变阅读排版：楼主与协作者的子贴正文前不常驻编辑控件或额外操作行，正文编辑/添加集中到顶栏按需主题操作。独立讨论把主题、子贴和楼层位置压入可随阅读收起的顶栏，正文区不重复相同语境；排序、筛选等低频阅读控制只保留一个弱化设置入口，完整能力按需展开。纵向列表的行、卡片和状态模块必须占满页面边距内的可用宽度，并在宽屏收束到统一最大宽度，绝不能由标题或正文长短决定自身宽度；标签、等级徽标等紧凑信息例外，必须按内容收缩。长篇 Markdown 正文默认约 17sp、1.8 行高和轻微字距，标题、引用与分隔线只建立阅读层级，不承担大面积装饰；接力主题主阅读流只连续呈现子贴正文与楼层正文，楼中楼默认折叠为弱化的回复数入口，具体回复进入独立讨论页后再完整呈现，不能插入楼层之间打断叙事。Quill 创作态使用 17sp、1.75 行高和同一标题比例，让输入节奏接近最终成稿。文字创作页把提交放入紧凑顶栏，低频草稿操作按需展开，纵向空间优先分配给随窗口增高的正文画布，不在底部堆叠整宽动作按钮；窄屏正文聚焦且软键盘可见时，整排格式栏退出布局，只保留 48dp 浮动“格式工具”入口，点开在原页面展开且不改变焦点或选区。`@提及` 候选同样不能插入文档流挤压正文，使用贴近键盘、最多 200dp 高且内部滚动的临时浮层，320～400dp 键盘态须避开格式工具入口，关闭或选择后保持 Quill 焦点、选区与画布尺寸。主题、楼中楼与动态详情的发表入口使用按内容收缩、48dp 命中区的柔和悬浮按钮，不再以整宽底栏永久扣减阅读视口；向下阅读时顶栏与发表入口共同收起，向上轻滑立即恢复，列表末尾仍留出安全空间。系统开启无障碍导航时不自动隐藏发表入口。动态详情图片只保留页面级外边距，360dp 视口下舞台宽 336dp，标题和正文另有内边距。普通正文图片始终 `contain` 且本体不叠加收藏、下载等低频按钮，轻触进入共享原图页；原图页支持系统返回、双击、捏合、平移和未放大下滑关闭，登录态私有动作集中在顶栏按需菜单。规范 sticker 仍作为紧凑原子图片，不伪装为普通插图。裁切封面必须能进入完整原图。

仓库不保存手工截取的设备页面作为长期设计事实，避免旧导航、旧文案和临时环境提示继续误导实现。当前自动化视觉基线覆盖 Foundation 基础组件、动态瀑布流、首页扁平文章索引、主题创作首屏与长文/键盘态、帖子全高编辑器、键盘态提及候选浮层、独立讨论阅读、长文阅读样张、360dp 紧凑悬浮发表入口、360/400/600dp 普通主题首屏、360dp 管理者正文优先首屏，以及默认折叠楼中楼的双楼层连续阅读态；变更必须同时通过 320/360/400/600dp Widget 回归和 Foundation 门禁。对应文件位于 `test/**/goldens/`，由 Widget 测试生成并校验。
