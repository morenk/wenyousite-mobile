# 移动端视觉基线

移动端视觉唯一规范是 Foundation 远端最新正式发布 Tag；当前锁定 v6.8.0 的 Flutter profile、品牌资源、核心元素、语义图标注册表与生成 Token。现行页面在亮色与黑夜模式下使用各自的中央语义画布与表面色、轻量分隔、12/24dp 响应式外边距、600dp 最大内容宽度和不小于 48dp 的独立触控目标；列表容器与列表项占满分配列，只有消息气泡、标签、徽标和紧凑操作可按内容收缩。品牌浅粉 `brandSurface` 只承担按钮、气泡和强调块，不能用作白底文字或图标；链接和通用强调前景使用 `brandForeground`，点赞与收藏选中态分别使用 `like` 与 `bookmark`，继续以透明容器及图标颜色/填充表达状态，表面上的内容使用对应 `on*` Token，并由程序化测试保证普通文字 AA 对比度。Foundation v6.8.0 的正文分隔线和主题标签生成常量已由阅读态、编辑态及共享标签组件消费。

Markdown v4 的普通段落与 H2/H3 可使用左、中、右布局；Markdown v5 再允许独占一行的普通图片块使用同一布局。编辑器在“更多”中使用 Foundation v6.8.0 左、中、右语义图标，阅读态按块应用相同对齐且不显示协议 marker。列表、引用、图片文字混排、分隔线和空段不参与对齐，不能仅因父级或相邻块样式改变布局。

编辑器标题、更多、链接和骰子托盘统一使用中性 `panel` 表面；主工具栏及更多托盘的格式选中项遵循透明静止容器，只让图标本身切换为亮/黑夜鲜粉色，不绘制常驻圆形、胶囊或填充底色，非颜色状态由按钮选中语义提供。“更多”保持纯图标、48dp 独立命中区和纵向自适应，不横向滚动；每行按实际图标数均分可用宽度，不保留空白占位。左、中、右对齐是三个普通图标按钮，不使用共享胶囊、分段轮廓或相连描边，并固定连续排在同一首行。

品牌标识只进入 Flutter 启动首帧、登录/注册品牌头和首页标题栏。相邻已有“温油站”名称时标识为装饰并排除重复朗读；单独使用必须提供语义名称。更新、错误、找回密码等任务页面不重复加标识。Android 与 iOS 系统启动层以及 Flutter 品牌页均使用纯白底色；系统层不显示标识或文案，Flutter 拿到有效窗口尺寸后再把完整品牌内容整体居中。平台图标与保留资产由 Foundation v6.8.0 生成物同步，并由哈希测试阻止客户端私自漂移。

站内传送门消费 `WenyouElementContract`：正文 em 比例决定柔粉胶囊的内边距、间距、圆角和门图标大小，文字使用 `onAccent` 与 600 字重；Markdown 与纯文本阅读态都用 alphabetic baseline 的 `WidgetSpan` 参与同一段落排版，可换行、不截断，透明命中区纵向保持 48dp、横向按内容收缩，因此短传送门能和前后文字自然同行而不会占满并居中整行。编辑态沿用同一文字基线且不导航。普通链接仍使用品牌深色下划线，不能与传送门混成同一种样式。骰子同样保持无图标的基线原子节点，但内部禁止换行或截断：已结算为柔粉 accent 表面，待掷为 warningSoft 表面，阅读和编辑复用同一组件，完整明细只进入 Semantics。阅读区的系统选字和内容操作复制都只输出行内原子的可见 label；传送门、提及、骰子和规范表情不得把目标地址或协议节点写入剪贴板，原子之外的 Markdown 源文本保持不变。

四个主导航固定为“首页 / 动态 / 消息 / 我的”，中央粉色按钮是全局“发布”；搜索从首页与动态顶栏进入，不占主导航分支。发布按钮在任一主导航分支都先显示“发布主题帖 / 发布动态”轻量选择器，当前频道不得替用户预选发布类型。消息未读是危险色状态而不是普通品牌徽标：通知条目使用 8dp `destructive` 圆点，底栏消息和私聊会话使用 `destructive / onDestructive` 计数角标；计数角标固定 16dp 高、10sp utility 粗体等宽数字，超过 99 显示 `99+`，零值隐藏。云草稿等普通 Badge 继续使用品牌色，不能通过全局 BadgeTheme 一并改色。开发 API、契约版本和环境连接提示不得作为正常用户首屏内容。

页面栏目、通知分组、动态模式与首页排头分类统一使用共享线性页签：白色表面、1dp 底部分隔线、纯文字标签和 2dp 品牌色短选中线，命中区不小于 48dp。二至四项且文字可容纳时等宽铺满；更多项目、长标签或放大字号放不下时只让页签条横向滚动，并保持当前选中项可见，横向手势不得切换内容页。页面排头使用统一响应式边距且不另加任意上下留白；面板和 Sheet 内仍使用同一视觉组件但继承父容器宽度。排序、状态、收藏夹等查询条件，以及裁剪比例、骰子面数和创作表单选项不是页签，继续使用各自的筛选或单选控件。所有下拉选择统一使用 16dp 圆角和至少 48dp 操作高度：闭合触发物、短暂按压/聚焦色层与展开面板不得出现锐角，普通菜单宽度与有界触发物对齐，选项行同样保持 48dp 高。讨论控制行的安静作者筛选是紧凑例外：触发器按内容收缩且最宽 112dp，菜单保持 160～260dp 独立宽度，以免长用户名被触发器宽度压缩。

临时操作按任务重量分层：不超过六项的复制、回复、编辑、删除、举报、发布类型和草稿快捷操作通常使用锚定触发物的轻量气泡，不遮蔽整页；操作项最多五列，图标在上、短标签在下，第六项起换行，破坏性操作使用错误色。主题正文、楼层、独立回复和动态评论的内容长按是明确例外：只有手指实际落在字形区域时才进入系统选字，同一行文字外的空白、元信息与非文字节点长按打开带对象标题的居中遮罩窗口；四项按 2×2、五至六项按三列对称排布，回复继续由点击内容进入且不在菜单重复出现，点按暗色遮罩只关闭窗口而不穿透背景。其他消息与锚点气泡优先出现在内容上方，顶栏菜单出现在触发物下方，空间不足时自动翻转并始终避开安全区与软键盘；点击外部只收起浮层，不穿透触发页面操作。长列表、完整表单、筛选器、草稿浏览和需要连续滚动的任务仍使用 Bottom Sheet。私聊收藏表情使用输入框旁的可滚动锚点面板，打开、切换与选择期间不得抢走正文焦点或收起键盘。

首页与标签聚合的主题卡片按“40dp 头像与作者/等级/时间 → 分类/状态/置顶语境 → 标题 → 整宽封面 → 两行摘要 → 固定 48dp 页脚”阅读。页脚左侧只保留玩家、回复与加油统计，右侧先尝试展示最多三个标签；只有三个标签按真实文字宽度无法容纳时才逐项减少，超过三个或因宽度隐藏的标签统一以不可点击的 `+N` 汇总。列表与详情的公开阅读标签只显示 `#名称`、亮/黑夜 `brandStrong` 与 600 字重，不使用常驻底色、描边、圆角或胶囊轮廓；移动端外围点击区域仍不小于 48dp，完整标签只在进入主题后展示。

连续正文使用留白和分隔线表达层级；卡片只用于真正独立的概览、发现或操作模块。主题题头属于阅读语境而不是独立卡片：只保留最多两行的主题标题，以及下一行最多两行的子贴标题、目录入口和两侧切换；分类、状态、标签、作者、时间与统计不在移动端题头重复出现。子贴导航与正文连续衔接，不另画分界线；多子贴导航在 320/360/400/600dp 下占满内容行，两侧 48dp 命中区包围占据剩余宽度、可见高度 36dp 的中央标题胶囊，普通态整栏高 56dp、冻结态高 48dp，大字体按双行文字实际高度扩展；目录抽屉内部的相邻子贴行使用 1dp 轻分隔线。喜欢、收藏、订阅和发表楼层形成固定底部拇指栏，Scaffold 为其扣除真实高度；360/400/600dp 均不允许溢出或遮挡正文。子贴正文底部保留与普通楼层一致的 12dp 内边距，再用横贯视口的 1dp 细线建立正文与楼层控制区边界；相邻主题顶层楼层使用 Foundation `input` 的 1dp 分隔线与 24dp 总节奏，独立讨论的顶层回复使用同一层级。作者写入的 Markdown `---` 使用正文可用宽度 50% 的居中短线圆点，线条为更浅的 `border` 1dp，中央为 `brandStrong` 5dp 圆点，上下各留 1.75em。楼中楼整个回复组共用 2dp `border` 左侧引导线和 12dp 外缩进，内容在线内再缩进 12dp；单条回复透明、无圆角、无描边、无底色，同级间仅用轻分隔线，主题流最多展示前三条并始终以安静文字入口进入全部楼中楼。控制行左侧显示总数，右侧依次显示无常驻描边、按内容收缩且最宽 112dp 的范围作者下拉框，以及按内容收缩的“正序 / 倒序”一键排序按钮，默认作者文案为“所有人”。两者统一使用 12sp、1.4 行高和 500 字重的弱化前景；读屏继续说明“最早在前 / 最新在前”，所有命中区不小于 48dp。管理身份不能改变阅读排版：正文编辑/添加和非楼主玩家退出都从顶栏按需操作进入。纵向列表的行、卡片和状态模块必须占满页面边距内可用宽度并在宽屏统一收束；标签、等级徽标等紧凑信息例外。长篇 Markdown 正文默认约 17sp、1.8 行高和轻微字距。阅读态行内代码保留外层斜体并继续使用 0.88em 等宽代码视觉。Quill 创作态使用 17sp、1.8 行高和同一标题比例。文字创作页把主题提交放入紧凑顶栏，楼层/回复提交固定在 Dock 最右侧；默认与非默认子贴正文只从主题详情进入同一半屏编辑器，主题管理工作台不嵌入正文编辑器。Dock 使用至少 48dp 的等分按钮槽位填满单行、禁止横向滚动，并保留系统底部安全区。`@提及` 候选使用贴近键盘、最多 200dp 高且内部滚动的临时浮层。动态与独立讨论仍可使用按内容收缩的固定发表入口；所有固定入口在滚动、分页、加载或身份变化时不播放收起、恢复、位移、缩放或淡入。普通正文图片始终 `contain`、保持自身宽度并在内容列左侧独占一行，轻触进入共享原图页；规范 sticker 仍作为可与文字混排的紧凑原子图片。

目录抽屉保留相邻子贴行的 1dp 轻分隔线；当前项以贯穿整行的无圆角柔粉色带和勾选标记强调，不与中央标题胶囊共用轮廓。

主题普通楼层正文不按内容长度或视口高度裁切、折叠或添加展开操作，始终直接全文显示。主题与动态楼中楼不按高度折叠或绘制渐变，展开操作统一使用普通字重、弱化前景、方向图标和至少 48dp 命中区；主题最多预览三条且只要存在回复便显示“展开楼中楼”，全部内容只在独立讨论展示，动态仅在尚有未展示回复时显示同款入口。

仓库不保存手工截取的设备页面作为长期设计事实。当前自动化视觉基线覆盖 Foundation 基础组件、动态瀑布流、动态纯文字/多图创作、首页卡片、主题创作与帖子编辑器、提及候选、独立讨论、长文阅读、主题流楼中楼超限渐变、360/400/600dp 普通主题首屏、360dp 管理者首屏、固定底部拇指栏、正文/楼层分界、内容分隔与 Markdown 分割线的层级差异、通知未读危险色，以及编辑态和阅读态的传送门同行混排与骰子两态。共享反馈/加载/空态/异步按钮另有组件画廊，覆盖 320、360、600、800 和 1200dp、竖/横屏、亮/黑夜与 1×/2× 字号，并检查溢出、48dp 命中区、语义标签与标准正文对比度。变更必须同时通过相关 Widget 回归和 Foundation 门禁。对应文件位于 `test/**/goldens/`；任何使用 `matchesGoldenFile` 的测试文件都必须在 `setUpAll` 加载 Foundation 字体。

管理工作台的线性页签本身承担区块标题，页签下不重复同名标题；正常状态不放刷新按钮，主题设置不放手动保存按钮，只以固定宽度的“待保存 / 保存中 / 已保存 / 未保存”反馈自动保存，“已保存”在 1.5 秒后退场，其他状态持续到下一次状态变化。主题设置主页面不显示“主题信息 / 发布与访问 / 主题操作”等复述内容的分组标题，也不使用内容分割线；区域以 24dp 留白分开，同组单行以 4dp 留白分开。仅页面标题使用展示字体，字段、设置项、操作和 Sheet 标题均使用正文字体；设置项标题为 16sp 半粗体，当前值为 14sp。标题是唯一内联输入框，不常驻显示计数；分区、标签、招募状态和可见范围统一使用至少 56dp、占满内容列的单行设置项，以当前值、整行点击反馈和尾部箭头表达可操作性，长标签单行省略，协作者只读可见范围把权限压缩进当前值且不显示箭头。主页面不把状态或标签画成胶囊，可移除胶囊和数量限制只存在于标签编辑 Sheet；隐私与状态含义放到选择 Sheet，删除风险只在二次确认弹窗出现。私密邀请、导出和删除使用无说明的单行语义图标操作。档案 Sheet 仍以同一胶囊语言区分格式单选与内容多选。主题设置不嵌入主正文，子贴管理只编辑标题与发帖权限；正文统一由详情页入口编辑，元数据保存不得覆盖正文。成员权限使用扁平紧凑列表与直接 48dp 图标操作；相邻角色操作保留 8dp 间距，当前为“是”时用职责色实心，为“否”时用同色空心。拖拽排序必须在手势完成后立即保持目标位置，稳定复用行 Key 和尾部操作槽位；服务端成功响应只合并元数据，不得通过旧列表回放或进度组件换位制造二次闪动。

当前 Foundation 覆盖状态、已确认差异和后续收敛顺序见 [Foundation v6.8.0 移动端实现审计](foundation-compliance-audit.md)。审计中的未闭环项不得在模块文档中标记为已满足 Foundation。

组件默认无动画：页面内容、状态提示、按钮标签、编辑器托盘、Dock、网络图片和分页结果直接进入最终状态。亮色、黑夜或跟随系统解析结果的变化在下一 Flutter 帧直接替换根主题，不对整棵应用做 `ThemeData` 插值。仅真实页面入栈/返回使用共享的 180ms 水平位移，全屏媒体使用 120ms 淡化；两者都不缩放页面，减少动态效果时直接完成。仅加载圆环、上传进度等对当前任务有直接含义的反馈可持续刷新；新增动画必须证明不会触发布局抖动、图片交叉合成或列表项批量重建，并按[移动端性能基线](performance.md)在 Profile 真机验证。长列表使用 builder/sliver 按视口创建内容，离屏普通条目不保留自动 keep-alive；缓存图片不交叉淡入，列表缩略图按显示尺寸解码。
