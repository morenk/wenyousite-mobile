# 移动端视觉基线

移动端视觉唯一规范是 Foundation 远端最新正式发布 Tag；当前锁定 v6.4.0 的 Flutter profile、品牌资源、核心元素、语义图标注册表与生成 Token。现行页面使用纯白画布、轻量分隔、12/24dp 响应式外边距、600dp 最大内容宽度和不小于 48dp 的独立触控目标；列表容器与列表项占满分配列，只有消息气泡、标签、徽标和紧凑操作可按内容收缩。品牌浅粉 `brandSurface` 只承担按钮、气泡和强调块，不能用作白底文字或图标；链接和通用强调前景使用 `brandForeground`，点赞与收藏选中态分别使用 `like` 与 `bookmark`，继续以透明容器及图标颜色/填充表达状态，表面上的内容使用对应 `on*` Token，并由程序化测试保证普通文字 AA 对比度。

品牌标识只进入 Flutter 启动首帧、登录/注册品牌头和首页标题栏。相邻已有“温油站”名称时标识为装饰并排除重复朗读；单独使用必须提供语义名称。更新、错误、找回密码等任务页面不重复加标识。Android 与 iOS 系统启动层以及 Flutter 品牌页均使用纯白底色；系统层不显示标识或文案，Flutter 拿到有效窗口尺寸后再把完整品牌内容整体居中。平台图标与保留资产由 Foundation v6.4.0 生成物同步，并由哈希测试阻止客户端私自漂移。

站内传送门消费 `WenyouElementContract`：正文 em 比例决定柔粉胶囊的内边距、间距、圆角和门图标大小，文字使用 `onAccent` 与 600 字重；阅读态可换行、不截断，透明命中区纵向保持 48dp、横向按内容收缩，因此短传送门能和前后文字自然同行而不会占满并居中整行。编辑态用 alphabetic baseline 的行内原子节点对齐文字且不导航。普通链接仍使用品牌深色下划线，不能与传送门混成同一种样式。骰子同样保持无图标的基线原子节点，但内部禁止换行或截断：已结算为柔粉 accent 表面，待掷为 warningSoft 表面，阅读和编辑复用同一组件，完整明细只进入 Semantics。

四个主导航固定为“首页 / 动态 / 消息 / 我的”，中央粉色按钮是全局“发布”；搜索从首页与动态顶栏进入，不占主导航分支。发布按钮在任一主导航分支都先显示“发布主题帖 / 发布动态”轻量选择器，当前频道不得替用户预选发布类型。开发 API、契约版本和环境连接提示不得作为正常用户首屏内容。

页面栏目、通知分组、动态模式与首页排头分类统一使用共享线性页签：白色表面、1dp 底部分隔线、纯文字标签和 2dp 品牌色短选中线，命中区不小于 48dp。二至四项且文字可容纳时等宽铺满；更多项目、长标签或放大字号放不下时只让页签条横向滚动，并保持当前选中项可见，横向手势不得切换内容页。页面排头使用统一响应式边距且不另加任意上下留白；面板和 Sheet 内仍使用同一视觉组件但继承父容器宽度。排序、状态、收藏夹等查询条件，以及裁剪比例、骰子面数和创作表单选项不是页签，继续使用各自的筛选或单选控件。

临时操作按任务重量分层：不超过六项的复制、回复、编辑、删除、举报、发布类型和草稿快捷操作使用锚定触发物的轻量气泡，不遮蔽整页；操作项最多五列，图标在上、短标签在下，第六项起换行，破坏性操作使用错误色。消息与楼层气泡优先出现在内容上方，顶栏菜单出现在触发物下方，空间不足时自动翻转并始终避开安全区与软键盘；点击外部只收起浮层，不穿透触发页面操作。长列表、完整表单、筛选器、草稿浏览和需要连续滚动的任务仍使用 Bottom Sheet。私聊收藏表情使用输入框旁的可滚动锚点面板，打开、切换与选择期间不得抢走正文焦点或收起键盘。

首页与标签聚合的主题卡片按“40dp 头像与作者/等级/时间 → 分类/状态/置顶语境 → 标题 → 整宽封面 → 两行摘要 → 固定 48dp 页脚”阅读。页脚左侧只保留玩家、回复与加油统计，右侧标签按卡片内宽在 `≤300 / 301～400 / >400dp` 分别显示一、二、三个，其余以不可点击的 `+N` 汇总；列表与详情共用 Web 风格的 32dp 可见胶囊、10dp 水平内边距、12sp 中字重和全圆角，移动端外围点击区域仍不小于 48dp。完整标签只在进入主题后展示。

连续正文使用留白和分隔线表达层级；卡片只用于真正独立的概览、发现或操作模块。主题题头属于阅读语境而不是独立卡片：只保留最多两行的主题标题，以及下一行最多两行的子贴标题、目录入口和两侧切换；分类、状态、标签、作者、时间与统计不在移动端题头重复出现。喜欢、收藏、订阅和发表楼层形成固定底部拇指栏，Scaffold 为其扣除真实高度；360/400/600dp 均不允许溢出或遮挡正文。子贴正文底部保留与普通楼层一致的 12dp 内边距，再用横贯视口的 1px 细线建立楼层边界；控制行左侧显示总数，右侧依次显示范围作者下拉框与带当前“最早/最新在前”文案的一键排序按钮。管理身份不能改变阅读排版：正文编辑/添加和非楼主玩家退出都从顶栏按需操作进入。纵向列表的行、卡片和状态模块必须占满页面边距内可用宽度并在宽屏统一收束；标签、等级徽标等紧凑信息例外。长篇 Markdown 正文默认约 17sp、1.8 行高和轻微字距；接力主题主阅读流最多预览服务端内嵌的前五条楼中楼。Quill 创作态使用 17sp、1.8 行高和同一标题比例。文字创作页把主题提交放入紧凑顶栏，楼层/回复提交固定在 Dock 最右侧；Dock 使用至少 48dp 的等分按钮槽位填满单行、禁止横向滚动，并保留系统底部安全区。`@提及` 候选使用贴近键盘、最多 200dp 高且内部滚动的临时浮层。动态与独立讨论仍可使用按内容收缩的固定发表入口；所有固定入口在滚动、分页、加载或身份变化时不播放收起、恢复、位移、缩放或淡入。普通正文图片始终 `contain`，轻触进入共享原图页；规范 sticker 仍作为紧凑原子图片。

主题楼层与楼中楼超限态沿用 Web 的“正文淡出 + 居中描边胶囊”层级，但判断始终基于 Flutter 真实排版高度。普通楼层超过视口 1.2 倍时裁到视口 0.8 倍；楼中楼预览超过 320dp 或总数大于最多五条的可见窗口时显示“展开全部”。渐变区固定 96dp 并使用当前连续画布表面色；未触发任何超限条件时不得为了进入独立讨论而常驻回复数或箭头入口。

仓库不保存手工截取的设备页面作为长期设计事实。当前自动化视觉基线覆盖 Foundation 基础组件、动态瀑布流、动态纯文字/多图创作、首页卡片、主题创作与帖子编辑器、提及候选、独立讨论、长文阅读、主题流楼中楼超限渐变、360/400/600dp 普通主题首屏、360dp 管理者首屏、固定底部拇指栏、正文/楼层分界，以及编辑态和阅读态的传送门同行混排与骰子两态；变更必须同时通过 320/360/400/600dp Widget 回归和 Foundation 门禁。对应文件位于 `test/**/goldens/`；任何使用 `matchesGoldenFile` 的测试文件都必须在 `setUpAll` 加载 Foundation 字体。

当前 Foundation 覆盖状态、已确认差异和后续收敛顺序见 [Foundation v6.4.0 移动端实现审计](foundation-compliance-audit.md)。审计中的未闭环项不得在模块文档中标记为已满足 Foundation。

组件默认无动画：页面内容、状态提示、按钮标签、编辑器托盘、Dock、网络图片和分页结果直接进入最终状态。仅真实页面入栈/返回使用共享的 180ms 水平位移，全屏媒体使用 120ms 淡化；两者都不缩放页面，减少动态效果时直接完成。仅加载圆环、上传进度等对当前任务有直接含义的反馈可持续刷新；新增动画必须证明不会触发布局抖动、图片交叉合成或列表项批量重建。长列表使用 builder/sliver 按视口创建内容，离屏普通条目不保留自动 keep-alive；缓存图片不交叉淡入，列表缩略图按显示尺寸解码。
