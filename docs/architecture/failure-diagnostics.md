# 故障诊断

移动端使用独立 Sentry 项目收集脱敏故障，同时在本机保存可复制的记录。用户文案、错误归因和是否发送是独立策略；服务端明确拒绝请求不等于服务端代码有缺陷，收到 HTTP 返回也不代表一定来自业务服务。

## 采集边界

- 全局 Flutter/Dart 未捕获异常由保留原处理器的错误入口收集；不改变原来的错误传播规则。
- 公共 Dio 在认证恢复与安全重试之后记录最终失败。刷新请求与对象存储直传也接入安全诊断，不记录地址或认证头。
- 帖子编辑器的会话 UUID 关联上传和提交尝试；阶段包括编码、认证准备、请求、返回和返回数据解析，媒体另记录准备、取得上传地址、直传、确认与处理。
- 已捕获的帖子提交失败、编码失败和媒体流水线异常主动记录，不能依赖全局未捕获异常入口。其他模块专属的已捕获本地异常尚未全面接入。
- 自动发送全局异常、5xx、未知业务码、契约/解析异常，以及帖子创建/编辑/正文保存的 `40000/40001/40006/40009`。这些 400 可能表示移动端生成了不合法的正文或图片引用。
- 普通权限、登录失效、冲突和限流只保留本地记录；普通读取的网络失败不上报。用户主动取消不生成错误记录。编辑器空内容、字数等本地校验不应生成远程问题。
- 本切片使用 Dart SentryClient，不安装 Flutter/原生自动采集集成，不覆盖 Java/NDK 崩溃、ANR 或 OOM，也不启用录屏、截图、界面树、日志、性能追踪和自动网络面包屑。

## 数据与生命周期

`DiagnosticRecord` 在写盘、导出和 Sentry 发送前重新执行白名单过滤，仅保留随机诊断/会话/尝试/请求编号、版本、平台、系统版本、阶段、计数、耗时、状态、业务码与源码坐标。异常只保留类型，不保留 message；堆栈不包含函数显示文本、绝对文件路径或源码上下文。正文、Delta、图片、URL、帖子 ID、账号、Token、请求体、返回正文及附件均不进入记录。

记录保存在应用私有 support 目录的 `failure-diagnostics-v1.json`，串行写入临时文件并替换，最多 50 条、7 天、1 MiB。存储失败时保留内存记录并显示保存失败，不递归记录诊断系统自身的故障。Sentry 确认同一事件编号后才移出待发送队列；发送失败留待下次启动、采集或回到前台，连接失败至少间隔一分钟，SDK 同时处理上游限流。

首次使用时开关默认开启；本地存储不可读取时暂停自动发送，以免丢失之前的关闭设置。仅配置了有效 DSN 的正式包发送。Debug 需显式开启 `WENYOU_ENABLE_ERROR_REPORTING`。关闭开关立即中止在途连接、清除待发送标记；重新开启不补发关闭前的记录。清除记录、退出与切号使旧尝试失效，旧会话迟到结果不重新落盘。应用重启可恢复尚未过期的记录，但没有离线发布队列，也不会为诊断重发业务操作。

## 页面与定位

游客在“我的”、登录用户在“账号设置”进入公开 `/diagnostics`，可开关自动发送、逐条复制和清除记录。帖子保存失败、编码失败与上传失败在原任务中提供“复制问题详情”。保留原编辑内容与原写入重放策略。

诊断编号对应 Sentry event ID（移除 UUID 连字符），同时以 `diagnostic_id` 标签保留；`request_id` 对应后端日志。`responseReceived` 表示观察到 HTTP 返回，`apiEnvelopeReceived` 表示观察到带业务码的返回，两者都不是请求已持久化成功的证明。没有返回或没有日志时不得直接断言错误来自手机。

## 本机构建与验证

在仓库外保存 JSON 配置，例如 `%LOCALAPPDATA%/WenyouSite/release/diagnostics.json`，只包含独立 Flutter 项目的 `SENTRY_DSN`。不要放管理员 API Token。

正式构建沿用现有 Windows 发布入口；将环境变量 `WENYOU_DIAGNOSTICS_CONFIG` 指向该 JSON，脚本以 `--dart-define-from-file` 传入 Flutter，不打印内容。缺失配置时构建仍可用于本地诊断，不能宣称远程上报已启用。Windows 路径请使用正斜杠（例如 `C:/private/diagnostics.json`）。直接 Debug 验证使用：

```powershell
flutter build apk --debug --dart-define-from-file=C:/private/diagnostics.json --dart-define=WENYOU_ENABLE_ERROR_REPORTING=true
```

本地测试覆盖真实 SDK 发出的信封白名单、上游失败保留、开关取消、跨重启、过期与容量、同异常去重、旧会话迟到结果、发布拒绝与窄屏复制操作。真实 Sentry 项目收件、真机网络条件和后端 requestId 对照仍需专用测试账号验收。

## 真机手测清单

1. 打开本人可编辑的专用测试私密帖历史楼层，插入图片并保存；正文与图片完整，成功不出现远程问题。
2. 在可控测试环境分别模拟格式/图片拒绝、网络断开、服务失败和返回解析失败；编辑内容保留，问题详情可复制，阶段和请求编号与实际情况一致。
3. 确认 Sentry 移动端项目能收到脱敏事件，用问题编号找到事件，再用 requestId 对照后端日志。检查事件及原始信封没有正文、图片地址或身份信息。
4. 断网产生记录后重启，仍可复制；恢复网络并回到前台后发送同一事件编号，不重发帖子请求。
5. 关闭自动发送后产生错误，仅本机保存；退出、切号、清除后旧记录不可见，旧请求返回不会复活记录。
6. 检查 320/360dp、两倍字号、亮色/黑夜以及软键盘状态的复制入口，确认无溢出或丢稿。
