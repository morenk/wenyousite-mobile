# 网络与会话

移动端调用 `authRefresh` 时必须携带 `X-Client-Platform: mobile`，以确保服务端返回轮换后的 refresh token。刷新遇到网络或 5xx 瞬时失败时保留本地会话，只有明确的 401 会话失效响应才清除 Token。

## 环境

`AppEnvironment` 从 `--dart-define=API_BASE_URL=...` 读取地址。Debug 默认值为 `https://wenyou.site/api/v1`；Android 模拟器连接本地后端时使用 `http://10.0.2.2:3000/api/v1`。生成客户端的 endpoint 已包含 `/api/v1`，因此底层 Dio 只使用配置地址的 origin，避免版本路径重复拼接。业务代码只依赖注入后的 Dio 和仓储，不读取全局常量。

契约同步与生产部署是两个独立事实。`npm run api:check` 会从仓库快照重新生成 Dart 客户端并要求生成目录零差异；准备声明“生产 API 已同步”前，还必须运行 `npm run api:verify:production`，由它比较本地 OpenAPI `info.version`、`backendRevision`、Markdown 版本与公网 `/meta`，并冒烟校验 `/threads` 的必需字段和单封面数组。`backend-contract.properties` 的 `contractVersion` 记录包含 fixture 与指南的整体契约包版本；当只升级编辑器黄金语料而不改变 HTTP API 时，它可以高于 OpenAPI 版本，不能拿来代替 API 版本比较。生产 `/meta` 中推荐的 Android build 属于移动端发布面，不会因后端部署或 Debug APK 构建自动更新；只有完成签名、上传和晋级后才能声明移动端生产版本已发布。

## 请求链

每个请求生成 UUID v4 `X-Request-ID`。登录和完成注册额外发送 `X-Client-Platform: mobile`。普通日志只记录方法、脱敏路径、请求 ID、成功响应状态或失败来源；所有查询参数与 fragment 都在格式化前截断，`/threads/join-by-link/{token}` 的私密邀请 token 固定替换为 `<redacted>`。显式开启现场诊断的 Debug 包才额外记录 HTTP 状态、业务码、传输类型和响应契约版本，不记录认证头、密码、验证码、正文、预签名 URL 查询参数、邀请凭据或隐私资料。

Access Token 与 Refresh Token 都保存到安全存储。刷新和退出由无业务拦截器的独立生成客户端发起，避免刷新请求递归进入 `40101` 拦截链。并发请求遇到 `40101` 时共享同一个刷新 Future；刷新成功后原子替换双 Token，每个可重放原请求最多重放一次。GET/HEAD、语义幂等的 PUT/DELETE 和显式声明 `idempotentCreate` 的创建请求可以重放；普通 POST 即使刷新成功也返回原结果，不自动重复写入。标记 `noAutomaticReplay` 的写请求同样只刷新会话、不重放请求。`40103` 至 `40106`、刷新失败或可重放请求再次返回 `40101` 时清空会话并携带失效原因进入登录页。

账号内页面状态使用 `SessionScope(accountId, generation)` 作为隔离边界。Access Token 轮转只替换凭据，不推进 generation，因此当前编辑器、待确认幂等创建、帖子讨论和云端草稿不会因正常刷新被销毁；登录建立新会话、退出、会话失效或切换账号才推进 generation 并释放旧账号状态。刷新完成前再次登录、退出或切号时，以刷新起点的 Token 与 generation 校验迟到结果，旧刷新既不能覆盖新凭据也不能清除新会话。JWT `sub` 只用于本地分区，不能作为权限事实。

退出当前终端时同时提交 bearer 与 refresh token；若 access token 已过期，先共享刷新再重试退出一次。服务端成功或明确判定会话失效后清除本机 Token；网络/5xx 失败保留会话和请求 ID供重试。只有用户在风险提示中再次确认，才允许仅清除本机登录。

Cursor 是不透明字符串。筛选变化清空 cursor；`40007` 清空列表并从第一页重载。请求附加语义只通过 `ApiRequestPolicy` 表达：公开请求使用 `public`，携带稳定 `clientRequestId` 的创建请求显式使用 `idempotentCreate`；业务代码不得直接写 Dio `extra` 键。自动重试只覆盖 GET/HEAD、语义幂等的 PUT/DELETE 和这类已声明创建请求，并保留原 `X-Request-ID`、请求体与幂等键；PATCH、普通 POST、4xx 与 429 均不自动重放。温油加油同样是幂等写入：一次弹窗操作以规范化目标、金额和 UUID 固定请求，失败后相同金额重试不得轮换 UUID。社区举报没有客户端幂等键，因此 `reportsCreate` 不自动重放；结果不明确时由用户显式重试，已成功但响应丢失由服务端唯一约束收敛为 `40914`。

## 错误模型

`ApiFailure` 只保存可稳定分支的失败原因、恢复动作、来源、HTTP 状态、业务错误码、请求 ID、响应契约版本和重试信息，不把后端 `message` 或底层异常文本当作界面文案。application/presentation 在具体对象上映射为 `UserFacingFailure`，明确“什么失败”、内容是否保留、安全恢复动作和页内/局部/瞬时的展示位置。core 只解释断网、超时、认证失效、频率、分页和通用冲突等横切语义；私聊、动态、贴纸、钱包等业务码仍由各 feature 在 data 边界映射，domain 不依赖网络错误类型。程序逻辑按业务码或 `FailureReason` 分支，页面不得按中文文案分支，也不得自行拼接请求 ID 或技术错误码。

普通构建按用户能否采取行动分级展示：

- 已知且可操作的 4xx/429 只显示对象结果和恢复方法，不显示问题环节或编号；主动取消和已经自动恢复的失败不再生成错误提醒。
- 文件、存储、相册、插件和应用内处理失败标注“问题环节：本机处理”，不虚构本地错误码；`40912` 属于本次请求与本机幂等状态冲突，可同时保留真实问题编号以便核对。
- DNS、TLS、Socket 和连接/发送/接收超时标注“问题环节：网络连接”；普通读取不显示编号，只有写入结果需要刷新核对时显示本次问题编号。
- 5xx/`50000` 标注“问题环节：温油站服务”，未知业务码、响应结构错配和序列化失败标注“问题环节：内容处理”；存在请求 ID 时作为次要“问题编号”展示。无法可靠归类的异常标注“暂无法判断”，只在已有安全编号时附带编号。

原始 HTTP 状态、业务码名称/数值、Dio 类型、响应契约版本和内部诊断码只进入显式开启 `WENYOU_ENABLE_FIELD_DIAGNOSTICS` 的 Debug 现场诊断。诊断项可复制，但不得包含后端错误文案、响应正文、请求 URL/查询参数、Token、验证码、密码、私信正文、上传地址或用户内容。架构门禁禁止 feature 页面直接拼接“问题编号”、业务码、HTTP 状态或内部诊断码。

可读取权威投影的写操作统一使用 `WriteReconciler`，结果分为已完成、明确失败、正在确认和待刷新核对。写入遇到超时、断网、瞬时异常或业务层明确列出的可收敛冲突时，只读取一次最新投影：投影证明目标已达成才按完成处理；读取到相反状态或读取本身失败都保留为待核对，因为原写入仍可能稍后落地。业务层必须逐项提供目标判定和允许收敛的业务码，通用层不把任意冲突视为成功。确认期间禁止重复点击，页面销毁和旧请求世代的结果不得覆盖新状态。

待核对时从当前对象出发说明“请刷新查看是否已生效”，同时明确“应用不会自动重复提交”；只提供刷新等安全入口，不使用“响应不完整”“结果不明”等实现语义。明确的权限、参数和内容冲突仍直接失败，例如 `40912` 不进入成功收敛。订阅创建的 `40904` 只有在重新读取后能以 `threadId + type + targetUserId` 精确匹配记录时才视为完成。

注册、找回密码与更换邮箱的发码请求统一使用不可自动重放策略。连接/发送/接收超时、断线、429/`42900` 或 5xx 会被视为写结果不明：UI 进入“邮件可能已发出”的验证步骤，保留邮箱和请求 ID，启动 60 秒冷却，不伪造有效期也不后台重发。明确失败则保留当前步骤和输入供用户修正。验证码和密码只存在于页面/控制器内存，完成、返回修改邮箱或页面销毁后不持久化。
