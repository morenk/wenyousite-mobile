## 原始反馈与复现

负责人提供编辑态与发布态两张截图，并确认 [Web 原楼层](https://wenyou.site/threads/cmtrvxfsy004s7q8a240qqb29?post=cmtsmut3k000y7q1s9zzf0myd) 显示正常。本任务通过只读 `GET /api/v1/posts/{id}` 取得版本 7 的完整正文，没有修改该楼层。

```markdown
> 123
123
<br />
`123`
123
<br />
~~123~~
`123`
```

复现步骤：打开该楼层，观察第一处代码下方普通文字和删除线下方第二处代码，再进入编辑器对照。预期两组相邻行分别回到同一行首；实际旧移动端发布态呈阶梯状水平偏移。上述 LF、空白行和行内样式均已原样保留在回归样例中。

## 已证实原因与候选范围

`_InlineCodeMarkdownBuilder` 原先直接返回独立组件，`flutter_markdown_plus` 无法把它合并进相邻文字的 RichText，而以多个 Wrap 子项排列；文本里的 LF 只影响所在子项，后续行因此出现在前一个子项右侧。旧实现四组原文测试失败，普通字体偏移约 55.83dp、两倍字体约 100.71dp。

扩展检查证实用户提及、全体提及与收藏表情也使用独立组件路径，在 1 倍／2 倍字体下共复现 6 项同类失败。负责人已明确要求一并修正。

候选增加 `WenyouMarkdownInlineBuilder`：子类只提供元素内容，由统一适配入口生成 `Text.rich` 与 `WidgetSpan`，静态检查通过 `@nonVirtual` 禁止子类重写包装方法。行内代码、提及、传送门、骰子均继承此入口；图片回调里的收藏表情复用相同包装方式，并保持相对文字居中。普通正文图片仍为独占块。修改只影响移动端阅读布局；没有更改 Codec、Quill、API 写入、字体规则、Foundation 依赖或线上正文。

| 内容 | 排查结果 |
| --- | --- |
| 行内代码、用户提及、全体提及、收藏表情 | 已复现同类错位，纳入候选 |
| 粗体、斜体、删除线、普通链接 | 原本共用文字 span，换行矩阵通过 |
| 传送门、骰子 | 原本已有行内 span，矩阵通过，现统一复用适配入口 |
| 标题、引用、列表、普通图片 | 属于块布局，本问题的独立行内组件根因不直接适用；保持既有回归 |

这能防止新增自定义行内组件意外绕过统一布局，不表示其他段落语义、超长内容或平台字体问题已被无限覆盖。新增行内元素必须补充前后换行、混排、窄屏和缩放用例；仅检查样式参数或编解码往返不足以证明排版正确。

Foundation 远端最新正式 Tag 已核对为 `v6.9.0`。后端部署来源同步单独提交；HTTP、Markdown 与生成客户端无变化。

## 自动验证

- 精确原文：明暗主题各 1 倍／2 倍字体，核对两组实际文字框与代码表面的行首位置和上下顺序。
- 混排：同一行的文字基线、代码前后文字位置及窄屏剩余宽度不足时的折行。
- 通用矩阵：十类行内内容各覆盖 1 倍／2 倍字体的前后换行，另检查所有注册的自定义行内 builder 均采用统一入口；原有提及点击、骰子明细、传送门、图片与表情交互回归继续执行。
- 真实页面：通过楼层长按编辑入口，检查可见行、空行和样式；在第一处代码内部插入字符，保存后阅读，再打开编辑器逐项检查。仓储使用本地测试替身，不写入线上。
- 视觉：新增原文黑夜回归图，并检查 360dp 明暗、600dp 和 2 倍字体的编辑／阅读配对图。测试引擎的等宽字体使用占位字形，原生字体外观仍须真机复验。
