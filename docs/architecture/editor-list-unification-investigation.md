## 已证实的问题与复现

1. 读取和写出均把两个空格当成一级，未根据实际父子结构处理编号标记的宽度。`1. 甲\n   1. 乙\n      1. 丙` 是三层，但旧读取会把部分行显示为字面源码；旧写出三层 Delta 的结果也可能实际变成同级。
2. `MarkdownContent` 把行首六个空格当作第四层，合法三层有序列表被误判超限。三层限制应按实际列表树判断。
3. 没有父项的 `  - 甲` 实际仍是根列表，旧实现会制造第二层。历史 `1. 甲\n  1. 乙\n    1. 丙` 在 Dart Markdown 默认／GFM 中是两个根级项，末行属于第二项的续文，不能猜测作者原先想要三层。此前提出的 `[0, 0, 1]` 推断已撤回；后端 markdown-it 的独立检查也得到两个根级项。两种解析器对续文的结构性前导空白处理另需在共同夹具中明确。
4. 空父项与空子项之间机械加入空行会结束父项。`-\n  -` 保留父子关系，`-\n\n  -` 会错层；仅比较列表项数量不能发现这个错误。
5. 空祖先、非空子项、空孙项还涉及源码分隔位置。Dart Markdown 7.3.1 对 `-\n  - 乙\n\n    -` 读取不足三项；同一树可以用 `- - 乙\n\n    -` 表达。同行嵌套也必须按树读取，不能认为一个源码行必定只有一个列表项。这个表示还需 VPS 独立验证，不能仅凭移动端解释器写成共享规则。
