## 原始反馈与复现边界

负责人反馈：删除楼层后出现删除成功提示，但当前页面仍显示被删除楼层，下拉刷新也不消失，只有退出帖子再进入才消失。负责人补充发生在[原主题](https://wenyou.site/threads/cmtrvxfsy004s7q8a240qqb29)：从帖子列表进入，删除前编辑过该楼层，残留的是原正文而非已删除占位。具体被删楼层编号未提供。

代码排查发现详情以两份状态展示内容：普通楼层分页与 `threadPostTargetProvider` 的定位目标。`threadFloorsWithTarget` 将定位结果补入列表，原删除和下拉刷新只重读普通楼层，目标查询缓存未失效；因此服务端列表已移除楼层，旧目标仍被补回。刷新失败时 AsyncValue 也可能保留历史值，不能把该值当成有效的定位结果。

真实页面脱敏回归使用 `?post=floor-1` 定位、成功删除后从仓储楼层列表移除、目标详情返回 40403 的独立预期。旧代码两项失败：删除成功后仍能找到楼层卡片，下拉刷新没有重读目标。删除请求失败的对照检查通过。未对共享线上内容执行删除或其他写操作。

已补全普通入口 → 编辑保存 → 自动定位已编辑楼层 → 删除 → 下拉刷新真实页面回归。保存后生产页面会通过 context.replace 增加 post 定位坐标，因此普通入口与定位缓存路径并不矛盾。候选完整链路通过；无编辑的普通入口作为对照，旧实现本就通过。测试正文为脱敏文本，未恢复或读取已删除的线上正文，真机仍待负责人复验。
