## 根因与定位规则

共享定位使用 `Scrollable.ensureVisible(alignment: 0.12)`。此比例基于阅读区与目标高度之差；当目标高于阅读区时会越过目标开头。构造几何回归中，600 高阅读区与 1,800 高目标使开头位于 -144。

原始正文页面回归也已证实同一现象：360×640 视口中，通过最新发言按钮及直接坐标进入，旧实现均将目标顶部定位到约 -1210.38，正确阅读起点为 96（顶栏及吸顶选择器下方）。页面使用真实 Markdown、测试作者与主题上下文，图片由测试环境处理，未在负责人设备上复现。

候选使用开头对齐。Flutter 视口计算负责扣除前方吸顶 Sliver 占位，滚动位置限制在实际范围内：

- 长楼层从目标块顶部开始，作者信息不被吸顶选择器遮挡。
- 短楼层在后续内容足够时也对齐开头；末尾空间不足时停在自然列表底部，整层可见且不新增空白。
- 不足一屏的整页保持自然排版。
- 分页、图片撑高和视口尺寸变化后，在用户未主动拖动时重对齐；用户拖动后保持原有停止自动定位规则。
- 主楼、主题楼中楼、动态评论及回复共用规则；传送门、通知、搜索和最新发言入口无需分别修正。
