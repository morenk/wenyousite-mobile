# 移动端删除与状态反馈 UX 审查

状态：楼层删除交互已形成候选，待负责人验收；其余条目为代码审查发现，尚未修改或真机复现。范围为删除、目标定位、404、自动分页及成功／失败反馈，没有对全部页面完成真机遍历。

## 本次反馈与候选

负责人在汇总包 `39e32767` 上反馈：删除确认解释“标记删除”，删除成功后又出现红色“目标内容已不可见”和“重试定位”。这属于正常操作被表现为故障，前一轮候选的删除 UX 验收失败，继续处理原问题。

原因已由真实页面回归证实：编辑保存会添加 `post` 路由坐标；前一轮失效了目标缓存，却保留坐标并重新查询已经删除的目标。原回归只验证旧正文不再补回，没有约束删除后的目标路由和错误提示。

本轮候选复用共享确认弹窗，只保留“删除这个楼层？”与取消／删除操作。成功删除当前定位楼层时移除该定位坐标，保留当前子贴，再刷新正文；删除失败不改变路由或内容。来自旧链接或外部删除的 404 使用普通不可见说明，不显示问题编号或无效重试；临时网络错误继续保留错误提示和重试。

`thread_deleted_target_test.dart` 共 7 项真实页面回归：旧实现 4 项失败、3 项对照通过，候选全部通过。覆盖普通入口编辑保存后删除、直接定位删除、普通入口直接删除、外部删除后刷新、删除失败、取消确认及定位网络失败后重试。不对共享线上内容执行删除测试。完整质量门禁和 APK 记录见[汇总复验](mobile-regression-validation.md)。

## 其他发现

| 优先级 | 场景与代码证据 | 建议与验证边界 |
| --- | --- | --- |
| 高 | [动态评论删除](../../lib/features/moments/presentation/moment_detail_page.dart) 的 `_deleteComment` 解释“评论会显示为已删除，楼中楼结构会保留”；删除后仍调用 `_invalidateTargetContext`，没有结束已删除评论的路由定位。[定位状态](../../lib/features/moments/presentation/moment_comment_navigation.dart) 对不可见目标使用红色错误色。 | 简化删除确认，删除当前目标时收敛定位。404 已没有重试按钮，但仍是错误样式；能否在删除后触发取决于目标上下文响应，须补真实页面删除回归，不能断言每次删除都出现红框。 |
| 中 | [主题楼层页尾](../../lib/features/threads/presentation/thread_detail_sections.dart) 的 `ThreadFloorsFooter` 在正常预取期间仍渲染“加载更多楼层／正在加载”按钮；[页面](../../lib/features/threads/presentation/thread_detail_page.dart) 已通过预取调度器自动请求剩余文字页。 | 与独立楼中楼候选一致，正常状态改为进度，失败才提供手动重试。需要慢请求与分页失败页面回归，保留原文窗口。 |
| 中 | [主题详情不可见状态](../../lib/features/threads/presentation/thread_detail_sections.dart) 的 `ThreadDetailFatalState` 对 404 同样提供“重新加载”。 | 失效内容优先返回或离开入口；权限变化与临时故障应按真实可恢复条件设计，不能把所有失败统一删掉重试。动态详情已有不可见时不提供重试的实现，可作为一致性对照。 |
| 中 | [动态收藏夹页](../../lib/features/moments/presentation/moment_bookmark_folder_page.dart) 监听 `transientFailure` 显示错误 Snackbar；移动失败又从 `onConfirm` 抛出同一失败，被[收藏夹选择弹窗](../../lib/core/widgets/wenyou_bookmark_folder_picker.dart) 捕获并显示 `WenyouFailureBanner`。 | 一次移动失败保留弹窗内反馈，避免背景页面同时报错。取消收藏是另一动作，需要保留其失败反馈；须用失败移动与失败取消收藏两个场景验证。 |
| 低 | [草稿状态](../../lib/features/drafts/application/content_drafts_controller.dart) 删除成功后设置“草稿位…正文已删除”，[草稿面板](../../lib/features/drafts/presentation/content_drafts_sheet.dart) 常驻 `content-drafts-success` 横幅，直到后续状态变化。 | 列表变化已表达结果，可取消常驻横幅或改为短确认；覆盖保存成功同样检查反馈时长，保留冲突与失败操作入口。 |

以上证据来自实际调用链审查，未把“存在重试／提示文案”本身等同于问题。通知中点击已删除内容的提示、显式展开内嵌回复、失败分页重试、账号注销的内容保留说明和草稿跨设备删除风险均有用户决策用途，本次不列为冗余。

## 后续实现约束

- 删除成功同时结束失效的选中对象、定位和详情状态；测试不只断言数据消失，也断言不再报错、不再提供重试。
- 不可见内容与暂时加载失败分开；只有动作能够恢复当前操作时才提供重试。
- 一个操作在当前操作界面展示一次反馈。成功短暂确认，失败在能处理问题的位置保留。
- 确认文案说明必要的用户后果，避免解释存储和组件结构；不取消有价值的不可逆、权限或隐私说明。
