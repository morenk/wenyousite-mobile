# 双端普通回车候选验收

状态：候选／待负责人验收。代码检查、浏览器自动操作和 APK 安装均不替代负责人反馈。

## 范围与原因

负责人要求普通正文和引用的一次回车只是换一行；标题和列表保留常规行为。此前 Web 的 Enter 创建段落，移动端按行编辑，且空引用／对齐空行存在自动退出规则；旧引用分隔、真正空白行及额外段落间距又被不同转换路径混用，因而会先出现可见 `>`，修正块归属后又暴露额外空行。

候选将普通 Enter、明确空白行和旧引用语法分隔分开处理；两端读取后端发布的 [newline v1 夹具](../../contracts/markdown-editor-newline-v1-fixtures.json)，保存前后分别核对可见行与格式。引用里的行间距不再误用整个引用的内边距，显式空行与相邻正文也不重复叠加段落间距。

## 预期操作

| 场景 | 一次回车 | 连续回车 |
| --- | --- | --- |
| 普通正文，含粗体、斜体和删除线 | 下一行 | 保留相应空白行 |
| 居中、右对齐普通正文 | 下一行继续当前方向 | 保留空白行，后续文字继续同方向 |
| 单层引用 | 同一引用内下一行 | 保留空白行；通过引用按钮退出 |
| H2/H3 | 行末进入正文，行中按原编辑器规则拆分 | 保留常规行为 |
| 有序／无序列表 | 继续下一个列表项 | 保留原编辑器的空项、退出及缩进行为 |

新文字行用 LF 表示；真正空白行分别用 `<br />`、`> <br />` 表示。旧帖独占 `>` 仍表示引用内部的段落分隔，不自动增加一条可编辑空行。不批量改写旧帖。
