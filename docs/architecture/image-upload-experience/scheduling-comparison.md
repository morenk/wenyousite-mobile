# 图片队列确定性对比

本对比用于验证客户端调度行为，不能作为真实网络或服务端处理速度的承诺。真实服务端耗时见[服务端分析](server-analysis.md)，真机待验场景见[验收清单](acceptance.md)。

## 模型与复现

测试入口：`test/features/media/media_upload_scheduling_comparison_test.dart`。

- 使用 Flutter 测试虚拟时钟，固定每张本地处理为 20ms、传输与确认为 100ms、确认后的就绪等待为 1000ms。
- 两种路径均限制本地处理并发为 1、实际传输并发为 2，图片质量、尺寸和文件数据不参与这个队列模型。
- 旧路径复现动态页面的两个完整流程名额，服务端等待期间不释放；新路径直接使用当前 `RepositoryMediaUploadGateway` 和 `MediaUploadWorkCoordinator`，确认后释放传输名额。
- 分别输入 1 张和 9 张；同时选择图片，所有任务均成功，无取消、断网或重试。

```powershell
flutter test --no-pub test/features/media/media_upload_scheduling_comparison_test.dart
```

## 固定输入的测试结果

单图、九图两项确定性测试均通过；下表时间由测试虚拟时钟采集并逐项断言。

| 指标（相对确认选图的时间） | 单张旧路径 | 单张新路径 | 九张旧路径 | 九张新路径 |
| --- | ---: | ---: | ---: | ---: |
| 最后一张完成传输与确认 | 120ms | 120ms | 4600ms | 520ms |
| 全部图片就绪 | 1120ms | 1120ms | 5600ms | 1520ms |
| 第三张开始传输 | 不适用 | 不适用 | 1140ms | 120ms |
| 选图后 500ms 点击发布的剩余图片等待 | 620ms | 620ms | 5100ms | 1020ms |

单张图片实际工作量未变。九张场景的差异来自避免让服务端等待占用后续图片传输机会；不能将这一模型中的缩短比例推广为真实上传提速比例。

## 测量边界

该模型不包含真实带宽竞争、对象存储延迟、服务端 CPU/处理队列容量、轮询发现延迟、设备解码/绘制、正文提交请求。1000ms 就绪等待是每张固定假设，没有模拟服务端资源不足导致的额外排队。真实场景可能小于、等于或大于上述耗时，仍需按素材及设备实测。

查询最多两路、轮询退避不占查询名额、取消排队不开始传输、提前释放后失败不重复释放，由 `media_processing_resume_test.dart` 和 `media_upload_work_coordinator_test.dart` 单独验证。
