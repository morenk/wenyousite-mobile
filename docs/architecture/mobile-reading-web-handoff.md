# 阅读性能优化的 Web 适用性

当前是 Mobile 后续候选的交接说明；不代表已经改动 Web、Backend 或 Foundation。

| 行为 | Web 可复用结论 | 平台差异与验证 |
| --- | --- | --- |
| 明确目标窗口、在途去重与迟到结果失效 | 发布、通知、搜索、编号共用导航代次，发布事实与只读定位失败分开 | 保留 Web 路由历史、权限与排序；不要重复提交创建请求 |
| 段落字符书签 | 窗口前插、图片与字体迟到时保持读到的文字；用户滚动优先 | Flutter RenderParagraph 坐标不能复制到 DOM，应验证 Range／Selection 与滚动锚定 |
| 有界正文保留 | 条数加内容重量，保护可见／选字页面并保存反向游标 | 移动端 1 MiB 估算与三页底线不能直接成为 Web 内存预算，须浏览器堆与 DOM 实测 |
| 解析结果复用 | 同一内容版本复用 AST，语义配置改变失效，样式更新不重解析 | Web 编辑与阅读语法可能不同；连续复制／引用／查找须保持 |
| 方向、速度与等待感知预取 | 有限提前、单请求、折返旧结果不应用、同位置不重复下页 | 浏览器后台节流和网络取消 API 不同；不能把逻辑失效当实际中断 |
| 返回原处 | 单次返回书签恢复原范围与文本位置 | 与浏览器后退栈职责分开，不新增无限阅读历史 |

大图按显示像素解码是 Flutter 引擎内存优化。Web 需要评估服务端已有缩略图与浏览器图片解码策略，不能假定 CSS 限宽会减少解码内存。Mobile 未因本轮优化更改图片契约。

当前未发现必须先改 Backend／Foundation 的依赖。跨仓实现应在 VPS 对应仓库另开明确目标；此文不授权修改只读镜像或部署。手机 Profile 与最终门禁证据记录在同目录 `mobile-reading-performance.md`，不要以 Windows Mock 数字替代 Web 或手机实测。
